## 2. 背景与产品结论

RoboThree 同时支持后台配置的企业模型和用户在本机添加的个人模型。两类模型在任务创建时共享同一个模型选择体验，但权限来源、凭证域、调用路径和故障范围保持隔离。

产品结论固定如下：

1. 企业模型来自后台配置、排序和授权；个人模型入口由后台权限控制，模型配置与凭证保存在本机；
2. 当前用户有权使用且状态允许的企业模型和个人模型都可以在新任务中被选择；
3. 有效用户偏好优先；没有有效偏好时使用后台排序中的第一个可用企业模型；企业模型为空但存在可用个人模型时要求用户明确选择，不自动猜测个人默认；
4. 用户在未选择机器人时手动选择模型，会更新用户默认模型，并影响后续新任务；
5. 机器人未开启模型限制时允许当前用户全部合法模型；开启后只允许已选模型与当前用户合法模型的交集，并按 Core/后台稳定顺序确定临时有效模型；该限制只改变当前待创建任务，不覆盖用户默认模型，取消机器人后恢复用户默认模型；
6. Core 接受首次 SubmitTurn 并原子创建 Task/Runtime Selection 时、第一次模型调用前锁定模型，本期不支持在同一任务/会话执行中切换；
7. 个人模型在“个人设置 → 模型”中添加、编辑和删除，本期不提供测试连接；
8. 个人 API Key 默认隐藏，用户可以主动查看自己的已保存 Key；企业模型 Credential 永不下发客户端；
9. MVP 不检测、不阻止、不审计操作系统截图或外部录屏；应用自身不得主动记录或持久化 Key 明文；
10. DFE-5A 编码不自动启动 DFI-2B。个人模型真实后端与 Credential 链路必须作为 DFI-4A 或等价独立批次评审和授权。
11. 新任务只提供一个全局 `Max` 开关：关闭时不增加推理强度参数，开启时优先由 Model Adapter 映射为当前模型已验证支持的最强模式；用户不配置 Provider 档位、参数名或预算。
12. `Max` 是增强偏好而非任务硬约束。不支持、提交时能力变化或安全映射失败时，任务按模型默认模式继续并明确说明；产品不强制独立偏好服务、独立锁体系或五个串行开发项目。

## 3. 范围

### 3.1 P0 范围

- 企业模型只读展示与选择；
- 后台“允许个人配置模型”权限的客户端表现；
- 个人模型添加、编辑、更换 Key、查看 Key、删除；
- DeepSeek、智谱、Kimi、自定义四类 Provider；
- 用户默认模型持久偏好；
- 机器人限制下的临时有效模型与取消后的恢复；
- 未验证、可用及七类不可用状态；
- Core 接受首次 SubmitTurn 后的模型锁定；
- 全局 `Max` 开关、个人偏好、模型支持状态与任务级解析结果锁定；
- 个人模型 Credential 的受控采集、保存、使用、查看和删除产品语义；
- Mock、静态 UI 和真实能力的明确边界。

### 3.2 明确不做

- 个人模型“测试连接”；
- 自动发现 Endpoint 或拉取 Provider 模型列表；
- 自动选择最佳模型、延迟测速或智能路由；
- 五档或任意档位推理强度选择、用户自定义推理预算、自动 Effort；
- 在 Admin 模型配置、个人模型设置或机器人配置中填写 Effort 参数名、档位与预算；
- 模型不可用时静默切换到其他模型；
- 同一任务执行中切换模型；
- 个人模型批量导入、共享或企业托管；
- 个人 Credential 上传、代理、备份或同步到企业服务；
- 企业 Credential 在 Desktop 中输入、查看或导出；
- 操作系统截图检测、截图拦截、外部录屏识别或截图审计；
- 在本 Spec 中静默修改 ADR-013、公共 Contract、IPC 或数据库结构。

## 4. 用户、权限与来源

### 4.1 企业模型

- 企业模型由后台配置、排序、启停并分配使用权限；
- 后台排序是“第一个企业模型”的唯一顺序来源，客户端不得按名称或本地时间重新排序后推断默认值；
- 企业模型 Credential 只存在于企业安全凭证域，通过企业 Model Gateway 使用；
- Desktop 只接收模型安全摘要、可用性、权限和必要能力信息，不接收企业 API Key 或内部 Credential Reference；
- 普通用户不能添加、编辑或删除企业模型。

### 4.2 个人模型

- 后台权限 `允许个人配置模型`（最终标识由权限 Contract 冻结）控制用户是否可以添加和使用个人模型；
- 有权限用户在本机创建个人模型配置，个人 API Key 只进入本机受控 Credential 链路；
- 企业服务不接收、代理、备份、同步或展示个人 API Key；
- 权限被收回后，既有个人模型不可继续用于新任务，也不可编辑；用户仍可删除本机个人模型和 Credential；
- 权限恢复后，既有配置是否重新可用由 Core 根据权限与 Credential 状态重新判定，前端不得自行恢复。

### 4.3 统一选择体验

- 企业模型与个人模型使用同一个新任务模型选择器；
- 常规选项主要展示显示名称，不使用强视觉标签制造两套选择体验；
- 显示名称相同且无法区分时，增加最小来源说明，例如“显示名称 · 企业”或“显示名称 · 个人”；
- 不可选择模型保留名称并进入禁用态，通过辅助说明展示原因；
- 模型来源不改变任务状态机，但凭证域、调用路径和错误范围必须保持隔离。

## 5. 个人设置中的模型管理

### 5.1 页面与入口

- 入口位于“个人设置 → 模型”；
- 没有个人模型权限时，不展示“添加个人模型”主操作；
- 企业模型可作为只读内容展示，个人模型提供编辑和删除入口；
- 模型列表主要展示显示名称；同名冲突时显示最小来源/Provider 辅助信息；
- 状态不可用时通过禁用态或辅助文案解释，不依赖颜色标签表达。

### 5.2 字段

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 提供商 | 是 | 固定为 DeepSeek、智谱、Kimi、自定义 |
| 接口地址 | 是 | 预设 Provider 自动带出受控默认值；选择“自定义”时由用户填写 |
| API Key | 新增/更换时是 | 默认隐藏，可在本次输入期间通过眼睛图标显示 |
| 模型标识 | 是 | 提交给 Provider 的精确 Model ID；不做翻译、改写或自动补全 |
| 显示名称 | 是 | 用户在列表和任务选择器中看到的名称；默认等于模型标识，可单独修改 |

`模型标识`、`显示名称`和系统内部 `Personal Model ID` 是三个不同事实：模型标识用于 Provider 调用，显示名称只用于用户界面，Personal Model ID 是不可编辑的本地资源标识。前端和 Contract 不得用一个字段混写三者。

Provider 规则：

- DeepSeek、智谱、Kimi 的默认接口地址由客户端受控发布配置提供，不在本文硬编码 URL；
- 选择预设 Provider 后接口地址自动填充，不作为普通可编辑字段；需要其他 Endpoint 时使用“自定义”；
- MVP 的“自定义”只支持已冻结的 OpenAI-compatible 最小协议；其他协议必须新增 Provider 类型或专项适配，不允许前端猜测；
- 切换 Provider 时，如果会覆盖用户已经输入的自定义地址，必须先明确提示，不静默丢失输入。

### 5.3 添加与保存

1. 用户进入个人设置的模型页；
2. 点击“添加个人模型”；
3. 选择 Provider，系统按规则带出或要求填写接口地址；
4. 输入 API Key、模型标识和显示名称；显示名称未修改时默认等于模型标识；
5. 客户端先完成必填和格式校验；
6. 通过受控 Credential 链路提交模型配置和 Secret；
7. Core 原子确认模型元数据与 Credential 保存结果；
8. 成功后列表出现该模型，初始状态为“未验证”；
9. 保存失败时保留非敏感字段；Key 是否保留在当前表单内由敏感输入组件控制，离开页面后必须清除。

保存不触发测试连接，也不把“保存成功”表述为“模型可用”。

### 5.4 编辑

- 可编辑 Provider、接口地址、模型标识和显示名称；
- 已保存 Key 默认显示掩码；
- 更换 Key 使用明确操作，不要求编辑普通字段时重新填写 Key；
- 修改 Provider、接口地址、模型标识或 Key 后，历史“可用”结果失效，状态回到“未验证”；仅修改显示名称不改变连接有效性状态；
- 编辑成功不改变 Personal Model ID；
- 并发修改或 revision 过期时不得覆盖较新配置，要求刷新后重试。

### 5.5 查看已保存 API Key

- 只有个人模型所有者可以请求查看自己的已保存 Key；
- 默认展示掩码，用户主动点击眼睛图标后显示明文，再次点击恢复隐藏；
- 离开页面、关闭弹窗、切换模型或组件卸载后必须恢复隐藏并清除 Renderer 中的明文；
- 自动定时隐藏可以作为后续增强，P0 不强制；
- 不提供企业模型 Credential 的查看入口；
- 不提供独立“复制 Key”快捷操作；用户主动显示后的屏幕暴露风险属于用户设备侧行为；
- MVP 不检测、不阻止、不记录系统截图或外部录屏。

该产品语义需要 ADR-013 增补或等价架构决策冻结“安全存储 → Core/Main 受控通道 → 所有者当前 Renderer”的反向读取。架构增补完成前，真实查看按钮必须禁用或标注待接入，不得通过普通 HTTP、URL、命令行参数、日志或公共 Contract 返回 Secret。

### 5.6 不提供测试连接

- 个人模型添加和编辑页面不展示“测试连接”；
- 保存前不发起 Provider 网络请求；
- 保存成功只表示配置与 Credential 已安全保存，不表示认证、网络、协议或模型标识有效；
- 模型状态通过后续真实任务调用结果更新。

## 6. 模型状态

### 6.1 状态定义

| 状态 | 含义 | 是否可选择 | 用户动作 |
| --- | --- | --- | --- |
| 未验证 | 新增或关键字段修改后尚无成功调用事实 | 是 | 可用于新任务，首次调用可能失败 |
| 可用 | 最近一次受支持的真实调用成功 | 是 | 正常使用 |
| 认证失败 | Provider 拒绝 Credential | 否 | 更换 Key |
| 网络失败 | 最近一次调用无法连接 Endpoint | 是，带最近失败警告 | 检查网络或地址后可再次创建任务并真实重试 |
| 协议不兼容 | 响应不符合已支持协议 | 否 | 修改 Provider/Endpoint |
| 模型不存在 | Provider 不识别模型标识 | 否 | 修改模型标识 |
| 不可用 | Provider、模型或本机 Credential Store 当前不可用 | 否 | 查看原因并稍后重试 |
| 权限不足 | 后台权限或资源授权不允许使用 | 否 | 联系管理员或删除本地配置 |

### 6.2 状态来源

- “未验证”来自保存或关键字段修改事实；
- “可用”只来自真实模型调用成功，不由前端按钮或本地计时器生成；
- 失败状态来自 Core/Provider Adapter 的类型化结果；
- 网络失败不形成永久禁用：用户可以再次选择并发起真实调用；只有该调用成功后才更新为“可用”，再次失败则保留最新失败事实；
- 页面可以展示最近错误的用户语言摘要，不展示原始 Provider 响应、Key、Endpoint 中的敏感 Query 或内部堆栈；
- 模型选择器主要展示名称，不强制显示状态标签；不可选择时必须提供禁用原因。

## 7. 默认模型与任务选择

### 7.1 两层模型状态

产品明确区分：

```text
用户默认模型 userPreferredModel
    用户长期偏好，用于后续新任务

当前有效模型 effectiveModel
    当前待创建任务实际准备使用的模型
    可以因机器人限制临时不同于用户默认模型
```

前端不得用一个字段同时表达两者。

### 7.2 初始默认模型

- `userPreferredModel` 仍有效且可选择时，使用该偏好，不因其来自个人模型而改选企业模型；
- 没有有效用户偏好时，Core 按后台有效顺序选择第一个可用企业模型；这不是“最佳模型”路由；
- 企业模型为空或均不可用，但存在可选择的个人模型时，不自动指定其中一个；页面要求用户明确选择个人模型，选择成功后更新用户默认模型；
- 企业模型和个人模型均无可选择项时才阻止创建任务，并提示联系管理员或修复个人模型；
- 客户端不得按名称、本地缓存顺序或最近请求结果猜测企业默认模型。

### 7.3 手动切换

- 用户在未选择机器人且任务首次提交前手动选择其他合法模型时，同时更新 `userPreferredModel` 与当前 `effectiveModel`；
- 新偏好用于后续新任务；
- 已经创建并开始执行的任务不受偏好变化影响；
- Core 接受首次 SubmitTurn 并创建 Runtime Selection 后，模型立即锁定，本期不允许在同一任务/会话内切换；
- 保存用户偏好失败时不得伪装成功，当前待创建任务是否继续使用该选择由 Core 返回的结果决定。

### 7.4 机器人模型限制

选择机器人时按以下顺序处理：

1. 机器人未开启模型限制：机器人不增加模型允许列表，当前用户全部合法模型继续参与选择；
2. 机器人开启模型限制：候选范围固定为“机器人已选模型 ∩ 当前用户合法模型”；
3. `userPreferredModel` 在候选范围内且当前可用：继续使用；
4. 不满足时，按 Core/后台返回的稳定模型顺序选择第一个可用模型作为临时 `effectiveModel`；当前初始实现可以按模型配置或添加时间形成顺序；
5. 页面提示“已根据机器人能力切换模型”，并允许用户在机器人候选范围内为当前待创建任务选择其他模型；
6. 机器人约束期间的临时选择不覆盖 `userPreferredModel`；
7. 取消机器人后恢复 `userPreferredModel`；如果原偏好已经不可用，则按 §7.2 重新确定有效模型并说明原因；
8. 模型限制开启但机器人未选择任何模型，或交集为空时，允许保存机器人草稿，但禁止机器人测试、发布和任务提交，并展示明确原因；
9. 选择机器人、取消机器人和临时模型切换都只发生在 Core 接受首次 SubmitTurn 之前；接受后以锁定结果为准，首次模型调用失败不重新开放切换。

机器人配置允许多个模型时不提供用户自定义排序。前端严格消费 Core/后台顺序，不得按显示名称、性能、点击先后、
本地缓存顺序或最近使用时间自行选优。

### 7.5 全局 Max 推理开关

#### 用户语义

新任务 Composer 只提供 `default/max` 两种意图：

- `Max` 关闭：遵循当前模型或 Provider 的默认推理行为，不额外发送 Effort、Thinking Level 或推理预算参数；这不表示强制使用最小档；
- `Max` 开启：优先请求当前模型已验证支持的最强推理模式。该模式可能增加响应时间和模型用量，但产品不承诺精确时长、Token 或费用；
- `Max` 不是任务完成的硬性条件；不能安全启用时，任务仍按模型默认模式执行；
- 首次使用默认关闭；用户修改后作为后续新任务的初始偏好。MVP 可以复用既有模型偏好或应用设置，不要求单独建设新的偏好服务、身份体系或数据表；保存失败不影响当前待创建任务，但必须反馈未保存为后续默认；
- 用户不需要理解不同 Provider 的参数名、档位或预算，界面不暴露这些技术差异。

#### 支持映射

Model Adapter 根据平台审核过的模型能力事实解析 `Max`：

| 模型能力形态 | `Max` 开启后的解析 |
| --- | --- |
| 多档强度 | 选择当前模型已验证支持的最高档，例如支持 `low/medium/high` 时解析为 `high` |
| 布尔思考 | 启用模型受支持的思考模式 |
| 预算型 | 使用平台针对该模型审核过的增强预算预设，不使用无上限或用户任意输入预算 |
| 不支持或能力未知 | 不发送无效参数，解析为模型默认行为；提交前已知时提前提示，提交时才发现则在任务反馈中说明 |

模型能力必须来自受控 Catalog、Provider Adapter 或等价可信来源，不由 Renderer、管理员或用户按模型名称猜测。P0 允许先支持已验证的模型和 Provider，未知模型仍可按默认模式完成任务。任务需要保存请求与实际解析结果，并复用既有锁定的模型和 Adapter 事实；除非代码事实证明无法复用，否则产品不要求另建独立 Reasoning Profile、偏好服务或复杂锁层级。

#### 换模、提交与任务锁定

- 首次提交前切换模型，或选择/取消机器人导致 `effectiveModel` 变化时，重新计算 `Max` 的支持状态和解析结果；
- 不支持 `Max` 时保留用户的全局偏好，但当前任务提交前显示“当前模型不支持 Max，将按模型默认模式运行”；不得发送无效参数或把默认行为描述为 `Max` 已生效；
- 提交瞬间能力发生变化或 Adapter 无法安全解析时，不返回仅由 `Max` 引起的强制二次提交；Core 解析为模型默认模式、继续创建任务，并在 Receipt、任务反馈或只读摘要中说明“本次未启用 Max”；
- 首次提交记录用户请求模式与实际解析模式，并与现有 Task Runtime Selection、模型锁或等价任务事实一起持久化。产品只要求结果可恢复，不指定必须新增独立 `ReasoningModeLock`；
- 同一任务后续对话、Tool 后的再次模型调用、重试和应用重启恢复沿用锁定结果，不根据最新全局偏好、Catalog 或 Adapter 映射重新计算；
- 用户之后改变全局开关只影响后续新任务；需要不同推理模式时创建新任务；
- 推理模式不改变用户权限、Workspace、Tool 风险确认、机器人模型范围或 Credential 边界。

### 7.6 任务中的模型交互与 Streaming

模型管理与模型运行使用同一锁定结果，但前端不得把设置页状态复制为任务状态机。

- 任务提交前的选择摘要展示当前有效模型；企业/个人来源只在需要解释同名、故障或数据外发时补充；
- 外部模型调用是否需要确认，继续由 Workspace 与智能授权、模型外发 Scope 和 Core 风险事实决定，本 Spec 不复制 DFI-2B 风险矩阵；
- 确认卡片只展示外发目标、锁定模型、数据类别与范围摘要，以及允许、拒绝或取消动作，不展示完整正文、Key、Credential Reference 或内部 Binding；
- 任务运行至少区分 `connecting`、`generating`、`reconnecting`、`enterprise_unavailable`、`manual_attention`、`completed`、`failed`、`cancelled`、`timed_out`；
- `connecting` 和 `reconnecting` 提供可理解的进行中说明，不把网络重试伪装成模型重新选择；
- ephemeral Streaming 只作为当前回复的临时展示；持久 Assistant Message 到达后替换临时内容，不能重复保存两份；
- 应用重启后只从持久消息、锁定模型和 Core 状态恢复，不恢复过期 delta，不重新选择模型；
- 企业模型不可用只影响依赖该企业目标的任务；个人模型 Credential/Endpoint 失败只影响对应个人模型，不互相静默回退；
- 模型失败、取消、超时或需要人工处理时，页面展示原因摘要和允许的下一步，不展示模型私有思考或原始 Provider 响应；
- 用户要使用其他模型时创建新任务；本期不通过“重试”在同一任务中偷偷更换模型。

## 8. 删除个人模型

- 只有个人模型可以在 Desktop 删除；企业模型由后台管理；
- 存在使用该模型的执行中任务时禁止删除；Core 必须在提交删除时重新检查，不能只相信前端缓存；
- 已完成、失败、取消或超时任务不阻止删除，历史任务保留当时锁定的显示名称、来源和必要追溯摘要；
- 删除的是 `userPreferredModel` 时，删除成功后按 §7.2 重新确定有效模型：优先后台顺序中的第一个可用企业模型；企业模型为空但仍有可用个人模型时要求用户明确选择；两类模型均不可用时阻止新任务；
- 机器人草稿引用该模型但没有执行中任务时允许删除；引用进入不可用状态，新任务提交前必须修正；
- 删除必须同时使个人模型配置不可再选择，并删除对应本机 Credential；
- 模型记录删除成功但 Credential 删除结果不确定时不得伪装完整成功，进入需要人工处理或明确重试状态；
- 删除期间模型 revision、权限或执行中任务事实变化时拒绝删除并要求刷新；
- 删除不可通过隐藏列表项代替真实 Core/Credential 删除事实。

## 9. Credential 安全与数据最小化

### 9.1 允许的短暂明文范围

Renderer 仅可在以下受控交互期间短暂处理个人 API Key 明文：

- 用户正在输入新增或替换 Key；
- 用户提交保存；
- 所有者主动查看已保存 Key。

明文只能存在于当前敏感输入/查看组件的最短生命周期，不得进入全局 Store、路由参数、普通 ViewModel、LocalStorage、SessionStorage、IndexedDB 或持久化状态。隐藏、离开页面、关闭弹窗或组件卸载后必须清除。

### 9.2 禁止进入的边界

个人 API Key 明文不得进入：

- URL、Query String 和命令行参数；
- 普通 HTTP/SSE payload 或访问日志；
- SQLite、Task、Session、Conversation、Event、Receipt、Effect、Artifact 或审计；
- 日志、Trace、埋点、错误对象、Crash metadata 和常规诊断；
- Renderer 全局状态、调试输出和持久化缓存；
- Contract Fixture、测试 Snapshot、Golden File 和 QA Evidence；
- 产品文档、官方演示截图和测试截图中的真实用户 Secret。

测试、演示和截图统一使用明确的假 Key。应用不负责检测用户或操作系统进行的截图/录屏。

### 9.3 存储与调用

- Local Core 是个人模型与 Credential 生命周期的业务 owner；
- PersonalCredentialStore/OS Keychain 保存 Secret，只持久化 opaque reference 与安全状态；
- Model Provider Adapter 在调用所需的最短生命周期解析 Secret；
- 企业 Credential 与个人 Credential 使用不同存储、调用和权限域；
- Keychain 不可用时个人模型失败关闭，不静默切换企业模型；
- Renderer 不自行实现加密、Keychain、本地文件 Secret、SQLite Secret 或通用 Secret Store。

### 9.4 保存后查看的架构门槛

ADR-013 当前只冻结 Renderer 一次采集和 Core/Keychain 解析，不包含“已保存 Secret 返回 Renderer”的产品路径。实现本 Spec 的查看能力前必须：

1. 通过 ADR-013 Addendum 或等价架构决策明确反向读取是否接受；
2. 冻结仅限模型所有者、仅限本机当前会话的受控敏感通道；
3. 证明 Secret 不经过普通 localhost HTTP、公共 Contract、日志或命令行；
4. 明确隐藏/离开后的内存清理和错误失败关闭；
5. 完成专项敏感信息扫描与独立 QA。

该门槛未关闭时，前端可以实现默认掩码和待接入状态，但不能伪造真实回显。

## 10. Mock、Prototype 与真实接入

### 10.1 Mock 阶段

- 可以展示企业模型只读样例、个人模型表单结构、状态和机器人约束交互；
- 个人 Key 输入框必须禁用、使用明显假值或标注“待接入”，不得诱导用户粘贴真实 Key；
- 不得把本地数组或 LocalStorage 变化宣传为保存、默认、删除或 Credential 成功；
- 不展示“测试连接”，也不模拟测试成功；
- 可以使用明确 Fixture 演示 `Max` 支持、不支持与换模重算，但不得把 Renderer 本地布尔值冒充真实 Adapter 解析或任务锁定；
- Mock 数据必须与真实企业/个人数据明确区分。

### 10.2 真实接入

以下条件全部满足后，才允许开放真实个人模型操作：

- 本 Spec 通过文档复核；
- ADR-013 PersonalCredentialStore 和目标 OS Keychain Adapter 有真实实现与测试；
- 新增/替换 Key 的受控敏感通道冻结；
- 如实现保存后查看，ADR-013 反向读取增补已接受；
- Personal Model CRUD、默认偏好、状态和删除阻断具有受支持 Contract/Projection；
- Core 完成模型约束、任务锁定、并发 revision 和执行中任务检查；
- 专项安全测试、敏感信息扫描和独立 QA 通过；
- 用户明确授权对应 DFI 和 DFE 编码批次。

真实 `Max` 开关还必须满足：受支持 Contract 能表达请求与解析结果；Core 在任务首次提交时保存结果并支持恢复；至少一个实际交付的企业或个人 Model Adapter 具有受控映射和默认降级路径；端到端验证覆盖关闭、支持、不支持、后续轮次、重试与重启。P0 不要求一次适配所有模型，也不要求独立偏好服务或独立锁体系。条件未关闭前，生产可点击开关继续 GATED。

## 11. 系统职责与依赖

| 层级 | 业务职责 | 不得承担 |
| --- | --- | --- |
| Central 后台 | 企业模型配置/排序/权限；个人模型配置权限 | 接收或查看个人 Key |
| Desktop Core | 个人模型生命周期、用户默认模型、机器人约束、状态、任务与 `Max` 请求/解析结果记录和恢复、删除阻断 | 把 Secret 写入 Task/Event/Audit，按模型名称猜测推理能力，因 `Max` 无法启用而阻断可正常运行的任务 |
| Model Adapter / Capability Catalog | 把 `Max` 映射为当前模型已审核的最强受支持模式，提供版本化能力事实 | 接受 Renderer 任意参数或无界预算，重新解释已锁定任务 |
| PersonalCredentialStore / Main Broker | 本机 Secret 保存、替换、解析、删除；经增补后可提供受控所有者查看 | 通用 Secret 服务、普通 HTTP 回显 |
| Renderer | 展示安全 Projection；短暂采集或按授权查看 Key；提交用户操作意图 | 推断业务状态、持久化 Secret、实现第二套模型状态机 |
| Contract / Projection | 模型 ID、名称、来源、状态、权限、默认/有效选择、`Max` 支持摘要、任务请求/解析结果和掩码状态 | 企业/个人 Secret、内部 Credential Reference、原始 Provider 参数或错误 |

实现依赖关系：

```text
DFE-5.0 文档确认
→ Model Experience Feature Spec 文档复核
→ Personal Model / Credential 后端详细方案（建议 DFI-4A）
→ DFE-5A 编码范围单独授权
```

DFI-2B 负责智能授权风险矩阵、Confirmation 策略和恢复 E2E，不是个人模型管理的依赖，也不因本 Spec 或 DFE-5A 自动启动。

## 12. 错误与反馈

| 场景 | 用户体验 |
| --- | --- |
| 无个人模型权限 | 不展示添加入口；既有个人模型禁用，允许删除本地配置 |
| 企业模型列表为空 | 有有效个人默认模型时继续使用；否则存在可用个人模型时要求明确选择；企业和个人模型都不可用时才阻止新任务 |
| 保存失败 | 停留表单，保留非敏感字段，展示可重试摘要 |
| Credential Store 不可用 | 个人模型不可用，说明本机安全存储不可用，不降级到明文文件 |
| 查看 Key 不受支持 | 保持掩码，展示“当前版本暂不支持查看”，不返回空值伪装成功 |
| 首次真实调用失败 | 更新为对应类型化状态，任务显示失败原因和修复入口 |
| 机器人无可用模型 | 阻止选择或提交，说明机器人模型范围不可用 |
| 默认偏好保存失败 | 不显示已保存反馈；当前有效模型以 Core 结果为准 |
| 当前模型不支持 Max | 提交前持续显示说明；按模型默认模式运行，不发送无效参数，不伪装 Max 生效 |
| 提交时 Max 能力变化或安全映射失败 | Core 不发送无效参数，按模型默认模式继续任务，并在 Receipt、任务反馈或只读摘要中说明“本次未启用 Max” |
| Max 偏好保存失败 | 当前待创建任务仍使用本次选择；提示未保存为后续默认，不伪装持久化成功 |
| 删除时存在执行中任务 | 拒绝删除并说明原因，不泄露任务正文 |
| 删除 Credential 结果不确定 | 不宣称完整删除，进入明确重试或人工处理状态 |

错误文案不得包含 Key、完整 Endpoint Query、Provider 原始响应、内部 Credential Reference、堆栈或任务正文。

## 14. 非功能要求

### 14.1 性能建议

- 已有安全 Projection 下，模型列表首屏目标 1 秒内可交互；
- 模型切换与机器人约束计算目标 100 毫秒内完成，不包含远程网络请求；
- 本期保存不执行测试连接，保存耗时主要由本机 Credential Store 和 Core 持久化决定；
- 列表和选择器必须在 100 个可用模型内保持可搜索和可键盘操作。

### 14.2 可靠性

- 模型元数据与 Credential 保存不得产生“配置存在但 Secret 丢失”的假成功；
- 用户默认模型和任务锁定模型必须分离，不因列表刷新、权限变化或机器人取消而混写；
- 全局 `Max` 偏好与当前任务记录的请求/解析结果必须分离；重试、后续轮次和重启恢复不得根据最新全局偏好重新解析已创建任务；
- `Max` 沿用既有有界超时、取消和重试原则；Adapter 可以为已验证模型提供受控、有限的超时配置，但不得形成无界时长、预算或重试次数；
- 删除、更新和默认切换使用 revision/幂等语义，重复提交不产生重复模型；
- 应用重启后恢复用户默认偏好，已经开始的任务继续使用原锁定模型；
- 任何 Credential、权限或状态不确定都只能收窄能力，不能静默扩大或替换模型。

### 14.3 可访问性

- Key 隐藏/显示按钮具有明确 `aria-label` 和键盘操作；
- 模型禁用原因可被辅助技术读取，不只依赖颜色；
- 机器人导致模型临时切换时使用持久、非 Toast-only 的提示；
- 表单错误就近展示并把焦点移动到首个可修复字段。

## 15. 验收标准

### 15.1 产品与前端

- [ ] 企业模型按后台顺序展示；有效用户偏好优先，没有有效偏好时选择第一个可用企业模型；企业模型为空但有可用个人模型时要求明确选择；
- [ ] 只有获得后台权限的用户能看到并使用“添加个人模型”；
- [ ] 个人模型字段固定为提供商、接口地址、API Key、模型标识、显示名称；模型标识精确提交给 Provider，显示名称默认等于模型标识；
- [ ] DeepSeek、智谱、Kimi 自动带出受控接口地址，自定义要求用户填写且只支持冻结协议；
- [ ] 个人模型页面不展示“测试连接”，保存成功后的初始状态为“未验证”；
- [ ] 模型选择器常规只展示显示名称；同名时提供最小来源说明；
- [ ] 用户在无机器人约束的新任务中手动选模后，后续新任务使用该用户默认模型；
- [ ] 机器人模型限制关闭时允许当前用户全部合法模型；开启后只允许已选模型与用户合法模型的交集；
- [ ] 选择机器人时不兼容的用户默认模型按 Core/后台稳定顺序被临时替换，页面有明确说明，取消机器人后恢复用户默认模型；前端不提供或推断另一套排序；
- [ ] 机器人临时模型选择不覆盖用户默认模型；限制开启但未选择模型或交集为空时允许保存草稿，但阻止测试、发布和任务提交；
- [ ] Core 接受首次 SubmitTurn 后模型锁定，同一任务不提供切换入口，首次模型调用失败不重新开放；
- [ ] 新任务 Composer 只提供一个 `Max` 开关；首次默认关闭，关闭时沿用模型默认行为且不发送额外推理参数；
- [ ] 开启 `Max` 后优先由可信 Adapter 映射到当前模型已验证的最强模式；换模或机器人约束改变有效模型时重新计算；
- [ ] 当前模型不支持 `Max` 时提交前持续说明并解析为模型默认行为，不发送无效参数或展示虚假生效；
- [ ] 提交时能力变化或安全映射失败不阻止任务，系统使用模型默认模式并在任务反馈中说明“本次未启用 Max”；
- [ ] 全局偏好只初始化后续新任务；任务首次提交记录请求与解析结果，后续对话、Tool 后调用、重试和重启恢复保持一致；偏好保存失败不影响当前任务；
- [ ] 任务选择摘要、外发确认和运行状态使用同一个锁定模型；确认卡片不展示正文或凭证；
- [ ] Streaming 临时内容在持久消息到达后被替换，重启后不重复恢复 delta 或重新选择模型；
- [ ] 企业/个人模型故障范围保持隔离，失败、取消、超时和人工处理均有明确下一步且不静默换模；
- [ ] 个人模型存在执行中任务时不可删除；其他终态任务不阻止删除；
- [ ] 删除用户默认模型后按统一初始规则重新选择；企业模型为空但有其他可用个人模型时要求用户明确选择；历史任务保留模型追溯摘要；
- [ ] 八种状态具有明确来源、选择可用性和修复动作；网络失败保留最近失败警告但允许再次选择并真实重试；
- [ ] Mock 阶段不接收真实 Key，不伪造保存、查看、默认或删除成功。

### 15.2 Credential 与安全

- [ ] 企业模型 Credential 从不进入 Desktop；个人 Key 从不进入 Central；
- [ ] 新增/替换 Key 默认隐藏，可在当前输入期间主动显示；
- [ ] 保存后默认显示掩码，所有者主动查看后可以再次隐藏；离开页面后清除 Renderer 明文；
- [ ] 应用不实现截图检测或阻断；官方测试和演示只使用假 Key；
- [ ] Key 不进入日志、Trace、埋点、错误、Crash metadata、Fixture、Snapshot、QA evidence 或持久化 Renderer 状态；
- [ ] PersonalCredentialStore 不可用时失败关闭，不以文件或 SQLite 明文降级；
- [ ] 查看已保存 Key 的反向敏感通道在实现前完成 ADR-013 增补和专项 QA；
- [ ] 删除个人模型后旧 Credential 不可继续解析；结果不确定时不伪装完整成功。

### 15.3 Core、Contract 与端到端

- [ ] Central 企业模型顺序、个人模型权限、Core 用户默认偏好和任务有效模型具有唯一事实源；
- [ ] `userPreferredModel` 与 `effectiveModel` 不混写，机器人选择/取消和应用重启场景可重复验证；
- [ ] 任务锁定模型不因用户偏好、列表刷新或权限变化静默改变；
- [ ] `Max` 请求模式、解析模式与当前任务模型/Adapter 事实形成可恢复的一致记录；允许复用既有任务选择与模型锁，不将独立锁对象作为验收前提；
- [ ] 关闭、支持、不支持、提交时能力变化、映射失败、偏好保存失败、后续轮次、重试和重启场景通过真实 E2E，任何 `Max` 降级都不阻断可正常运行的核心任务；
- [ ] 保存、更新、默认切换和删除具有 revision、幂等与冲突测试；
- [ ] 执行中任务删除阻断由 Core 在提交时重新判断；
- [ ] 未验证模型的首次真实调用能够收敛到“可用”或对应失败状态；网络失败模型可通过下一次真实调用恢复，不形成无法触发恢复的禁用死路；
- [ ] 企业与个人 Provider 路径、Credential 域和故障不会互相静默回退；
- [ ] Desktop → 受控通道 → Core → Credential Store 的新增、替换、使用和删除链路通过真实 E2E；
- [ ] 如交付保存后查看，所有者校验、反向敏感通道、隐藏清理和泄漏扫描通过真实 E2E；
- [ ] 独立 QA 确认不存在可点击假成功、Secret 泄漏或 DFI-2B 超前启动。

## 16. 交付门槛与阶段建议

产品语义已经冻结，文档完成不等于授权编码。

### 16.1 DFE-5A.1 候选范围

- 企业模型安全只读列表；
- 个人模型页面结构和字段；
- 默认/有效模型、机器人约束和八种状态的纯 ViewModel；
- 明确 GATED 的新增、查看、保存、删除状态；
- 不接收真实 Key，不产生真实成功。
- `Max` 开关只允许静态/GATED 或明确 Fixture 演示，不把本地状态当作真实模型调用参数。

### 16.2 真实接入候选范围

建议先形成 DFI-4A 或等价的 Personal Model/Credential 详细方案，冻结：

- Personal Model CRUD、状态、默认偏好和机器人约束的 Core 所有权；
- 新增/替换 Key 的受控敏感通道；
- OS Keychain Adapter 与 PersonalCredentialStore；
- 删除与执行中任务检查；
- Provider Adapter、未验证状态和首次调用收敛；
- 保存后查看所需 ADR-013 增补；
- Contract/Projection、错误码、恢复、敏感扫描和 E2E。
- `Max` 请求/解析结果、对既有任务选择/模型锁的最小复用、Model Adapter 映射和默认降级路径。

上述方案通过独立评审并获得用户编码授权后，再确定 DFE-5A 的真实集成批次。

### 16.3 与 DFI-2B 的关系

- DFI-2B 继续 `GATED`；
- 本 Spec、DFE-5.0 或 DFE-5A 文档完成均不构成 DFI-2B 编码授权；
- 智能授权风险矩阵与个人模型管理分别评审、分别编码、分别验收；
- 两者仅在创建任务时共同进入已受支持的 Task Selection/Runtime Selection，不互相拥有业务状态。

### 16.4 Max 实施范围收敛

- 产品按一个端到端功能验收：最小 Contract/Core 传递、已验证 Adapter 映射、Composer 开关和任务生命周期 E2E；研发可以内部拆分提交，但不要求五个独立产品项目或五次产品授权；
- 优先复用既有模型偏好、应用设置、Task Runtime Selection、模型锁和 Adapter Descriptor；只有代码事实证明无法满足真实生效与恢复时，才增加新的最小记录或 Port；
- P0 只需覆盖首批已验证模型/Provider，其余模型明确显示不支持并按默认模式运行；
- `Max` 不建立独立成本系统、无限推理预算、无限超时或无限重试，也不改变 Workspace、Tool、权限和确认规则。
