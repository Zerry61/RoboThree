## 2. 文档目标

本规范用于统一 RoboThree Desktop Client 与 Admin Console 的前端体验，确保不同模块在以下方面保持一致：

- 导航和页面层级；
- 列表、详情、创建和编辑页面结构；
- Loading、Empty、Error、Disabled 等通用状态；
- 搜索、筛选、分页和表单操作；
- 权限不足、服务不可用和数据过期体验；
- 凭证、本地路径、任务正文等敏感信息展示边界；
- Mock、Prototype 和真实业务状态的区分；
- 中文业务术语、提示文案和基础可访问性。

本规范不重新定义机器人、技能、工具、模型、知识、任务和成果的业务规则。具体模块进入真实链路前，仍需按照 PRD 要求形成对应 Feature Spec。

## 3. 事实来源与优先级

发生冲突时，按以下顺序处理：

1. 已接受的 Contract、ADR 和安全边界；
2. `PRD-ROBOTHREE-MVP.md` v1.6 Final Revision 15；
3. 已确认的模块 Feature Spec；
4. 本全局体验规范；
5. 前端 Living Spec 中的临时交互假设；
6. Mock 数据和演示实现。

前端不得为了完成页面效果而自行新增或修改：

- 公共 Contract；
- Desktop IPC；
- Core/Central 业务状态；
- 权限事实；
- 持久化事实；
- 审计字段；
- Credential、真实路径和敏感内容展示规则。

发现现有数据不足时，应记录为“数据需求”或“待确认项”，不得在前端静默补造业务事实。

用户侧统一使用以下中文名称：

| 技能 | Skill |
| 工具 | Tool |
| 模型 | Model |
| 知识 | Knowledge |
| 项目空间 | Workspace |

| 成果 | Artifact |

全局规则：

- 一级导航和页面标题不使用 Agent、Skill、Tool 或“能力中心”等替代名称；
- 首次需要解释技术概念时，可以使用“机器人（Agent）”形式，后续只使用中文名称；

- 用户界面不展示 Receipt、Effect、Outbox、Lease、Fencing、Projection 等内部术语；
- 错误信息使用用户语言，不直接展示异常栈、进程信息和数据库字段。

## 5. 信息架构与页面地图

### 5.1 Desktop Client 一级导航

一级导航固定为：

```text
工作台
任务
智能中心
知识中心
设置
```

成果不作为一级导航，主要通过工作台最近成果、任务详情和项目空间入口访问。

### 5.2 Desktop Client 页面地图

| 一级导航 | 页面 | 优先级 |
| --- | --- | --- |
| 工作台 | 新建任务、最近任务、最近成果、项目空间选择 | P0 |
| 任务 | 任务列表、任务详情 | P0 |
| 智能中心 | 机器人列表/详情/创建，技能列表/详情/创建，工具列表/详情 | P0 |
| 知识中心 | 知识列表、知识详情、检索测试 | P0 Conditional |
| 设置 | 模型管理 | P0 |
| 设置 | 个性化 | P1 / Prototype |
| 设置 | 个人记忆 | P1 / Prototype / Gated |
| 设置 | 问题反馈 | P1 / Prototype |
| 设置 | 登录与身份信息 | P1 / Enterprise Integration |

智能中心内部页面固定为：

- 机器人：`全部 / 我创建的`；
- 技能：`技能广场 / 已安装 / 本地目录 / 我创建的`，不提供“全部”；
- 工具：不设置子分类，使用单一卡片列表；
- 机器人、技能和工具的查询、筛选、选中状态彼此独立，不相互联动。

### 5.3 Admin Console 页面地图

| 模块 | 页面 | 优先级 |
| --- | --- | --- |
| 模型管理 | 列表、详情、新增/编辑 | P0 |
| 工具管理 | 统一列表/详情、代码工具自动登记后的策略配置、HTTP 新增/编辑、MCP 连接/发现/注册 | P0 / 分批 Gated |
| 机器人管理 | 列表、详情、使用限制开关创建/编辑草稿、审核 | P0 |
| 技能管理 | 列表、详情、上传并解析技能压缩包、编辑技能信息、保存草稿、审核 | P0 |
| 知识管理 | 列表、详情、新增/编辑、连接测试 | P0 Conditional |
| 系统管理 | 二级页面：用户与权限、审计日志、反馈管理；不设置独立概览页 | 用户与权限/审计日志 P0；反馈管理 P1 / Prototype |

### 5.4 页面层级原则

- 一级导航通常进入模块首页；系统管理是导航分组，按第 6.2 节直接进入第一个有权访问的二级页面；
- 列表页负责发现、筛选和进入对象；
- 详情页负责查看完整信息、状态和允许操作；
- 创建/编辑页负责修改草稿或配置；
- 高风险确认使用弹窗或确认卡片，不在普通提示中完成；
- 不为同一对象同时建立两个相互独立的详情事实源。

任务详情是会话型工作页面，不强制套用普通对象详情页的信息区块；其右侧操作面板遵循第 9 章专项规范。

## 6. 全局应用框架

### 6.1 Desktop Client

Desktop 默认由以下区域构成：

1. 左侧导航区；
2. 主内容区；
3. 浮层区，包括弹窗、抽屉、选择器和确认卡片；
4. 用户与设置入口。

左侧导航应满足：

- 当前一级导航具有明确选中状态；
- 支持展开和收起；
- 收起后仍可通过图标、提示和键盘访问主要入口；
- 动态任务或项目空间内容不能挤压或隐藏固定一级导航；
- 用户头像、姓名和设置入口保持稳定位置；
- 页面切换不得中断正在执行的任务。

### 6.2 Admin Console

Admin 默认由以下区域构成：

1. 左侧模块导航；
2. 顶部页面标题和当前用户区域；
3. 主内容区；
4. 全局反馈层。

Admin 不建设运营大盘。默认进入首个有权限的管理模块；没有任何管理权限时展示无权限页面，不显示空白后台。

Admin 一级导航固定为“模型管理 / 工具管理 / 机器人管理 / 技能管理 / 知识管理 / 系统管理”六项。“系统管理”展开或进入后提供“用户与权限 / 审计日志 / 反馈管理”三个二级入口，不额外建设系统管理首页：

- 点击系统管理时进入当前管理员有权限访问的第一个二级页面，默认优先“用户与权限”；
- 没有“查看审计”权限时隐藏“审计日志”，不能只禁用后仍暴露入口；
- 进入二级页面的列表、详情和编辑路由时，一级“系统管理”和当前二级入口均保持选中；
- 当前反馈页面只处理用户反馈，统一使用“反馈管理”名称；企业公告、消息模板和通知渠道不在本期页面中；
- 如果没有任何系统管理子页面权限，则不展示“系统管理”一级入口。

### 6.3 页面标题区

列表、详情和编辑页面统一包含：

- 页面标题；
- 一句简短说明；
- 当前对象状态或模块状态；
- 主要操作；
- 返回或面包屑入口。

同一页面只保留一个主要操作，例如“创建模型”或“保存”。次要操作不得与主要操作具有相同视觉优先级。

任务详情标题区属于专项例外：只保留任务标题，不显示“创建于… · 耗时… · 空间”元信息行，也不提供包含重命名或删除的“⋯”菜单。右侧操作面板收起时，标题右侧仅显示“«”展开按钮；面板展开时该按钮不存在。

## 7. 通用页面状态

每个 P0 模块必须识别以下状态是否适用，并在模块 Feature Spec 或前端 Living Spec 中记录。基础状态必须覆盖；条件状态在业务存在对应场景时实现，不适用时明确标记 `N/A`，不得用空白页面或普通错误代替。

| 状态 | 要求 | 展示内容 | 主要操作 |
| --- | --- | --- | --- |
| Loading | 基础 | 稳定骨架或进度提示 | 必要时允许取消 |
| Empty | 基础 | 空原因和下一步说明 | 创建、添加、选择或刷新 |
| Ready | 基础 | 正常数据和允许操作 | 按页面定义 |
| Permission denied | 基础 | 权限不足说明 | 返回、切换对象或联系管理员 |
| Unavailable | 基础 | 依赖不可用及影响范围 | 重试、使用其他可用能力或返回 |
| Error | 基础 | 用户可理解的错误摘要 | 重试、修改输入、查看诊断摘要 |
| Disabled | 条件 | 对象已停用或不可操作原因 | 返回、查看详情或联系管理员 |
| Stale | 条件 | 数据已更新或当前版本过期 | 刷新，不覆盖较新事实 |
| Partial | 条件 | 部分数据可用、部分失败 | 继续查看可用部分并重试失败部分 |

统一规则：

- 不出现无反馈白屏；
- Disabled、Permission denied 和 Unavailable 必须区分；
- 错误提示说明“发生了什么、是否可重试、下一步是什么”；
- 未知错误可以显示 correlation ID，但不得暴露内部栈和敏感字段；
- 页面局部失败不应导致整个应用不可用；
- 状态变化不得只依赖颜色表达。

## 8. 列表页规范

### 8.1 标准结构

列表页按以下顺序组织：

1. 页面标题与说明；
2. 主要操作；
3. 搜索和筛选；
4. 结果数量或当前范围；
5. 列表、表格或卡片；
6. 分页或继续加载；
7. 空状态和错误状态。

### 8.2 展示方式

- Desktop 智能中心的机器人、技能和工具统一使用卡片列表；
- Admin Console 的模型、工具，以及系统管理中的用户与权限、审计日志等管理对象优先使用表格；
- 同一模块不因数据数量变化随意切换卡片和表格；
- 列表必须展示对象名称和最重要的识别信息；是否展示状态严格按模块规则执行，机器人卡片不展示状态标签；
- 敏感字段、完整路径和凭证明文不得作为列表字段。

智能中心卡片字段固定为：

| 对象 | 卡片字段 |
| --- | --- |
| 机器人 | 图标、机器人名称、来源 · 创建人、简介；不展示状态标签 |
| 技能 | 技能标题、技能名称、创建人或所属目录、技能描述；不展示图标、分类或状态标签 |
| 工具 | 工具名称、来源 · 类型、描述、风险等级、状态；不展示图标，风险等级和状态使用中性灰标签 |

技能名称是技术标识，使用较小的次要文本；“技能广场”“已安装”“我创建的”展示创建人，“本地目录”展示工作区文件夹名称。来源、创建人和目录是文本元数据，不显示为分类标签。

工具 Tab 的标题区不提供“＋申请工具”或其他用户新增入口；工具由管理员在中央配置，Desktop 只提供浏览和详情。

### 8.3 搜索

搜索统一遵循：

- 输入后展示明确搜索状态；
- 支持清空搜索；
- 无结果时保留原搜索条件，并提供修改建议；
- 搜索不应自动扩大资源权限和数据范围；
- 本地任务搜索与企业资源搜索必须使用各自允许的数据源；
- 搜索结果中的同名技能、机器人或模型必须展示来源。

### 8.4 筛选与排序

- 只提供用户能理解且有稳定业务含义的筛选项；
- 筛选条件应可清除；
- 多个筛选条件同时生效时展示已选条件；
- 默认排序规则在模块 Feature Spec 中定义；
- 前端不得根据未确认字段自行建立“智能排序”或推荐分。

任务列表使用 PRD 已确认的固定排序：

- 置顶任务位于普通任务之前；
- 置顶任务按置顶时间倒序，普通任务按更新时间倒序；
- 搜索和筛选只改变当前结果范围，不改变两组内部排序规则；
- 取消置顶后，任务按更新时间回到普通任务中的对应位置；
- 不使用前端临时数组顺序伪装持久置顶状态。

### 8.5 分页与加载更多

- Admin 表格默认采用分页；
- Desktop 卡片列表可以使用分页或加载更多；
- 翻页和筛选后保留当前查询条件；
- 加载下一页失败时保留已加载数据；
- 不使用虚假的总数或使用次数。

## 9. 详情页规范

### 9.1 通用详情页

除 9.2～9.7 定义的任务详情专项布局外，普通对象详情页统一包含：

1. 对象名称、状态和来源；
2. 简介或用途说明；
3. 主要操作；
4. 基础信息；
5. 能力、权限或关联信息；
6. 状态与最近错误；
7. 版本、更新时间或来源信息；
8. 该模块 Feature Spec 规定的专项内容。

全局规则：

- 详情页默认只读；
- 编辑通过明确“编辑”操作进入；
- 已发布机器人或技能不得直接在详情页修改；
- API Key 保存后只展示“已配置”或掩码状态；
- 本地技能路径只展示安全摘要，不默认展示完整用户目录；
- 历史对象已下架或停用时仍可查看必要元数据；
- 资源不可用不等于删除，页面需说明状态及影响。

#### 技能详情专项

技能详情的主要信息固定为：

| 字段 | 展示要求 |
| --- | --- |
| 技能标题 | 用户命名的展示标题，例如“全栈设计” |
| 技能名称 | 英文技术标识，例如 `ui-ux-pro-max` |
| 技能描述 | 展示技能用途说明 |
| 技能行为与规则 | 展示技能工作准则、步骤和约束 |

技能来源、目录、测试、安装或发布操作可以作为页面辅助信息或操作区存在，不扩展上述主要信息字段。“我创建的”草稿详情提供“运行测试”和“提交发布”；创建助手对话页不重复提供这两个操作。

“我创建的”草稿详情至少覆盖未测试、测试中、测试通过和测试失败。测试结果必须标明对应的草稿版本或当前有效性；草稿内容改变后，旧测试结果进入失效状态，不得继续显示为当前版本已通过。测试失败保留草稿并提供重试。真实 revision、测试结果和提交门槛由 Agent/Skill Feature Spec 与受支持 Contract 定义。

技能广场详情的“安装”不是仅修改一个前端状态。点击后进入下载安装过程，依次展示下载、校验、解压和完成；成功后进入“已安装”。目标位置使用用户可理解的“用户技能目录”或“当前项目技能目录”，完整绝对路径只在受控文件操作需要时展示，不进入列表、日志或埋点。失败页面说明失败阶段并允许重试；系统清理暂存文件和半安装目录，不把失败结果显示为已安装。

P0 安装不执行压缩包中的脚本，不自动安装 Python、Node.js 或系统依赖。若 `SKILL.md` 声明环境或 Tool 要求，详情页可以在安装前展示说明，但实际执行与依赖准备仍走受控 Runtime、Tool 和授权流程。同名不同版本不得静默覆盖；发现新版本时使用明确的“更新”操作。

### 9.2 任务详情布局

任务详情由对话区和右侧操作面板构成：

- 对话区承载消息、继续输入、确认卡片及与会话直接相关的持续反馈；
- 右侧操作面板承载产物、任务进程、工作空间目录和文件预览；
- 右侧面板不是普通抽屉，不遮挡时应与对话区形成稳定分栏；
- 面板的切换、折叠、全屏和文件标签操作不得改变任务运行状态；视图数据可以按需加载，加载期间使用对应区域的独立状态，不阻断对话。

### 9.3 面板视图与概览

面板左上角使用“概览 ▾”下拉菜单切换两个固定视图：

| 视图 | 内容 |
| --- | --- |
| 概览 | 默认视图；包含“产物”和“任务进程”两个可折叠区块 |
| 工作空间文件 | 当前任务工作空间的嵌套文件目录树 |

概览视图要求：

- “产物”在上，“任务进程”在下，两个区块可独立展开和收起；
- 产物条目固定展示图标、文件名、“类型 · 时间”；
- 任务进程按计划步骤在前、工具调用记录在后的顺序展示；
- 计划步骤使用状态点和文本共同表达完成状态，不只依赖颜色；
- 工具调用记录使用用户可理解的工具名称、结果或错误摘要，不展示模型私有思考、原始参数、凭证或基础设施细节。

“产物”只作为界面分组名称，继续复用现有 Artifact / 成果事实。

### 9.4 工作空间文件视图

- 使用树形结构展示文件夹和文件，支持多级目录；
- 文件夹节点可展开和收起，并通过图标、名称和可访问状态表达层级；
- 只展示当前任务已授权 Workspace 范围内的内容；
- 默认展示安全相对路径或节点名称，不展示未经脱敏的绝对路径；
- 空目录、读取中、权限不足和读取失败分别展示对应页面内状态；
- 当前版本只承诺目录浏览，不在树中提供编辑、移动、重命名或删除操作。

### 9.5 文件标签与预览

- 点击产物条目后，在右侧面板顶部新增并激活文件标签，不跳转到独立“成果”页面；
- 每个标签包含文件名和关闭“×”，支持多个标签并存、切换和关闭；同一文件只保留一个标签；
- 关闭活动标签后激活相邻标签，关闭最后一个标签后返回最近使用的面板视图；
- 打开的文件标签与“概览/工作空间文件”视图状态并存，视图切换不得隐式关闭标签；
- Markdown 预览渲染标题、列表、粗体等基础格式；渲染前必须进行安全处理，不执行嵌入脚本；
- HTML 使用项目既有受控本机预览链路和安全边界，不允许通过未经隔离的 `innerHTML` 绕过 CSP、Workspace 授权或 Renderer 边界；
- PDF、XLSX 等二进制文件或不支持文本编码的文件，在活动文件标签内展示空页面提示：“此文件是二进制文件或使用了不受支持的文本编码，所以无法在文本编辑器中显示。”；
- 上述提示属于文件详情页面状态，不使用 Toast；不得将预览不支持误写为文件损坏，也不代表模型或已启用工具无法处理该文件；
- 预览加载中、加载失败和文件已不存在应使用不同页面内状态，并提供可执行的刷新或关闭操作。

### 9.6 工具栏、全屏与收起

面板展开时，右上角工具栏固定包含以下操作，并严格按从左到右排列：

| 顺序 | 图标操作 | 目标与行为 |
| --- | --- | --- |
| 1 | 打开本地文件夹 | 调用操作系统文件管理器打开当前任务所在工作空间目录，即“在文件夹中显示 / Reveal in Finder” |
| 2 | 全屏 | 面板占满 RoboThree 软件窗口内容区域 |
| 3 | 收起 | 完全隐藏面板，并在对话区标题右侧显示“«”展开入口 |

- 三个图标按钮在概览、工作空间文件和文件标签预览状态下常驻相同位置，并具有 Tooltip、辅助技术名称和可见焦点；
- 打开目标由当前任务锁定的 Workspace 决定：默认空间打开对应的用户可展示目录且不暴露应用数据库或其他内部管理文件，非默认空间打开用户已授权的项目空间目录；活动文件标签不改变打开目标；
- Renderer 不直接拼接、持有或执行任意绝对路径；打开操作必须通过受信任的 Desktop Main/Preload 与 Workspace 授权边界解析目标，再调用系统文件管理器；
- 没有可用本地目录、授权失效或目录不存在时，“打开本地文件夹”保留工具栏位置并进入禁用态，同时提供原因；调用系统文件管理器失败时保留面板状态，展示可重试错误；
- 打开系统文件管理器不改变任务运行、当前面板视图、区块折叠状态或文件标签；
- 全屏后面板占满 RoboThree 软件窗口内容区域，再次点击恢复原分栏，不触发操作系统全屏；
- 收起后面板完全隐藏，“»”按钮消失，“«”按钮出现在对话区标题右侧；
- 重新展开后“«”消失，“»”回到面板右上角，两个按钮任何时刻不得同时出现；
- 全屏、收起和重新展开保留当前视图、区块折叠状态、打开的文件标签和活动标签；
- 面板模式切换不得造成焦点丢失：收起后焦点返回“«”，重新展开后焦点进入面板标题或原活动标签。

### 9.7 移除项与操作归属

- 不再保留“任务信息、任务操作、运行组合、计划步骤、工具活动、文件、用户确认、成果”等旧右侧 Section；
- 计划步骤和工具活动合并到“任务进程”，成果文件合并到“产物”，用户确认保留在对话流；
- 任务重命名、置顶和删除以任务列表作为 P0 统一入口，任务详情不再提供管理操作菜单；
- 移除右侧展示不改变 Core Projection、恢复、确认和审计事实，也不得为了适配新面板新增第二套状态。

## 10. 创建与编辑页规范

### 10.1 表单结构

本节适用于模型、知识来源、机器人、企业资源配置和技能创建第一阶段等以结构化字段为主的创建与编辑页面。技能创建第二阶段采用 10.7 的会话式创建助手。

表单按业务含义分组，不按数据库字段分组。常见分组：

- 基础信息；
- 连接或来源；
- 能力配置；
- 使用范围与授权用户；
- 风险与确认；
- 测试和发布信息。

### 10.2 字段规则

- 必填字段有明确标记；
- 可选字段说明用途；
- 字段帮助文本说明影响，不重复字段名称；
- 保存前校验必填、格式和明显冲突；
- 远程校验失败与本地格式错误分开展示；
- 不在用户输入时频繁弹出阻断提示；
- 密钥输入仅在对应 Feature Spec、受控 Credential 链路和真实编码批次获授权后允许粘贴真实值；Mock 阶段必须禁用或使用明确假值；
- 个人模型所有者可以按 `MODEL-EXPERIENCE-FEATURE-SPEC-v1.0.md` 主动查看自己的已保存 Key；其他 Credential 保存后不得再次显示明文。

### 10.3 保存

保存结果必须明确：

- 保存中；
- 保存成功；
- 保存失败；
- 当前数据已过期；
- 是否需要重新测试或发布。

不允许仅关闭弹窗表示保存成功。

### 10.4 未保存修改

用户离开存在未保存修改的页面时，应明确询问：

- 保存并离开；
- 放弃修改；
- 继续编辑。

浏览列表、切换详情 Tab 等不改变编辑草稿的操作，不应重复提示。

### 10.5 测试连接与测试运行

测试与保存分开：

- “测试连接”不等于“保存”；
- 测试成功不自动发布或启用；
- 测试失败保留表单内容或当前草稿文件；
- 测试结果展示成功、认证失败、网络失败、协议不兼容或服务错误；
- 测试结果不得展示 API Key、完整任务正文和敏感响应内容。

个人模型是本期明确例外：个人设置的模型添加/编辑不提供“测试连接”，保存后进入“未验证”，由后续真实任务调用结果更新状态。不得复用本节通用组件擅自增加个人模型测试入口。

### 10.6 创建机器人

#### 基础信息

- 字段固定为头像、名称、标签、简介、行为与规则；
- 头像初始展示系统默认头像，并提供“选择预设”和“上传图片”两类入口；
- 用户选择预设头像后立即更新预览；上传图片后先展示本地预览，真实保存成功前不得标记为已保存；
- 平台预设头像只允许选择和切换，不提供删除或移除操作；用户可以改选其他预设头像或系统默认头像；
- 只有当前头像来自用户上传时，悬停头像才显示覆盖式“×”图标；点击后清除上传头像并恢复系统默认头像，不提供独立“移除”按钮；未上传头像时不显示该图标；
- 上传失败、格式不支持或文件不符合限制时，在头像字段附近显示错误，保留修改前头像，不使用仅 Toast 反馈；
- 头像显示使用统一尺寸与裁切框；真实图片格式、大小、裁切、持久化和删除规则由 Agent/Skill Feature Spec 冻结；
- “简介”用于列表展示，不使用“能力说明”；
- “行为与规则”用于定义工作方式和约束，不使用“Instructions”作为用户界面名称；
- 不展示输入要求、输出要求和风险说明字段。

#### 能力配置开关

| 配置项 | 默认状态 | 开启后交互 |
| --- | --- | --- |
| 模型 | 关闭并收起；不设置机器人级限制，可使用当前用户全部合法模型 | 展开模型多选区；开启后仅允许已选模型 |
| 技能 | 关闭并收起；不设置机器人级限制 | 展开并显示“＋添加技能” |
| 工具 | 关闭并收起；不设置机器人级限制 | 展开并显示“＋添加工具” |
| 知识 | 关闭并收起；不设置机器人级限制 | 展开并显示“＋添加知识” |

- 开关和标题位于同一配置行，点击开关只控制该项；
- 开启时在配置行下方原位展开内容，不跳转新页面；
- 关闭时收起内容，已选内容保留在当前草稿但不生效；再次开启时恢复原选择；
- 开关关闭表示“不设置机器人级限制”，不表示禁止使用全部对应资源；
- 选择弹层只展示当前用户可用资源；模型支持多选，但不提供拖拽或另一套前端排序，展示和回退顺序使用 Core/后台返回的稳定顺序。
- “添加技能”“添加工具”“添加知识”只能在对应限制开关开启后出现；关闭状态下不得保留可点击但隐藏不完整的选择入口；
- 选择器使用抽屉或弹层承载搜索、多选和来源辨识，不把全部资源长期铺在创建表单中；已选项回到展开区以列表或可移除项展示；
- 技能和工具选择项以中文名称、用途和来源为主，同名时补充版本或来源；技术 ID 只在必要的次要信息中展示；
- 开启限制但未选择任何资源时，在展开区显示“该机器人将不能使用任何模型/技能/工具/知识”的就近提示；允许保存草稿；模型为空时禁用“运行测试”和“提交发布”并就近说明，其他资源为空时在测试和发布复核中再次明确；
- 详情和复核摘要使用三种明确文案：关闭为“未设置机器人级限制”，开启且有选择为“仅允许以下资源”，开启且无选择为“不允许使用任何此类资源”。

#### 草稿、测试与发布门槛

- 保存草稿时名称必填；简介和行为与规则允许暂缺，并在草稿详情中标出未完成；
- 运行测试和提交发布时，名称、简介和行为与规则全部必填；错误在字段附近展示；
- 存在未保存修改时，“运行测试”先要求保存，不直接使用临时表单内容；
- 测试页和结果摘要展示实际运行的保存 revision，不用“当前最新”模糊表述；
- 头像和标签只影响展示；名称、简介、行为与规则或任一能力限制变化后保存，产生新的可运行 Agent revision。

### 10.7 创建技能

#### 阶段一：创建表单

- 页面只展示技能名称、描述、技能主要功能三个必填字段和“下一步”按钮；
- 技能名称是用户输入的展示标题，英文技术名称由创建助手生成；
- 描述使用简短文本区域，技能主要功能使用多行文本区域；
- 不展示 Tool、Knowledge、输入输出、脚本语言、依赖、权限或风险配置；
- 字段错误就近展示，不使用 Toast；创建会话失败时停留在当前页、保留全部输入并显示“重试”入口；
- 点击“重试”必须重新调用创建会话流程，不得只清除错误或直接切换页面；重试成功后进入新建任务/会话并继续发送结构化首条消息；
- 每次重新打开创建技能表单都开始新的创建尝试，不继承上一次打开期间的失败或重试状态。

#### 阶段二：对话式创建助手

- 点击“下一步”后新建并打开任务/会话，预选内置“技能创建助手”能力；
- 系统把三个字段整理为第一条可见的用户消息并自动发送，用户不需要再次确认或重复输入；
- 对话页复用任务对话布局，用户可以继续输入、添加已有文件并要求修改；
- 右侧面板展示生成文件、任务进程和工作空间文件；
- 助手生成 `SKILL.md`，并在有实际内容时生成 `references/`、`scripts/`；不生成空目录；
- `SKILL.md` 展示技能标题、英文技术名称、技能描述、技能行为与规则、输入输出和 Tool/Knowledge 要求；
- Tool 和 Knowledge 不在创建表单或对话页形成独立选择器；
- 对话页不展示“运行测试”和“提交发布”按钮；
- 生成有效技能目录后，草稿进入“我创建的”；用户在技能详情查看四项主要信息，并使用“运行测试”和“提交发布”；
- 生成失败时保留会话、自动发送的用户消息和已生成文件，允许继续补充或重试，不返回阶段一重复填写。

#### 原型必须覆盖的状态

- 阶段一默认、字段错误、创建会话失败、失败后真实重试成功，以及重新打开表单后的尝试状态重置；
- 阶段二消息自动发送、生成中、可继续修改、生成失败；
- 生成完成后“我创建的”出现草稿；
- 技能详情展示四项信息、“运行测试”和“提交发布”，并覆盖未测试、测试中、测试通过、测试失败及旧结果失效；
- 对话页始终不出现“运行测试”和“提交发布”。

### 10.8 个人模型管理

#### 页面与字段

- 入口位于“个人设置 → 模型”；后台未授权个人模型配置时不展示添加入口；
- 企业模型为只读，个人模型支持添加、编辑、更换/查看 Key 和删除；
- 字段固定为提供商、接口地址、API Key、模型标识、显示名称；模型标识精确提交给 Provider，显示名称默认等于模型标识；
- Provider 固定为 DeepSeek、智谱、Kimi、自定义；前三者自动带出受控接口地址，自定义由用户填写且只支持已冻结协议；
- 模型列表和任务选择器常规只显示显示名称；同名无法区分时补充最小来源/Provider 信息；
- 页面不展示“测试连接”，保存成功只表示配置和 Credential 已保存，初始状态为“未验证”。

#### 默认模型与机器人约束

- 有效用户偏好优先；没有有效用户偏好时，使用后台顺序中的第一个可用企业模型；
- 企业模型为空或均不可用但存在可选择的个人模型时，不自动猜测默认值，要求用户明确选择个人模型；两类模型都不可用时才阻止新任务；
- 用户在未选择机器人且 Core 尚未接受首次 SubmitTurn 前手动选模时，更新用户默认模型；
- 用户默认模型与当前待创建任务的有效模型分别建模和展示，不得共用一个可变字段；
- 机器人模型限制关闭时允许当前用户全部合法模型；开启后只展示已选模型与用户合法模型的交集；
- 用户默认模型在允许范围内时继续使用；不允许时按 Core/后台稳定顺序临时切换到第一个可用模型，并展示持久说明；前端不按名称、性能、点击先后或本地缓存自行排序；
- 机器人约束期间的临时选择不覆盖用户默认模型；取消机器人后恢复用户默认模型；
- 机器人限制开启但未选择模型或交集为空时阻止测试、发布和任务提交；
- Core 接受首次 SubmitTurn 并创建 Task/Runtime Selection 后模型锁定，同一任务中不展示切换入口；首次模型调用失败也不重新开放。

#### 切换机器人后的 Skill 与知识

- 首次提交前切换机器人时，前端根据 Core 返回的合法组合取消不在新机器人允许范围内的已选 Skill 和知识；
- 被取消项在选择区就近显示一次明确说明，例如“已取消：当前机器人不可使用该技能”，不得静默消失；
- 被取消项不进入提交摘要；切回原机器人或取消机器人后不自动恢复，用户需要重新选择；
- 模型不采用上述取消规则，继续使用用户默认模型和当前有效模型的双层恢复语义；
- 前端不得只在本地推断资源兼容性，提交前仍以 Core 最终校验结果为准。

#### 状态与删除

- 个人模型状态包括未验证、可用、认证失败、网络失败、协议不兼容、模型不存在、不可用、权限不足；
- 网络失败模型保留“最近一次网络失败”警告但仍可再次选择并触发真实调用；成功后更新为可用，再次失败则刷新失败事实；
- 认证失败、协议不兼容、模型不存在等不可选择模型使用禁用态和原因说明，不依赖彩色状态标签；
- 使用个人模型的执行中任务会阻止删除，Core 在提交删除时重新检查；
- 其他终态任务不阻止删除；历史任务保留模型名称、来源和必要追溯摘要；
- 删除用户默认模型后按统一初始规则重新选择：优先后台顺序中的第一个可用企业模型；企业模型为空但有其他可用个人模型时要求用户明确选择；
- 删除失败、revision 冲突或 Credential 删除结果不确定时保留页面并给出可执行下一步，不只显示 Toast。

#### Credential 交互

- API Key 默认隐藏；新增或更换时可以使用眼睛图标显示本次输入；
- 保存后默认显示掩码；只有个人模型所有者可以主动查看自己的完整 Key，再次点击、离开页面、关闭弹窗或组件卸载后恢复隐藏并清除明文；
- 应用不检测、不阻止、不审计系统截图或外部录屏；测试和官方演示只使用假 Key；
- Renderer 只在输入、保存提交或所有者主动查看期间短暂处理明文，不得写入全局 Store、持久化状态、日志、埋点、错误、Fixture、测试快照或 QA 证据；
- 企业模型 Credential 始终不提供客户端查看入口；
- 保存后真实回显必须等待 ADR-013 增补冻结受控反向敏感通道；未接入前按钮禁用或标注待接入，不得通过 Mock、普通 HTTP 或公共 Contract 伪装成功。

完整业务规则、系统职责和验收矩阵遵循 `MODEL-EXPERIENCE-FEATURE-SPEC-v1.0.md`。

### 10.9 Admin Tool 管理

完整产品语义遵循 [`TOOL-MANAGEMENT-FEATURE-SPEC-v1.0.md`](./TOOL-MANAGEMENT-FEATURE-SPEC-v1.0.md)。本节只冻结管理端的页面结构和交互，不由前端生成 Tool 技术事实、Policy、验证或健康状态。

#### 列表

- 使用统一表格展示代码工具、HTTP API、MCP 三种接入来源；不建立三个独立管理模块；
- 首屏固定为 6 个聚合列：Tool、接入方式、状态、治理、更新时间、操作；
- “Tool”列展示标题和技术名称；“接入方式”列分别标注接入来源与执行位置；“治理”列展示风险和使用范围摘要；
- “状态”列可以聚合布局，但配置、验证、健康和生效仍是四组可识别事实，不压缩成一个“正常”标签；
- 名称/技术名称搜索和接入来源筛选常驻；执行位置、四组状态、风险和使用范围收进“更多筛选”抽屉或弹出层；
- 列表不展示 Endpoint、Credential Reference、Secret、设备绝对路径、Runtime Handle 或完整错误正文；
- 主操作为“新增 Tool”，点击后只提供“连接 API”和“连接 MCP 服务”两个入口；代码 Tool 由研发可信发布后自动登记，不出现在新增菜单。

#### 代码工具详情与配置

- 当前内置 Document Tool 与其他代码工具使用同一页面类型；官方或企业研发完成测试和可信发布后，系统自动登记到企业 Tool 列表；
- 页面不提供代码工具候选库、选择添加、安装、创建步骤、保存草稿或管理员测试；
- 发布后的代码工具默认显示“待启用”或“当前环境不可用”，环境状态由系统根据 Manifest、package、Runtime 和客户端兼容性自动检查；
- 系统只读展示官方名称、技术 ID、Schema 摘要、官方风险、package/revision/digest、Binding/Adapter、Runtime、执行位置、适用版本和覆盖情况；
- 技术 ID、模型可见官方说明、Schema、风险事实、Binding、Adapter 和官方兼容范围只读；
- 管理员只配置企业启用、允许的部门/用户/机器人和更严格确认要求；
- 代码工具使用独立的详情/策略页，不复用 HTTP 编辑器；管理员决策字段默认展开，Binding、Adapter、digest、Runtime 等放入默认折叠的“技术详情”；
- 页面不展示“上传代码”“编写代码”“安装依赖”“替换实现”“编辑 Schema”“运行测试”或“删除”；
- TGM-1/2 未接入前，真实配置操作禁用并显示“待接入”，不得用本地状态伪装启用成功。

#### HTTP API 新增/编辑

HTTP 使用独立条件表单，不与 MCP 或代码工具共用一张通用表单。创建对齐当前原型，固定为 2 步：

1. 基础配置：工具标题、工具名称、工具描述与能力边界；
2. 连接配置：API 访问地址、认证、P0 的 GET/POST、参数和使用范围，完成后保存草稿。

第二步顶部增加“快速导入 API 配置（推荐）”卡片：

- 默认展示一块 cURL 文本输入区、“解析并填入”主按钮和“继续手动填写”入口；手动表单始终保留，不因导入功能隐藏；
- 解析成功后卡片收起为“已从 cURL 填入，可重新导入”的摘要，下面现有字段展开并显示解析结果；
- 重新导入前说明将覆盖第二步尚未保存的解析结果，但不得覆盖第一步业务信息；
- 导入不跳转到独立页面，不新增“候选 Tool”“解析进度”“发布确认”等页面，不形成第二套创建状态机；
- P0 只接收单条 cURL。OpenAPI/Swagger 文本、文件、URL和批量 Operation 选择保持 P1。

- 技术名称按受控规则自动生成并校验企业内唯一；需要修改时放入“高级配置”；
- JSON Schema、完整参数映射、超时和受控重试等低频字段放入默认折叠的“高级配置”；
- 业务表单只展示完整“API 访问地址”，系统内部拆分 Base URL 和 Relative Path；普通管理员不手工维护两份地址；
- cURL 解析后将 Query、Path、Header 和 JSON Body 字段转换为现有可增删参数卡片；示例值只进入示例字段，用户仍需确认值来源、必填性和无法识别的类型；
- 认证 Header、API Key、Cookie 和 Basic Auth 不进入普通参数卡片；只显示认证类型、掩码和“选择/配置凭证”状态；
- “解析并填入”只表示字段解析成功，不使用成功 Toast 宣称已连接、已保存、已测试或已启用；
- 解析错误在 cURL 输入区就近展示；部分解析同时显示已识别结果和待处理项，未解决的阻断项禁止保存；
- 创建末尾只保存草稿，测试和显式启用移至详情页；
- 管理员不填写内部 Credential Reference；
- 保存后 Credential 只显示“已配置”或掩码，不回显明文；
- 修改 Connection、Credential、Method、Path、映射、Schema 或风险后，页面显示“配置变更，需重新测试”；
- 已启用技术配置的修改进入新草稿 revision，不直接覆盖当前生效版本；
- 并发冲突或 stale revision 使用页面级持久错误，保留非敏感输入并要求刷新。

#### MCP 新增/编辑

MCP 创建固定为 3 步：

1. 验证并发现工具：填写远程服务名称、地址和认证，验证成功后自动发现 Tool；
2. 选择 Tool：按业务名称、技术名称、用途和风险摘要展示结果，支持搜索和安全批量选择；
3. 设置范围并保存草稿：统一配置使用范围和额外确认，保存为多个独立 Tool 草稿。

- P0 只连接已部署的远程 MCP 服务，不展示“远程 MCP/本地 MCP”选择，也不展示 Command、Arguments、工作目录、环境变量或依赖安装；
- 首屏只展示服务名称、MCP 服务地址、认证方式和访问密钥。P0 认证选项为“无需认证 / 访问令牌（Bearer Token） / API Key”；选择“无需认证”时隐藏密钥输入，选择后两者时分别展示“访问令牌”或“API Key”密码输入框，由管理员直接填写；
- 密钥输入框支持本次输入的显示/隐藏；保存后只显示掩码，编辑时提供“保留原密钥/输入新密钥替换”，不得回显完整值；本期不出现 Credential 名称、已有凭证下拉、“新建凭证”按钮或独立 Credential 页面；
- 选择 API Key 时，系统默认通过 `X-API-Key` Header 发送；仅当服务要求不同 Header 名称时，在默认折叠的“高级配置”中修改。Header 名称必须通过格式校验，API Key 不允许放入 URL Query；
- 切换认证方式时清空当前尚未保存的密钥输入，并更新字段名称和帮助文案；OAuth 完整授权流程保持 P1，后端未支持的 Transport 或认证方式不出现；
- 主按钮使用“验证并发现工具”；依次展示“正在连接/正在识别协议/正在发现工具”，失败时在字段附近显示服务不可达、认证失败或协议不兼容；
- 连接成功后才能进入选择；发现失败保留连接表单和错误建议；
- 发现列表顶部提供搜索、“选择全部只读工具”和“取消选择”，不提供无差别全选；
- 每项展示中文显示名称、灰色小字技术名称、用途说明和读取/写入/删除/外发风险摘要；读取能力可默认选中，写入、删除和外发能力默认不选；
- 首次创建不展示 Schema diff，也不要求逐项编辑 Endpoint、Method、Schema、参数、风险摘要或显示名称；系统使用 discovery title/description 形成草稿，管理员可在 Tool 详情补充业务信息；
- 第三步使用“所有人/指定范围”；指定范围通过部门和用户搜索多选器配置，不使用自由文本姓名；
- 确认设置只提供“遵循工具默认规则/所有已选 Tool 额外要求调用前确认”，不得降低 Tool 原始风险要求；
- 风险摘要由系统按已选 Tool 自动生成并只读展示，不提供管理员手写输入框；
- Server identity、稳定 capabilityId 和 Schema digest 由系统生成，不作为管理员输入字段；
- 创建末尾主按钮为“保存为工具草稿”，结果说明生成的独立草稿数量；不得使用“发布”或宣称已经可用。单个 Tool 的测试和显式启用移至详情页；
- MCP Tool 编辑页只允许修改显示名称、补充说明、使用范围、额外确认和启停；原始技术事实和服务连接只读；
- Tool 详情中的“来源 MCP 服务”进入连接详情，统一编辑服务名称、地址和访问密钥，并提供重新验证和手动重新发现；不新增一级 MCP 菜单；
- 修改 Server Connection 或 Credential 形成新草稿 revision，历史连接测试和发现结果对新 revision 失效，不直接覆盖当前有效连接；
- P0 不自动同步远端新增 Tool；手动重新发现展示新增、变化和移除摘要，Schema 变化进入“待复核”，不自动覆盖或启用；
- 管理员不能手工编辑或伪造远端发现的原始 Schema；
- MCP discovery 未接入时不得把可点击 Fixture 表述为真实发现；只有通过明确“查看演示结果”入口载入且持续标注 Mock/Gated 的固定数据可以参与原型演示。

#### 信息层级

- 默认页面只展开管理员需要理解和决定的字段：名称、说明、连接摘要、风险、范围、启用和确认策略；
- Binding、AdapterDescriptor、digest、Server identity、Schema digest 和内部 revision 等放入默认折叠的“技术详情”；
- 折叠只改变信息层级，不删除审计、排障和只读技术事实。

#### 测试、启用和停用

- HTTP/MCP 的保存、测试和启用使用三个明确动作和结果，不因关闭弹窗互相冒充；
- 代码 Tool 不展示管理员测试按钮；发布验证作为只读事实，部署后的 package、Runtime 和兼容性由系统自动检查；
- 测试绑定当前草稿 revision，测试失败保留非敏感表单内容；
- 有副作用 Tool 必须展示测试目标和影响，不默认对生产数据执行写入、删除或外部发送；
- 测试结果只展示脱敏请求/响应摘要，不展示 Secret、完整响应或内部堆栈；
- 普通停用确认说明“影响后续新任务，运行中任务保持已锁定配置”；
- 被机器人引用时展示依赖和影响，不宣传自动降级或自动换 Tool；
- 代码 Tool 不可由管理员删除；只有未启用、未被引用的 HTTP/MCP 草稿显示删除企业登记入口；
- 紧急撤销不是普通停用，不在 MVP 页面提供同名或含混入口。

#### GATED 状态

- TGM-1 前只允许明确 Prototype/GATED 的已发布代码工具列表、发布验证和自动环境状态 Fixture，不提供候选添加或测试；
- TGM-2 前不声明企业 Policy、启停或客户端覆盖真实生效；
- TGM-3 前 HTTP 表单使用明确假值或禁用控件，不接收真实 Endpoint/Secret，不伪造保存、测试或启用成功；
- TGM-3 前 cURL 原型只允许不含真实 Secret/生产 Endpoint 的示例内容，解析仅在演示状态回填字段，不联网、不持久化原始文本、不伪造 Catalog 写入；
- TGM-4 前 MCP 真实“验证并发现工具”保持禁用；原型可提供“查看演示结果”载入明确 Mock 的固定 discovery Fixture，但不得把它表述为真实连接、发现或注册成功；
- GATED 状态下，启停和删除只能解释待接入边界，不修改 Renderer/LocalStorage 状态并伪造业务成功；
- 每个真实 TGM 批次接入后删除或隔离对应 Mock，不混合展示真假状态。

#### 当前 Tool 原型修订要求

- “新增 Tool”菜单删除“代码工具”，只保留“连接 API”和“连接 MCP 服务”；删除可信候选 Catalog 页面、代码工具三步创建路由及其草稿复核页；
- 代码 Tool 直接作为已发布资源出现在统一列表。原型可使用“文档转 Markdown（MarkItDown 封装示例）”Fixture，必须标注 `Prototype/Gated`，不得暗示已经完成真实集成；
- 代码 Tool 详情首屏只展示名称、用途、来源、版本、风险、当前环境状态、使用范围和启停；删除“运行测试”“保存草稿”“删除企业登记”和兼容版本输入；技术 ID、Schema、package/digest、Binding/Adapter、Runtime 收进默认折叠的“技术详情”；
- 代码 Tool 的状态示例使用“发布验证通过/发布验证失效”和“当前环境可用/环境不可用”，由系统只读投影，不出现“未测试”或要求管理员上传样例文件；
- API 入口使用“连接 API”，保持“基础配置 → 连接配置”两步。连接配置顶部新增 cURL 快速导入，解析后回填 API 访问地址、认证、Method 和现有参数卡片；手动填写始终可用。Schema、完整映射、超时、重试和内部 Connection 拆分进入“高级配置/技术详情”。OpenAPI/Swagger 文档导入保持 P1，原型不得把 `openapi-core` 等开发库展示为业务 API Tool；
- MCP 入口使用“连接 MCP 服务”，不增加远程/本地类型选择。第一步只展示远程服务名称、地址、“无需认证 / 访问令牌（Bearer Token） / API Key”和对应密钥输入框；管理员直接填写 Token/API Key，不展示凭证下拉或独立 Credential 功能；API Key 默认使用 `X-API-Key`，特殊 Header 名称只在高级配置中出现；真实验证按钮 GATED，另以“查看演示结果”载入明确 Mock 的 GitHub discovery Fixture；
- MCP 第二步展示搜索、选择全部只读工具、取消选择，以及“中文名称 + 灰色技术名称 + 用途 + 风险摘要”；读取能力可默认选中，写入、删除和外发能力默认不选；首次创建不展示 Schema diff；
- MCP 第三步将授权用户自由文本改为“所有人/指定范围”的部门/用户搜索多选器；删除手写风险摘要，改为系统只读汇总；确认设置只能遵循默认或额外收紧，主按钮保持“保存为工具草稿”；
- MCP Tool 详情展示可点击的“来源 MCP 服务”，进入非一级菜单的连接详情；该页承担编辑地址/访问密钥、重新验证和手动重新发现，单个 Tool 编辑页不重复这些字段；
- HTTP 两步与 MCP 三步流程切换时必须在当前创建会话内保留非敏感输入，返回上一步不得丢失；保存摘要必须使用用户实际填写、导入并确认的数据；原始 cURL 不进入浏览器持久存储；
- GitHub 仓库地址只能作为研发接入参考，不能在管理端粘贴后直接安装或执行任意代码；如未来提供“申请新工具”，应另按 P1 需求评审，不混入本轮新增流程。

### 10.10 Admin 机器人创建与编辑

#### 页面结构

- 基础信息沿用 Desktop 的业务字段：头像、名称、标签、简介、行为与规则；Admin 额外展示发布范围和草稿版本；
- 不使用“一句话说明”“Instructions/System Prompt”“关联技能”“关联工具”等旧主字段名称；
- 能力配置固定为模型、技能、工具和知识四行限制开关，默认均关闭并收起；
- 已发布机器人进入编辑时创建新草稿，页面不得直接修改当前已发布版本。

#### 限制开关和选择

- 管理端与 Desktop 使用相同语义：关闭表示不设置机器人级限制，开启表示建立允许列表；
- 只有开关开启后才显示“添加技能”“添加工具”“添加知识”或模型多选；不得在默认页面直接铺开所有技能、工具和知识复选框；
- 模型限制关闭时，该机器人可使用目标用户当时全部合法可用模型；开启时只能使用“管理员已选模型”与“目标用户合法可用模型”的交集。模型多选按后台返回的稳定顺序展示，当前实现可沿用后台配置/添加时间顺序，Admin 前端不提供拖拽排序，也不按名称、性能或本地缓存自行重排；
- 资源选择使用搜索多选弹层或抽屉。技能以标题、技术名称、来源和版本辨识；工具以业务名称、用途、来源和风险摘要辨识；知识以名称和来源辨识；
- 技能只展示企业内已发布且当前可引用的资源；工具只展示已启用、未撤销且允许机器人引用的资源；知识和模型同样按当前企业权限过滤；
- 已选资源在开关下方展示，可单项移除；关闭开关时保留当前草稿选择但不生效，再次开启恢复；
- 开启后未选择任何项时必须显示禁止使用该类资源的提示，不把空列表解释为未限制；
- 保存草稿、测试和发布复核均分别显示开关状态和实际生效项。所选资源已不可用时，指出资源名称并阻止对应测试或发布动作。

#### 草稿、测试与发布门槛

- 保存机器人草稿只要求名称；简介和行为与规则允许暂缺，页面需明确提示“发布前补充”；
- 运行测试和提交发布要求名称、简介、行为与规则完整；模型限制开启但允许列表为空或没有实际可用模型时，禁止测试和发布。Skill、Tool 或知识限制开启但列表为空时，语义是明确禁止使用该类资源，可以继续保存和发布；运行测试是否可完成由测试任务的实际能力需求决定，不把空列表误判为表单错误；
- 测试只能针对已保存的草稿 revision。页面存在未保存修改时，先提示保存新 revision，不得用旧测试结果覆盖新内容；
- 头像和标签只属于展示信息；修改它们可以形成新的资源草稿版本，但前端不得暗示其已改变模型使用的机器人指令。

#### 原型调整要求

- 当前 Admin 原型中默认模型下拉、“允许用户切换”和默认铺开的技能/工具/知识复选框应替换为四项限制开关；模型项标题统一为“模型”，不再表达单一“默认模型”；
- 技能、工具选择入口打开统一多选组件，Prototype 可以使用 Fixture，但必须覆盖搜索、选择、移除、关闭后保留、空允许列表警告和资源不可用；
- 机器人详情的能力摘要不得把关闭状态显示为“无”，而应显示“未设置机器人级限制”。

### 10.11 Admin 技能包上传与客户端安装

#### Admin 新增技能

- 技能列表只保留一个主要新增操作“上传技能包”；删除“创建企业技能”空白编辑器和“导入技能包”并列入口；
- 上传页接受产品已支持的 `.zip`、`.rar`、`.tar.gz` 或 `.tgz` 文件，单个压缩包上限为 200 MB，主操作文案使用“选择技能包”；选择器辅助文案同步展示支持格式和大小上限；
- 上传页只负责选择文件、解析和安全校验，不在解析完成后直接创建草稿；校验通过后的主操作固定为“下一步：编辑技能信息”；
- 解析成功后进入独立的“编辑技能信息”页面，不返回列表，也不把解析成功提示成“上传成功”或“草稿已保存”；
- 编辑页默认回填技能标题和技能描述；只有包内存在且可识别为有效发布版本的版本声明时才回填版本号，否则版本号输入框保持为空并由管理员填写。页面同时展示使用范围；管理员可以修改技能标题、技能描述、企业发布版本和使用范围，其中技能标题、技能描述和企业发布版本在保存草稿时为必填；
- 技能标题默认依次使用包内显式标题、`SKILL.md` 一级标题或由技能名称生成的可读名称；技能描述默认使用解析结果；`SKILL.md` 未声明版本、版本无法识别或不符合企业发布版本格式，均不得阻止解析完成或进入编辑页；
- 版本号使用 `主版本.次版本.修订号` 格式。上传已有技能的新版本时，页面就近提示版本重复或未高于当前发布版本，并阻止保存；草稿状态使用独立状态标签表达，不把 `-draft` 拼入版本号输入框、列表或详情；
- 技能名称作为从 `SKILL.md` 解析的英文技术标识只读展示，不提供修改、重新生成或使用标题覆盖的入口；
- `SKILL.md` 原文/Markdown 预览、压缩包名称、包内原始描述、可选的包内版本声明、文件清单、完整性摘要和校验结果统一放在“解析结果”只读区；未声明包内版本时显示“未声明”，不得进入“未通过校验项”或警告区；详细 Markdown 和文件清单可以折叠，但技能名称和校验结论默认可见；
- 压缩包内任意目录存在且只存在一个可识别的 `SKILL.md` 即通过结构校验，不要求位于压缩包最外层；系统以该文件所在目录作为技能包逻辑根目录，`references/`、`scripts/` 和其他文件按该目录下的实际内容展示。页面不得要求管理员手工填写目录路径、文件清单或 README；未找到时展示“包内未找到 SKILL.md”，检测到多个时展示“检测到多个 SKILL.md，当前只支持单技能包”，已经找到唯一文件但读取、解压或 Markdown 解析失败时分别展示对应错误，不得统一归类为“文件不存在”；
- 面向管理员的文件清单默认隐藏 `__MACOSX`、`.DS_Store`、`._*`、`PaxHeader` 等操作系统或归档工具生成的元数据；安全校验、解压限制和审计仍检查这些条目，隐藏不等于忽略；
- 编辑技能标题、技能描述、版本号或使用范围只修改企业技能目录中的草稿信息，不改写压缩包和 `SKILL.md`；当展示信息与包内声明不同时，页面分别标明“展示信息”和“包内声明”；
- 需要修改技能行为、Markdown 正文、脚本或其他技能文件时提示“请修改技能包后重新上传”，不提供在线编辑包内文件；
- 未固定的草稿详情提供“编辑”入口，可继续修改标题、描述、版本号和使用范围；已发布版本和已固定 revision 不提供原地编辑，统一通过“上传新版本”重新进入上传、解析和编辑流程；
- “解析完成”“保存草稿”“测试”“发布”是四个不同结果。解析完成不表示草稿已保存，保存成功不表示测试通过、已发布或已安装；发布固定当前包 revision 后才进入技能广场；
- Prototype/GATED 阶段不得读取或执行真实包内脚本，不得伪造上传、测试或发布成功。

#### 客户端安装

- 用户从技能广场点击“安装”后，客户端从企业技能库下载该固定版本压缩包，校验身份、版本和完整性，再安全解压到对应的 RoboThree 受控 Skill 目录；
- 安装进度至少区分下载中、校验中、安装中、安装成功和安装失败；只有完整解压并完成原子切换后才进入“已安装”；
- 安装禁止路径穿越、绝对路径和不受支持的符号链接；失败时清理暂存文件和半安装目录；
- 安装只解压文件，不执行 `scripts/`，不运行包内安装命令，不自动安装环境依赖；依赖要求由 `SKILL.md` 展示并在运行时另行处理；
- 默认安装到用户级 RoboThree 受控 Skill 目录；当产品提供明确的项目级安装入口时，目标为当前已授权 Workspace 的 `.robothree/skills/<skill-name>/`。不得因安装企业技能而改写 `.claude` 来源目录；
- 同名同版本重复安装保持幂等；同名不同版本使用明确更新或替换确认，不静默覆盖；卸载只移除本机安装副本，不影响企业技能库中的发布包。

## 11. 操作反馈与浮层

### 11.1 弹窗

适用于：

- 破坏性确认；
- 少量字段编辑；
- 用户必须先作出决策才能继续的操作。

弹窗必须：

- 标题明确；
- 说明目标和影响；
- 主按钮使用具体动作名称；
- 关闭后焦点返回触发位置；
- 不允许多个阻断弹窗无限叠加。

### 11.2 抽屉

适用于：

- 在不离开当前列表的情况下查看简要详情；
- 选择机器人、技能、模型或项目空间；
- 展示较长但不需要完整页面导航的内容。

对象存在复杂编辑、版本或发布流程时，应进入独立页面，不在抽屉中完成全部操作。

### 11.3 Toast 与页面消息

Toast 适用于短时成功反馈，例如“已保存”“已复制”。

以下情况不得只使用 Toast：

- 权限不足；
- 删除失败；
- 连接失败；
- 发布失败；
- 任务进入人工处理；
- 数据版本冲突。

这些情况必须在页面或弹窗中提供持久信息和下一步操作。

### 11.4 破坏性操作

删除、停用、下架、撤销授权等操作必须：

- 明确操作对象；
- 说明影响；
- 区分可恢复和不可恢复；
- 使用二次确认；
- 完成后更新页面状态；
- 失败时不伪装成功。

具体删除一致性由模块 Feature Spec 冻结。

任务删除确认必须额外展示：

- 被删除的任务名称；
- 会话记录和消息将被永久删除且不可恢复；
- 已生成成果和实际文件不会被删除；
- 保留成果后续显示“原任务已删除”；
- 明确的“永久删除任务”主操作和“取消”操作。

## 12. 状态与操作一致性

### 12.1 状态所有权

- 任务状态来自 Core Projection；
- 企业资源可用性来自身份、配置和 Core/Central 结果；
- 前端不得根据网络请求结果推导第二套业务状态；
- Mock 状态必须与未来真实状态建立明确映射；
- 临时 Streaming 不作为持久消息；
- Stale 状态不得覆盖较新的 revision。

### 12.2 状态展示

- 使用中文业务状态；
- 全局状态标签统一使用中性灰背景、边框和文字层级，不使用绿、黄、蓝、红语义色区分状态；
- 状态标签必须包含明确文本，不使用仅靠颜色、圆点或图标表达的状态；
- 状态名称在列表、详情和选择器中保持一致；
- 同一对象的 Disabled、Unavailable 和 Permission denied 不得混用；
- 不确定的外部结果展示“需要人工处理”，不得伪装为普通失败；
- 机器人列表、卡片和选择项不展示状态标签；不可用、维护中或草稿等事实通过所属分类、操作可用性、禁用态、原因说明或详情信息表达；
- 状态标签中性化不影响错误消息、警告提示、风险确认和破坏性操作使用语义色。

### 12.3 操作可用性

按钮不可用时：

- 展示不可用原因；
- 必要时提供联系管理员或完成前置操作的入口；
- 不只将按钮灰化；
- 用户无权限的高敏感操作可以直接隐藏，但页面应保留可理解的权限说明。

### 12.4 任务置顶与删除交互

本节只规定 PRD 已确认业务规则的前端表现，不替代 Task/Session/Artifact Feature Spec：

- 任务列表是 P0 的置顶、取消置顶、重命名和删除统一入口；任务详情不重复提供任务管理菜单；
- 置顶状态同时使用可读文本或辅助技术名称，不只显示无标签图标；
- 所有任务状态均可置顶，操作成功后列表按固定规则重排；
- 置顶或取消置顶失败时保持原顺序，并提供持久错误信息或可重试入口；
- 未结束或结果不确定的任务不展示可执行的删除操作；如保留禁用按钮，必须说明当前状态不允许删除；
- 删除确认期间检测到状态或 revision 变化时关闭提交态，保留任务并要求刷新；
- 删除成功后返回任务列表，移除任务、消息和置顶表现；
- 删除失败时保持当前页面、任务和消息，不只显示短时 Toast；
- 被保留成果的来源任务已删除时，展示“原任务已删除”，不提供失效返回链接；
- Mock 阶段必须标记演示数据；接入真实链路前不得把现有 tombstone 或仅隐藏列表入口的行为宣传为物理删除。

## 13. 权限与资源范围

### 13.1 权限分工

系统管理中的“用户与权限”页只配置通用权限：

- 添加和使用个人模型；
- 创建机器人；
- 创建技能；
- 提交发布；
- 进入管理中心；
- 查看审计。

具体资源使用范围在资源页面配置：

- 模型；
- 工具；
- 机器人；
- 技能；
- 知识。

同一权限不得在两个位置形成冲突事实源。

### 13.2 前端权限表现

- 无权进入的 Admin 模块不显示导航入口；
- 可查看但不可编辑时展示只读详情；
- 资源选择器只展示当前用户可使用的对象；
- 已选资源在提交前失效时阻止提交，并说明原因；
- 权限变化不静默改变已启动任务的运行组合；
- 管理员不能代替用户确认本机风险操作。

### 13.3 资源来源与智能中心分类

- 前端开发及测试阶段，“部门”使用测试身份中的简化部门信息；
- 正式环境的“部门”以企业组织与权限系统同步结果为准，前端只消费身份与权限链路提供的部门标识、名称和资源可见范围；
- “企业”和“部门”继续作为资源来源、使用范围和权限事实，但不再作为机器人或技能的分类 Tab；
- 机器人按“全部/我创建的”分类；技能按“技能广场/已安装/本地目录/我创建的”分类；工具不设置子分类；
- 来源可以在卡片中作为普通文本元数据展示，不使用“企业/部门/我的”等分类标签；
- 测试身份无部门信息时，不生成虚假部门来源，也不把企业资源或个人资源自动归入部门；
- 前端不得通过名称、邮箱或文件路径推断部门归属。

### 13.4 Workspace 与智能授权选择

- 项目空间选择器决定 WorkspaceGrant 和文件访问硬边界；智能授权选择器只决定该边界内的确认策略，两者不得混为同一字段；
- 最终模式固定为“手动复核/智能确认/任务内授权”，默认“智能确认”，不使用“工作区授权”作为模式名称；
- 控件位于新任务 Composer 的任务选择区域，使用单选控件或三段式选择器，并展示名称、简短说明和选中态；
- 首次提交后模式与任务绑定，同一任务后续对话只读展示已锁定模式，MVP 不支持执行中切换；
- 模式不可用时保留选项并展示禁用原因，不静默降级；
- 真实接入前只允许带“待接入”和“当前不改变任务执行”的只读说明卡片，不得显示可点击、默认选中、`aria-pressed` 或已保存反馈；
- 真实接入后，提交前选择摘要展示将进入受支持 Contract 的 requested mode，提交成功后任务详情只展示 Core 返回的 resolved mode；前端状态、LocalStorage 和 Mock receipt 不能代替业务事实；
- 模式必须通过版本化 Contract 进入 Core，并在 Task/Runtime Selection、恢复和审计中保持一致；现有 v1alpha1 不得原地静默增加字段；
- 详细行为、状态矩阵和验收遵循 `WORKSPACE-AUTHORIZATION-FEATURE-SPEC-v1.0.md`。

### 13.5 全局 Max 推理开关

- 控件位于新任务 Composer 的模型选择附近，使用一个标记为 `Max` 的开关，不提供五档、预算输入或 Provider 技术参数；
- 首次使用默认关闭；用户修改后作为后续新任务的初始偏好。偏好可以复用既有模型偏好或应用设置能力；保存失败时当前待创建任务仍使用本次选择，同时就近提示“本次选择可用，未保存为后续默认”。已经创建的任务只读展示其结果，不允许用全局开关修改当前任务；
- 关闭态辅助说明为“使用模型默认模式”，不得写成“最低推理”或“关闭推理”；
- 开启态辅助说明为“优先使用当前模型支持的最强推理模式，可能需要更长时间”；不得承诺固定档位、Token、时长或费用；
- 当前模型不支持 `Max` 时，开关保留用户偏好，但提交区必须显示可持续读取的页面内说明“当前模型不支持 Max，将按模型默认模式运行”；不得只使用 Toast，也不得显示虚假的已生效状态；
- 用户在首次提交前切换模型、选择或取消机器人并导致有效模型变化时，前端立即重新读取支持状态和实际解析摘要，不复用上一模型的结果；
- 提交前摘要展示“Max / 模型默认”及必要的不支持说明；如果提交瞬间发生能力变化或安全映射失败，任务不因 `Max` 被阻止，按模型默认模式继续，并在任务反馈或只读摘要中持续说明“本次未启用 Max”。提交成功后以 Core 返回的任务结果为准，本地 Store、LocalStorage 或 Mock 不能代替任务事实；
- 开关必须支持键盘操作、清晰焦点和可读状态；名称、说明、不支持原因不得只通过颜色表达；
- 界面始终只展示推理模式，不展示思维链、私有推理正文、Provider 原始参数或预算值；
- `Max` 是增强偏好而非硬性执行条件；只有当前模型本身不可用、权限不足或任务缺少其他必需能力时才按既有规则阻止提交，不能仅因 `Max` 不可用要求用户二次提交；
- 详细产品与真实接入语义遵循 `MODEL-EXPERIENCE-FEATURE-SPEC-v1.0.md`。

## 14. 凭证与敏感信息

### 14.1 禁止展示或持久化

除个人模型所有者按 `MODEL-EXPERIENCE-FEATURE-SPEC-v1.0.md` 主动查看自己 Key 的受控交互外，前端不得展示、记录或持久化：

- API Key 和 Token 明文；
- Credential Reference；
- 完整系统 Prompt；
- 模型私有思考过程；
- 完整任务正文的管理端副本；
- 未脱敏真实路径；
- 完整外发正文；
- 内部进程、数据库和运行实例信息。

### 14.2 凭证输入

- 密钥输入默认遮罩；
- 保存后默认只显示“已配置”或掩码；个人模型所有者可以在受控链路接入后主动查看自己的已保存 Key；
- 编辑普通字段不要求重新填写已有 Key；
- 更换 Key 使用明确操作；
- 个人模型新增、保存和查看期间，Renderer 只短暂处理当前明文，不得写入全局/持久状态、日志、错误、埋点、Fixture、测试快照或 QA 证据；
- 隐藏、离开页面、关闭弹窗或组件卸载后清除 Renderer 明文；
- 企业 Credential 不进入客户端；
- 应用不检测或拦截系统截图/外部录屏，官方测试和演示只使用假 Key；
- 个人模型不提供测试连接；其他模块的测试连接和保存过程不得把 Key 写入可见日志、错误和埋点。

### 14.3 本地路径

- Desktop 可以在用户明确授权和必要场景中展示安全路径摘要；
- Admin 不展示用户本地真实路径；
- 默认空间只展示“默认空间”，不暴露物理位置；
- 错误提示不拼接完整用户目录。

## 15. Mock、Prototype 与真实接入

### 15.1 Mock 规则

Mock 可以用于：

- 页面结构；
- 通用状态；
- 选择、筛选和表单交互；
- Streaming、任务状态和连接状态演示；
- P1/Prototype 页面探索。

Mock 不得：

- 伪装成真实调用；
- 生成真实权限、审计和持久化事实；
- 保存真实 API Key；
- 触发未确认的 IPC 或 Core/Central 行为；
- 自动解锁 Gated 能力。

个人模型 Mock 还必须遵守：不接收真实 Key，不伪造新增、查看、保存、默认切换或删除成功，不展示测试连接；可以演示用户默认模型与机器人临时有效模型的纯交互，但必须明确不是 Core 持久事实。

`Max` 原型可以用明确的 Fixture 演示支持、不支持和换模重算；在受支持 Contract、Core 锁定和 Model Adapter 映射接入前，生产界面的可点击开关必须标注“待接入”或保持禁用，不得把本地布尔值冒充真实推理模式。

### 15.2 原型标识

开发和演示环境中，未接真实能力的区域必须明确显示：

- 演示数据；
- 尚未接入；
- 未配置；
- 暂不可用。

生产界面不得展示“Prototype”等内部研发词汇，应使用面向用户的状态文案。

### 15.3 Mock 到真实数据映射

每个模块在 Living Spec 中记录：

- Mock 字段；
- 对应现有 Projection/API；
- 暂无真实来源的字段；
- 接入阻断项；
- 不再需要的 Mock 字段。

真实接入后必须删除或隔离对应 Mock，不允许混合显示无法区分的真假数据。

## 16. 视觉、可访问性与窗口适配

### 16.1 视觉与组件基线

- 整体采用简洁、专业、企业中性的工作台风格，优先保证信息层级、任务状态和操作结果可读；
- 使用中性背景和表面色以及一个主要操作色；状态标签统一使用中性灰，语义化成功、警告、危险和信息色只用于页面消息、风险提示、确认和错误反馈，不用于状态标签；
- 正文默认使用 14～16 px 字号和 1.4～1.6 行高；表格、时间、数量和运行信息保持紧凑但可读，必要时使用等宽数字；
- 颜色、字号、间距、圆角、阴影和层级通过语义化 Design Token 管理，避免为单个页面持续增加无来源的任意值；
- 导航、按钮、输入框、选择器、Tab、卡片、表格、状态标签、弹窗、抽屉、Toast 和空状态优先复用统一组件；
- 同类组件的尺寸、焦点、禁用、Loading、错误和破坏性操作表现保持一致；
- 页面级视觉优化可以在前端 Living Spec 中迭代，但不得改变本规范、PRD、Contract 或模块 Feature Spec 定义的业务事实。

### 16.2 键盘与焦点

- 核心操作可使用键盘完成；
- Tab 顺序符合视觉顺序；
- 弹窗打开后焦点进入弹窗；
- 弹窗关闭后焦点返回触发位置；
- 键盘焦点必须清晰可见，不得仅依赖浏览器或系统中不可辨认的默认样式；
- 不依赖悬停才能发现关键操作；
- 快捷键不覆盖系统常用组合。
- 任务详情的视图下拉、折叠标题、目录树、文件标签、打开本地文件夹、全屏、收起和展开均可使用键盘操作；图标按钮不得只有视觉符号而没有可读名称。

### 16.3 表单、状态与对比度

- P0 页面以 WCAG 2.2 AA 作为可访问性目标；
- 普通文本与背景对比度不低于 4.5:1，大字号文本和关键非文本界面元素不低于 3:1；
- 表单控件具有可读 Label；
- 错误说明与对应字段关联；
- Loading、Streaming、成功和失败向辅助技术提供提示；
- 状态不只依赖颜色；
- 图标按钮提供可读名称。

### 16.4 窗口适配

- Desktop 默认窗口基线为 1180 × 760，最小支持窗口为 900 × 600；
- Desktop 在 900 × 600 下不得隐藏或裁掉主要操作；空间不足时，次要操作进入可访问的更多操作菜单；
- 侧栏收起后仍可访问一级导航；
- 内容不足时保持稳定布局；
- 内容溢出时使用可预期滚动区域，页面主体不应产生不可控的横向滚动；复杂表格允许在表格容器内横向滚动；
- Admin Console P0 采用桌面优先布局，以不小于 1024 × 720 的内容视口作为正式验收基线；更窄视口仍需保留导航和关键操作，但不要求完成移动端专项布局；
- 不要求 P0 支持复杂多分屏和任意拖拽布局；
- 动画遵循减少动态效果偏好。
- 任务详情右侧面板在默认窗口与 900 × 600 最小窗口下均不得挤压到使对话区主要操作不可用；空间不足时允许用户收起面板，文件标签过多时在标签栏内部滚动或溢出处理，不推动页面主体横向滚动；
- 面板全屏只覆盖软件窗口内容区域，退出后必须恢复进入全屏前的分栏、滚动和焦点状态。

## 17. 文案规范

### 17.1 文案原则

文案应：

- 简洁、具体；
- 使用主动语态；
- 说明结果和下一步；
- 避免技术内部词汇；
- 不夸大尚未接入的能力；
- 不把“已提交请求”写成“操作已完成”。

### 17.2 操作按钮

按钮使用具体动作：

- 保存；
- 测试连接；
- 创建任务；
- 启用技能；
- 停用技能；
- 提交发布；
- 通过；
- 拒绝；
- 重新授权。

避免使用含义不清的“确定”“处理”“执行”等作为主要操作。

### 17.3 错误文案结构

推荐结构：

```text
发生了什么
可能影响
用户可以做什么
```

例如：

```text
当前模型无法连接，任务尚未开始。
请检查网络，或选择其他已授权模型后重试。
```

## 18. 产品埋点、日志与审计边界

### 18.1 产品埋点

全局候选事件沿用 PRD：

- `task_submitted`
- `task_status_viewed`
- `confirmation_decided`
- `tool_activity_viewed`
- `artifact_opened`
- `personal_model_created`
- `preferred_model_changed`
- `personal_model_deleted`
- `feedback_submitted`

埋点不包含：

- 任务正文；
- API Key；
- Memory 正文；
- 完整文件内容；
- 未脱敏真实路径。

### 18.2 三类记录的区别

- 产品埋点：用于体验分析；
- 运行日志：用于故障定位；
- 审计：用于记录用户、对象、操作和结果。

前端不得因为页面调试而突破数据最小化边界，也不得使用埋点代替业务持久化事实。

## 21. 全局验收标准

### 21.1 Desktop

- [ ] 五个一级导航名称和页面归属与 PRD 一致；
- [ ] 左侧导航支持清晰选中状态和展开/收起；
- [ ] 页面切换不影响正在运行的任务；
- [ ] P0 模块覆盖 Loading、Empty、Ready、Permission denied、Unavailable 和 Error，并在 Feature Spec 或 Living Spec 中将 Disabled、Stale、Partial 标记为已实现或 `N/A`；
- [ ] 任务、机器人、技能、工具、模型和知识使用统一中文业务名称；
- [ ] 机器人、技能和工具的分类结构与 PRD 一致，三个列表的查询、筛选和选中状态互不联动；
- [ ] Desktop 智能中心三个对象均使用卡片，Admin 工具管理继续使用表格；
- [ ] 智能中心卡片字段与本规范一致，不残留“企业/部门/我的”及技能安装类型等旧分类标签；
- [ ] 全局状态标签均为中性灰且有明确文本，机器人列表、卡片和选择项不展示状态标签，风险和错误反馈仍可清晰识别；
- [ ] 创建机器人字段、文案和四项能力开关符合 10.6，默认关闭、展开收起和选择范围行为一致；头像支持系统默认、平台预设、用户上传、预览、替换和失败反馈，预设头像不可移除，只有用户上传头像在悬停时显示“×”并可恢复默认；
- [ ] 技能、工具和知识只有限制开关开启后才能选择；关闭、有限允许列表和禁止使用三种语义在创建页、详情和复核摘要中一致；
- [ ] 创建技能先展示三字段表单，点击“下一步”后自动创建会话并发送结构化首条消息；创建会话失败后保留输入并可真实重试，重试成功进入对话，重新打开表单不继承上一次失败状态；
- [ ] 技能创建助手生成 `SKILL.md` 及按需 `references/`、`scripts/`，对话页不展示 Tool/Knowledge 选择器、“运行测试”或“提交发布”；
- [ ] 有效技能草稿进入“我创建的”，技能详情只展示四项主要信息，并从详情页发起“运行测试”和“提交发布”；测试状态和旧结果失效可被明确识别；
- [ ] 技能广场安装通过下载、校验和安全解压形成“已安装”，不执行脚本或自动安装环境依赖，安装失败不留下半安装目录；
- [ ] 技能和工具卡片不展示图标，工具 Tab 不展示“＋申请工具”或其他用户新增入口；
- [ ] 选择器只展示当前用户可用资源；
- [ ] 同名资源展示来源，不静默覆盖；
- [ ] 任务置顶、取消置顶、重命名和删除以任务列表为统一入口，排序、失败和重启恢复符合 PRD；
- [ ] 未结束或结果不确定的任务不可删除，并展示明确原因；
- [ ] 任务删除确认明确说明不可恢复、删除消息但保留成果和实际文件；
- [ ] 删除成功、删除失败、状态冲突和来源任务已删除的成果状态均有可执行反馈；
- [ ] 任务详情右侧面板只保留“概览/工作空间文件”两类视图，不残留旧 Section、标题更多菜单或元信息行；
- [ ] “产物”和“任务进程”可独立折叠，工作空间目录支持多级嵌套且不泄露绝对路径；
- [ ] 产物支持多个文件标签，Markdown/HTML 按安全边界预览，二进制或编码不支持时展示规定的页面内提示而非 Toast；
- [ ] 面板右上角工具栏按“打开本地文件夹/全屏/收起”排序；打开目标来自当前任务 Workspace，路径或授权不可用时存在清晰禁用和失败反馈；
- [ ] 面板全屏覆盖软件窗口内容区域，收起/展开入口互斥，并在模式切换后保留视图、标签、滚动和焦点状态；
- [ ] 智能授权真实接入前仅展示明确的只读“待接入”状态；接入后“手动复核/智能确认/任务内授权”均真实进入任务并由 Core 返回 resolved mode；
- [ ] WorkspaceGrant 与智能授权模式分别表达访问范围和确认策略，任何模式都不能扩大用户、Workspace 或 Tool 权限；
- [ ] 高风险操作具有明确目标、影响和确认；
- [ ] Mock、未配置和真实数据可以被明确区分；
- [ ] 企业模型按后台顺序展示；有效用户偏好优先，没有有效偏好时使用第一个可用企业模型；企业模型为空但存在可用个人模型时要求用户明确选择；
- [ ] 用户在无机器人约束的新任务中手动选模后更新用户默认模型；机器人限制只改变当前有效模型，取消机器人后恢复默认；
- [ ] 切换机器人会取消与新机器人限制不兼容的已选 Skill 和知识，并就近说明原因；切回原机器人或取消机器人时不自动恢复此前被取消的选择；
- [ ] 机器人模型限制关闭时可使用当前用户全部合法模型，开启时只允许已选模型与用户合法模型的交集；候选模型按后台稳定顺序展示，前端不自行排序；
- [ ] 机器人没有可用模型时阻止提交；Core 接受首次 `SubmitTurn` 并原子创建 Task 与 Runtime Selection 时锁定机器人和模型，发生在第一次模型调用之前；后续网络或模型调用失败也不能在原任务内切换；
- [ ] 新任务 Composer 在模型选择附近提供单一 `Max` 开关，关闭说明为“使用模型默认模式”，开启说明为“优先使用当前模型支持的最强推理模式”；
- [ ] `Max` 首次默认关闭，个人偏好用于后续新任务；换模或机器人约束改变有效模型时重新计算支持状态，不支持时使用页面内说明而非 Toast-only；
- [ ] 提交后以 Core 返回的请求状态与实际解析结果固定当前任务；后续修改全局开关不影响运行中任务，Mock 或 LocalStorage 不伪装真实生效；
- [ ] `Max` 不支持、提交时能力变化或映射失败时，任务按模型默认模式继续并持续说明“本次未启用 Max”，不因增强偏好要求用户二次提交；
- [ ] 偏好保存失败只影响后续新任务默认值，当前任务仍使用本次选择并就近提示未保存；
- [ ] 有权限用户可以在个人设置添加、编辑、更换/查看 Key 和删除个人模型；模型标识与显示名称分别填写，页面不展示测试连接，保存后状态为“未验证”；
- [ ] 网络失败保留最近失败警告但允许再次选择并真实重试；认证失败、协议不兼容和模型不存在在配置修正前保持禁用；
- [ ] 个人模型存在执行中任务时不可删除；删除默认个人模型后按统一初始规则重新选择；
- [ ] 个人 Key 默认掩码，所有者主动查看后可以再次隐藏，离开页面后清除 Renderer 明文；应用不检测系统截图；
- [ ] 除上述受控个人 Key 交互外，API Key、凭证明文、模型私有思考和未脱敏路径不进入界面；任何 Key 都不进入持久 Renderer 状态、日志、埋点、错误、Fixture 或 QA 证据；
- [ ] 核心操作可使用键盘完成，焦点清晰可见，文本与关键界面元素符合本规范对比度要求；
- [ ] Desktop 在 900 × 600 下不存在主要操作丢失和页面主体不可控横向滚动。

### 21.2 Admin

- [ ] 六个一级模块具有与页面地图和优先级一致的可访问页面骨架；系统管理不出现独立空白首页；
- [ ] 系统管理包含用户与权限、审计日志和反馈管理三个二级入口；默认进入第一个有权访问的页面，审计入口受“查看审计”权限控制，详情/编辑路由保持父子导航选中；
- [ ] P0 模块实现各自适用的列表、详情、创建和编辑页面；审计日志仅包含列表和详情，反馈管理保持 P1/Prototype，知识管理保持 P0 Conditional；
- [ ] 列表支持必要搜索、筛选、空态和异常状态；
- [ ] 模块适用的保存、测试、启停、发布和拒绝操作具有明确结果反馈；
- [ ] Tool 管理统一展示代码工具、HTTP API、MCP 三种来源；列表使用 6 个聚合列，来源/执行位置和四组状态仍分别可识别；
- [ ] Admin 创建/编辑机器人使用模型、技能、工具、知识四项限制开关；模型关闭表示目标用户全部合法模型，开启表示所选模型与用户合法模型的交集，候选项按后台稳定顺序展示；
- [ ] 机器人草稿只要求名称即可保存；测试和发布要求名称、简介、行为与规则完整，模型限制开启但无实际可用模型时必须阻止；Skill、Tool、知识空允许列表表达明确禁用而非表单错误；测试只针对已保存 revision；
- [ ] Tool 新增入口只提供连接 API 与连接 MCP 服务；代码工具可信发布后自动登记，不提供管理员添加、安装、保存草稿、测试或删除；
- [ ] 代码工具使用独立详情/策略页；管理员只配置范围、确认策略和启停，Binding/Adapter/digest 等技术事实默认折叠；
- [ ] HTTP 使用两步条件表单并在第二步支持单条 cURL 快速导入；MCP 使用 3 步条件表单并完成连接验证、发现、多选注册和 Schema 差异复核；创建均只保存草稿；
- [ ] cURL 导入在现有表单内完成解析、回填、错误和待确认项展示，不新增独立复杂流程，不把解析成功冒充连接、保存、测试或启用成功；
- [ ] MCP P0 只连接远程服务，不展示本地 Command/Arguments；发现列表业务化呈现且写入/删除/外发能力默认不选，第三步不要求管理员手写风险或用户名；
- [ ] MCP Tool 策略编辑与服务连接编辑分离；重新验证和手动重新发现从 Tool 来源进入，不自动同步、覆盖或启用；
- [ ] HTTP/MCP 保存、测试、启用互不冒充；有副作用测试明确目标和影响，不默认修改生产数据；代码 Tool 以发布验证和自动环境检查替代管理员测试；
- [ ] 普通停用明确只影响后续新任务；机器人依赖不可用时失败关闭，不静默降级或换 Tool；
- [ ] TGM 未接通前 Tool 配置页面不接收真实代码包、Endpoint 或 Secret，不修改本地状态伪造 Catalog、Policy、保存、测试、健康、启停或删除成功；
- [ ] Admin 新增技能只有“上传技能包”入口；支持 `.zip`、`.rar`、`.tar.gz`、`.tgz`，单包不超过 200 MB；包内任意目录存在且只存在一个可识别的 `SKILL.md` 即通过结构校验，并以其所在目录作为逻辑根目录；`SKILL.md` 未声明版本或版本无法识别不得计入校验失败；解析通过后进入独立编辑页，允许修改技能标题、技能描述、企业发布版本和使用范围；未找到、检测到多个、已找到但读取或解析失败时使用准确且不同的错误文案；
- [ ] 技能名称、`SKILL.md` 正文、文件清单、包摘要和校验结果保持解析只读；页面不要求管理员手工编辑目录、文件清单或 README，编辑展示信息不改写技能包；
- [ ] 文件选择、结构与安全校验、解析完成、草稿保存、测试、固定 revision、发布与客户端安装状态分离；未固定草稿可编辑，已发布版本通过“上传新版本”形成新草稿；
- [ ] 用户通用权限与具体资源权限具有唯一配置入口；
- [ ] API Key 保存后不再次展示明文；
- [ ] 已发布机器人和技能不被直接覆盖；
- [ ] 无权限模块不展示导航入口；
- [ ] 审计、日志和埋点不混用；
- [ ] Gated 能力不被前端原型伪装成已接入；
- [ ] Admin 在不小于 1024 × 720 的内容视口下完成布局、键盘和关键操作验收。

### 21.3 开发边界

- [ ] 前端没有自行新增公共 Contract、IPC 或业务状态；
- [ ] 前端不维护第二套任务状态机；
- [ ] Mock 字段具有来源或阻断说明；
- [ ] Stale 数据不会覆盖较新 revision；
- [ ] 模块接真实链路前完成对应 Feature Spec；
- [ ] 每轮演示更新 Living Spec 的已确认、假设和待确认项。

## 22. 本规范不定义的事项

本规范不定义：

- 模块具体字段全集；
- API、IPC 和事件协议；
- 数据库和持久化设计；
- Core/Central 状态机；
- Worker 和 Sandbox 实现；
- Agent/Skill Package 格式；
- Memory 写入和检索；
- 正式 SSO/RBAC；
- Task/Session 置顶持久化、物理删除一致性和历史数据迁移；
- Artifact 文件生命周期；
- 模型 Provider 协议与恢复算法；
- 知识 Provider 的真实接口。

以上内容由模块 Feature Spec、Contract、ADR 和技术计划负责。
