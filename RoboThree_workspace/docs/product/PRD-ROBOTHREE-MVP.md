## 2. 产品概述

### 2.1 产品定位

RoboThree 是面向企业员工的桌面 AI 工作台。

用户通过自然语言描述工作目标，RoboThree 使用企业授权的机器人、技能、工具、模型和知识能力，帮助员工完成工作任务，并生成可继续查看和编辑的成果。

RoboThree MVP 重点解决：

- 员工如何在不理解底层 Agent 技术的前提下开始并完成 AI 任务；
- 企业如何安全提供模型、工具、技能和知识能力；
- 本地文件、企业能力和 AI 工作流如何在明确权限边界内协同；
- 长时间任务如何展示进度、请求用户决策，并在应用重启后恢复。

### 2.2 产品目标

MVP 必须跑通以下核心闭环：

```text
用户输入任务目标
→ 选择项目空间和可选机器人 / 技能 / 模型
→ Core 校验并锁定当前任务的运行组合
→ 模型理解任务并生成最小执行计划
→ 按需读取项目空间、技能和知识
→ 调用本地或中央工具
→ 风险操作或外部发送请求 Desktop 用户确认
→ 生成并保存成果
→ 用户查看、继续修改或发起后续任务
→ 应用重启后仍可恢复任务、确认和成果关系
```

### 2.3 成功标准

MVP 达到以下结果即视为产品核心闭环成立：

1. 新用户无需预先配置机器人或技能即可创建开放式任务；
2. 用户能够明确看到当前项目空间、模型和可能使用的能力；
3. 普通文件读取、创建和修改不会被重复确认打断；
4. 删除、程序执行和外部发送具有清晰的确认信息和影响范围；
5. 用户可以查看任务状态、执行摘要、工具活动和成果；
6. 任务失败、取消、超时、等待输入和需要人工处理时均有可执行的下一步；
7. 应用重启后，任务和最终成果不会因临时流式内容丢失而不可恢复；
8. 管理员可以完成最小 Model、Tool、Agent/Skill 发布、用户权限和审计管理；
9. API Key、完整任务正文和模型私有思考过程不进入不应出现的界面或审计记录。

### 2.4 产品原则

- 从用户目标出发，不要求用户先理解 Agent、Skill、Tool 等技术对象；
- Tool 是唯一原子执行能力，MCP 只是 Tool 的实现来源之一；
- 用户可以显式选择机器人或技能，但 Core 不建设跨对象的全局智能评分和自动路由；
- 每个任务的运行组合启动后保持稳定，不因配置更新或服务波动静默切换；
- 前端展示业务状态，不建立独立于 Core Projection 的第二套状态机；
- 风险确认只绑定当前任务、目标和数据范围，不跨任务扩大权限；
- 研究、原型和临时 Mock 不自动成为正式产品事实。

## 3. 产品术语

RoboThree 的界面、帮助文案和产品需求默认使用中文业务名称。英文名称只用于技术映射、Contract、代码和首次解释，不作为用户侧一级产品导航名称。

| 中文名称 | 技术映射 | 产品定义 |
| --- | --- | --- |
| 机器人 | Agent | 面向某类工作的 AI 助手，定义默认行为、模型和能力范围 |
| 技能 | Skill | 完成某类工作的经验、流程、方法、模板和参考资料 |
| 工具 | Tool | AI 可以调用的原子执行能力，例如文件处理、浏览器、API 或数据查询 |
| 模型 | Model | 提供语言理解、推理、Tool Calling 和内容生成能力的模型 |
| 知识 | Knowledge | AI 可以查询和引用的企业信息来源 |
| 项目空间 | Workspace | 用户明确授权给 RoboThree 的本地工作目录和任务上下文边界 |
| 任务 | Task | 为完成一个用户目标而持续执行、可恢复、可取消的工作单元；用户侧一条任务等同于一条会话记录，内部 Run、Step 和 Tool Activity 不作为独立任务出现在任务列表 |
| 成果 | Artifact | 任务产生、可查看、可继续修改并保留来源关系的文件或结构化输出 |

后续 UX、Feature Spec 和客户端文案必须沿用本表，不得把 Agent、Skill、Tool 或“能力”重新作为一级导航名称。

## 4. 用户与权限

### 4.1 用户类型

| 用户类型 | 可以做什么 |
| --- | --- |
| 普通用户 | 创建任务、选择项目空间和已授权能力、确认本人发起的风险操作、查看成果 |
| 机器人/技能创建者 | 在普通用户能力基础上创建、测试个人草稿并提交发布 |
| 个人模型用户 | 在普通用户能力基础上添加和使用自己的模型连接 |
| 管理员 | 配置 Model、Tool、资源权限、可选 Knowledge，管理企业机器人/技能并查看基础审计 |

### 4.2 通用权限项

管理中心只配置少量通用权限：

- 是否可以添加和使用个人模型；
- 是否可以创建机器人；
- 是否可以创建技能；
- 是否可以提交机器人或技能发布；
- 是否可以进入管理中心；
- 是否可以查看审计。

具体资源的使用范围在资源页面配置，不在用户权限页重复维护：

- 模型页面配置模型使用范围与授权用户；
- 工具页面配置工具使用范围与授权用户；
- 机器人页面配置机器人使用范围与授权用户；
- 技能页面配置技能使用范围与授权用户；
- 知识页面配置知识使用范围与授权用户。

### 4.3 权限边界

- Renderer 不直接访问文件系统、系统命令、数据库或 Credential Store；个人模型 Key 仅按专项 Spec 在输入、保存或所有者主动查看期间短暂处理，不得持久化或进入普通 ViewModel；
- 管理员不能代替用户确认本机风险操作；
- 本地 Skill 不能扩大 Workspace 权限；
- 企业能力不可用或企业会话失效时，前端只展示 Core 提供的可用性结果，不自行推断或静默回退；
- 正式 SSO、组织同步和企业完整 RBAC 属于 Enterprise Integration，P0 前端使用测试身份和简化权限完成体验开发。

### 4.4 部门来源与展示边界

“部门”继续作为资源来源、使用范围和权限判断事实存在，但不再作为机器人或技能的前端分类 Tab，也不要求当前建设完整组织体系：

- 前端开发及测试阶段，“部门”使用测试身份中的简化部门信息；
- 正式环境以企业组织与权限系统同步结果为准；
- 前端只消费身份与权限链路提供的部门标识、名称和资源可见范围，不自行推断组织归属；
- 测试身份没有部门信息时，不生成虚假的部门来源或可见范围；
- 智能中心卡片可以把企业或部门作为“来源”文本的一部分，但不显示“企业”“部门”“我的”等分类标签。

## 6. Desktop Client 需求

### 6.1 全局体验

所有核心页面必须覆盖以下通用状态：

| 状态 | 展示要求 |
| --- | --- |
| Loading | 使用稳定骨架或进度提示，不出现无反馈白屏 |
| Empty | 解释为什么为空，并给出可执行的下一步 |
| Ready | 展示主要信息与允许操作 |
| Disabled | 展示不可操作原因，不只降低透明度 |
| Permission denied | 说明权限不足及联系管理员或切换对象的建议 |
| Unavailable | 区分本地依赖不可用、企业服务不可用和企业会话失效 |
| Error | 使用用户语言说明失败原因、可重试性和替代动作 |
| Stale | 当数据 revision 已变化时要求刷新，不覆盖较新状态 |

前端开发可以用 Mock 覆盖所有状态；接真实链路后，状态必须来自现有 Projection 或确认后的 Feature Spec。

全局状态标签统一使用中性灰样式，以状态文字作为主要信息，不使用绿、黄、蓝、红区分状态。该规则适用于智能中心、任务、设置中的模型、知识中心及其他状态标签；错误消息、风险确认、破坏性操作和阻断性页面反馈仍可使用语义色。机器人列表、卡片和选择项不展示状态标签，机器人不可操作时通过禁用态、按钮可用性和原因说明反馈。

### 6.2 工作台

#### 目标

用户无需理解 Agent、Skill 等概念即可开始任务。

#### 功能

用户可以：

- 输入任务描述；
- 附加本地文件；
- 选择项目空间；
- 选择机器人；
- 选择技能；
- 选择模型；
- 查看最近任务和最近成果；
- 查看当前选择摘要后提交任务。

“可添加文件”只表示文件可以附加到任务；是否能够读取、理解、生成或编辑，以当前模型、工具、Workspace 权限和运行状态为准。

#### 文件支持范围

| 文件类型 | 可添加 | 可读取理解 | 可生成或编辑 |
| --- | --- | --- | --- |
| Text / Markdown | 是 | P0 | P0 |
| PDF | 是 | P0 | 不支持直接编辑 |
| DOCX | 是 | 取决于已启用工具 | 取决于已启用工具 |
| XLSX | 是 | 取决于已启用工具 | 取决于已启用工具 |
| 图片 | 是 | 取决于模型能力 | P1 |
| PPTX | 是 | 取决于已启用工具 | 取决于已启用工具 |

前端不得仅根据扩展名或“可添加”状态宣传完整处理能力。提交任务前，应结合当前模型、已启用工具和 Workspace 权限展示实际可用能力；能力不可用时给出明确提示。

#### 能力选择

机器人选择项展示头像、名称和简介，不展示状态标签；机器人不可选择时，使用禁用态并给出原因说明。

技能选择项展示：已启用技能、当前项目技能、来源和可用状态。

模型选择项统一展示当前用户可用的企业模型和个人模型，常规只显示模型的显示名称；同名无法区分时补充最小来源说明。不可用模型保留显示名称并展示禁用原因。

模型选择必须遵循：

- 用户没有有效偏好时，使用后台排序中的第一个可用企业模型；
- 用户在未选择机器人且任务首次提交前手动切换模型时，同时更新用户默认模型，并用于后续新任务；
- 用户默认模型与当前待创建任务的有效模型是两个事实，不得使用一个前端字段混写；
- 机器人未开启模型限制时，可使用当前用户全部合法模型；用户默认模型仍可用时继续使用；
- 机器人开启模型限制后，只能使用机器人已选模型与当前用户合法模型的交集；用户默认模型在交集内时继续使用，不在交集内时按 Core/后台返回的稳定模型顺序临时选择第一个可用模型并明确提示；当前顺序可以来自模型配置或添加时间，前端不得自行按名称、性能或点击先后重排；
- 机器人开启模型限制但未选择任何模型时，允许保存机器人草稿，但该机器人不得运行测试、发布或开始任务；
- 机器人约束期间的模型选择不覆盖用户默认模型，取消机器人后恢复用户默认模型；
- 机器人没有任何可用模型时阻止提交，不静默扩大模型范围；
- 模型不可用时不静默替换为其他模型；
- Core 接受首次 `SubmitTurn` 并原子创建 Task 与 Runtime Selection 时，在第一次模型调用前锁定模型；此后不因列表、默认偏好、机器人配置、网络失败或模型调用失败静默切换。

首次提交前切换机器人时，已选择但不在新机器人允许范围内的 Skill 和知识立即取消选择，并在选择区就近说明取消
原因；它们不进入提交摘要或 Task Runtime Selection。用户切回原机器人或取消机器人后，不自动恢复这些已取消项，
需要用户重新选择。模型继续遵循上述“用户默认模型/当前有效模型”规则，不采用 Skill/知识的取消逻辑。

#### Max 推理开关

新任务输入框在模型选择附近提供一个全局 `Max` 开关，帮助用户用一个简单选择请求当前模型更强的推理模式：

- 首次使用默认关闭；用户手动开关后作为后续新任务的初始偏好。MVP 可以复用既有模型偏好或应用设置能力，不要求为一个布尔开关建设独立偏好系统；偏好保存失败不阻止当前任务，但必须提示“本次选择可用，未保存为后续默认”；
- 关闭表示“遵循当前模型默认行为”，系统不额外发送 Effort、Thinking Level 或推理预算参数；关闭不等于强制使用模型最小档；
- 开启后，系统优先由受控 Model Adapter 将 `Max` 映射为当前模型已验证支持的最强模式：多档模型选择最高受支持档，布尔思考模型启用思考，预算型模型使用平台审核过的增强预设；
- `Max` 是增强偏好，不是任务必须满足的硬约束。模型或 Provider 不支持、能力在提交时发生变化或安全映射失败时，不发送无效参数，任务继续按模型默认模式运行；提交前已知时使用页面内提示，提交瞬间才发现时在任务反馈或只读摘要中说明“本次未启用 Max，已按模型默认模式运行”；
- 用户在首次提交前切换模型时，系统重新计算 `Max` 的支持情况和实际映射；不要求用户理解或选择不同 Provider 的参数名、档位或预算；
- 首次提交时记录用户请求状态和本次实际解析结果；可以复用既有任务选择、模型锁和 Adapter 描述，不要求建立独立的复杂锁体系。同一任务后续对话、Tool 后模型调用、重试与重启恢复沿用该结果，之后修改全局开关只影响后续新任务；
- 开启 `Max` 可能增加响应时间和模型用量，控件附近提供简短说明，但不展示或承诺未经模型能力事实支持的精确耗时、Token 或费用；
- MVP 不提供五档推理强度选择器，不在 Admin 模型配置、个人模型设置或机器人创建中增加 Effort 参数字段，也不展示模型私有思考过程。

#### 异常处理

- 无可用模型：提示联系管理员或选择其他合法模型；
- 项目空间不可访问：提示重新选择或授权；
- 所需工具不可用：说明缺失能力；
- 企业服务不可用：使用 Core 提供的企业状态和可继续能力清单；
- 当前选择发生变化：提交前重新校验，不使用过期选择。

### 6.3 项目空间

用户可以：

- 添加本地文件夹；
- 查看项目列表；
- 移除项目授权；
- 在项目中创建任务；
- 查看项目相关任务和成果。

项目空间用于管理任务上下文、使用项目技能和访问授权文件。

#### 默认空间

未选择项目空间时，RoboThree 在应用自身管理的默认空间中工作：

- 默认空间不是任意用户业务目录；
- 只允许访问应用管理目录内的任务数据和临时成果；
- 需要读取用户业务文件、使用项目 Skill 或把成果保存到指定目录时，必须选择并授权项目空间；
- 默认空间不自动获得程序执行、网络发送或 Workspace 外文件权限；
- 前端展示“默认空间”标签，不暴露内部物理路径；
- 默认空间的容量、清理和成果迁移规则在真实文件能力接入前由 Workspace Feature Spec 冻结。

### 6.4 智能授权

智能授权是新任务输入框中的真实任务级选项，用于决定已通过固定权限、Workspace 和 Tool 风险校验的动作如何确认；它不是新的权限系统。固定用户权限、Workspace 边界、能力可用性和安全策略始终优先。

| 模式 | 行为 | 不可绕过边界 |
| --- | --- | --- |
| 手动复核 | Workspace 内普通读取可以直接执行；创建、修改及需要确认的风险动作逐次询问，确认结果不跨动作复用 | 不能扩大用户权限、Workspace 或 Tool 范围 |
| 智能确认（默认） | Workspace 内普通读取、创建和修改直接执行；删除、批量覆盖、受保护资源、程序执行和外部发送逐次确认 | 目标、数据范围或风险事实变化时必须重新确认 |
| 任务内授权 | 普通 Workspace 操作直接执行；允许复用的动作首次确认后，可在当前任务、相同目标和相同数据范围内复用 | 不跨任务；删除、程序执行和权限拒绝不能自动放行；范围扩大必须重新确认 |

“工作区授权”不是模式名称。项目空间选择器和 WorkspaceGrant 决定访问范围，智能授权模式只决定该范围内的确认策略。

用户在首次提交新任务时选择模式，任务创建成功后与 Runtime Selection 一起锁定；同一任务后续对话和重启恢复继续使用该模式，MVP 不支持任务执行中切换。模式无法满足企业或本机策略时，必须在提交前禁用并说明原因，或阻止提交，不得静默改成其他模式。

真实链路接入前，前端只能把三种模式展示为带“待接入”和“当前不改变任务执行”说明的只读卡片，不得提供可点击选中态或把选择写入本地后伪装生效。真实接入必须遵循 [Workspace 与智能授权 Feature Spec](./WORKSPACE-AUTHORIZATION-FEATURE-SPEC-v1.0.md)，通过版本化 Contract 传递 requested mode，由 Core 返回并持久化 resolved mode；现有严格 v1alpha1 不得静默改写。

确认卡片至少展示：

- 当前任务目标；
- 操作对象和 Tool；
- 文件、程序或外部目标；
- 参数或数据范围摘要；
- 可能影响；
- 本次确认的适用范围；
- 允许、拒绝或取消操作。

用户拒绝后，任务停止当前操作并展示可选替代方案；用户可以取消正在等待确认的任务。

### 6.5 任务列表

#### 产品口径

- 用户侧“任务”与“会话”一一对应，一条任务列表记录代表一条完整会话；
- 用户界面统一使用“任务”，不再同时提供含义相同的“会话”列表；
- 内部执行 Run、Step 和 Tool Activity 归属于当前任务，只在任务详情中展示，不作为独立任务列表项。

#### 列表展示与操作

任务列表展示：置顶状态、任务名称、目标摘要、更新时间、状态和主要成果摘要。

用户可以：

- 搜索任务；
- 按状态和时间筛选；
- 置顶或取消置顶任务；
- 重命名任务；
- 打开任务详情；
- 删除允许删除的本地任务。

#### 置顶与排序

- 所有状态的任务均允许置顶和取消置顶；
- 置顶状态保存在本机，应用重启后保持；
- 任务列表先展示置顶任务，再展示普通任务；
- 置顶任务按置顶时间倒序排列，任务后续更新不改变置顶区顺序；
- 普通任务按更新时间倒序排列；
- 取消置顶后，任务按更新时间回到普通任务中的对应位置；
- MVP 不限制置顶数量；
- 删除任务后，同时移除该任务的置顶记录。

#### 删除任务

删除任务是删除单个会话记录。产品行为固定如下：

- 只有已经结束且结果确定的任务允许删除，包括成功、失败、已取消和已超时；
- 准备中、执行中、等待输入、等待确认、恢复中和需要人工处理的任务不允许删除；删除操作必须不可用并展示原因；
- 删除前使用二次确认，明确任务名称、删除范围、不可恢复，以及成果和实际文件不会被删除；
- 用户确认后，物理删除该会话记录及其消息，不提供回收站、撤销或恢复；
- 删除成功后，任务从任务列表、最近任务和当前任务详情中消失，相关置顶记录一并移除；
- 该任务已经生成的成果及实际文件继续保留，不因任务删除而删除或修改；
- 保留成果通过项目空间和最近成果继续访问，来源显示“原任务已删除”，不再提供返回任务入口；
- 最小审计记录继续保留，只记录操作者、删除对象、时间和结果，不保留已删除消息正文；
- 删除期间任务状态或 revision 发生变化时拒绝删除并要求刷新；删除失败时保留当前任务和消息，展示可重试原因，不伪装成功。

前端可以按上述规则完成置顶和删除 Mock。真实置顶持久化、物理删除、审计保留以及成果独立索引接入前，必须完成 Task/Session/Artifact Feature Spec，并复核现有 Contract、IPC、外键、恢复和迁移边界。现有 tombstone 或仅隐藏列表入口的行为不等于完成本需求。

#### 用户可见状态

| 状态 | 用户含义 | 主要操作 |
| --- | --- | --- |
| 准备中 | 正在校验能力和运行条件 | 取消 |
| 执行中 | 正在生成内容或调用工具 | 查看、取消 |
| 等待输入 | 需要用户补充信息 | 补充输入、取消 |
| 等待确认 | 需要用户决定风险操作 | 允许、拒绝、取消 |
| 成功 | 任务已完成 | 查看成果、继续任务 |
| 失败 | 任务执行失败 | 查看原因、符合条件时重试 |
| 已取消 | 用户或系统已取消 | 查看历史、按新任务重试 |
| 已超时 | 任务超过执行期限 | 查看原因、重试 |
| 需要人工处理 | 外部结果或恢复状态无法自动确认 | 查看指引、重试、取消或导出诊断摘要 |

这些是产品展示状态，不修改 Core 的既有状态所有权。

### 6.6 任务详情

任务详情由对话区和右侧操作面板构成。对话区继续承载用户消息、Assistant 消息、任务输入、确认卡片及与当前会话直接相关的反馈；右侧操作面板用于查看产物、任务进程和工作空间文件。

#### 标题区精简

- 对话区保留任务标题；
- 移除标题右侧的“⋯”菜单，不在任务详情标题区提供重命名或删除入口；
- 移除标题下方“创建于… · 耗时… · 空间”的元信息行；
- 任务重命名、置顶和删除以任务列表为 P0 统一入口，并继续遵守 6.5 的状态、排序和删除规则；
- 右侧面板收起时，标题右侧仅出现用于重新展开面板的“«”图标。

#### 面板导航

右侧操作面板左上角提供视图下拉菜单，固定包含：

| 视图 | 说明 |
| --- | --- |
| 概览 | 默认视图，展示“产物”和“任务进程”两个可折叠区块 |
| 工作空间文件 | 展示当前任务所在工作空间的文件目录树 |

切换视图只改变面板主体内容，不影响对话、任务运行或已经打开的文件标签。

#### 概览视图

“产物”位于“任务进程”上方，两个标题行均可独立展开或收起：

- 产物：展示任务输出的文件列表，包括 Markdown、HTML、PPTX、XLSX、PDF 等；每项展示“图标 + 文件名 + 类型 · 时间”；
- 任务进程：展示计划步骤和工具调用记录；计划步骤使用状态点表达完成情况，工具调用展示用户可理解的名称、结果或错误摘要，不展示模型私有思考过程和基础设施细节。

“产物”是右侧面板中的界面分组名称，底层仍对应 `Artifact` / 成果事实，不建立新的产物数据模型。

#### 工作空间文件视图

- 展示当前任务所在工作空间的文件目录树；
- 目录支持多级嵌套，使用文件夹和文件两类节点；
- 文件夹节点支持展开和收起；
- 只展示当前 Workspace 授权范围内的安全相对路径或名称，不泄露未脱敏的真实绝对路径；
- 本次原型只确认目录浏览结构，文件编辑、移动、重命名和删除不属于本节范围。

#### 文件标签与面板内预览

- 点击产物条目后，不跳转到独立“成果”页面，而是在右侧面板顶部新增并激活文件标签；
- 文件标签展示文件名和关闭“×”，支持同时打开多个文件、切换和关闭；重复打开同一文件时激活已有标签，不重复创建；
- 关闭当前标签后，激活相邻标签；关闭全部文件标签后，返回最近使用的“概览”或“工作空间文件”视图；
- Markdown 文件在面板内渲染标题、列表、粗体等基础格式；HTML 文件在受控预览环境中渲染页面；
- PDF、XLSX 等二进制文件或使用不受支持文本编码的文件进入文件标签后，展示空页面状态，不使用 Toast，固定文案为：“此文件是二进制文件或使用了不受支持的文本编码，所以无法在文本编辑器中显示。”；
- 预览不可用只表示当前面板无法以文本编辑器方式展示，不代表模型或已启用工具不能读取、理解或处理该文件。

#### 面板工具栏、全屏与收起

面板展开时，右上角固定显示三个图标按钮，并按从左到右的顺序排列：

| 顺序 | 操作 | 行为 |
| --- | --- | --- |
| 1 | 打开本地文件夹 | 在操作系统文件管理器中打开当前任务所在工作空间的本地目录，相当于“在文件夹中显示 / Reveal in Finder” |
| 2 | 全屏 | 右侧面板铺满 RoboThree 软件窗口内容区域 |
| 3 | 收起 | 完全隐藏右侧面板，并把“«”展开入口移动到对话区标题右侧 |

- 三个按钮在“概览”“工作空间文件”和文件标签预览中保持相同位置；面板收起后工具栏随面板隐藏；
- “打开本地文件夹”始终针对当前任务锁定的工作空间：默认空间打开对应的用户可展示目录，不暴露应用数据库或其他内部管理文件；非默认空间打开用户已经授权的项目空间目录；
- 打开产物标签不会改变该按钮的目标目录；操作不会中断任务、切换面板视图或关闭文件标签；
- 当前任务没有可打开的本地目录、授权已经失效或目录不存在时，按钮保留位置但不可用，并展示明确原因；系统文件管理器打开失败时保留当前页面并提供可重试的错误说明；
- 前端不得把未经脱敏的绝对路径展示给用户，也不得接受任意页面文本作为打开目标；真实目录由受信任的 Workspace 能力解析并交给系统文件管理器；
- 前端可以先 Mock 该操作；接入真实系统文件管理器时必须复用受限的 Desktop/Workspace 能力，如现有 IPC 不足，应先在 Workspace Feature Spec 中冻结最小新增边界，不得让 Renderer 直接打开任意路径；
- 点击“全屏”后，右侧面板铺满 RoboThree 软件窗口的内容区域，不是仅扩大面板局部；再次点击退出并恢复原布局；
- 点击“收起”后，右侧面板完全隐藏，“»”图标同时消失，“«”展开图标移动到对话区标题右侧；
- 点击“«”后恢复面板，“«”消失，“»”重新出现在面板右上角；“«”与“»”任何时刻不得同时出现；
- 全屏、收起和重新展开不关闭文件标签，并保留当前视图、折叠状态和活动文件。

#### 移除的旧面板区块

右侧面板不再分别展示“任务信息、任务操作、运行组合、计划步骤、工具活动、文件、用户确认、成果”等 Section；其中计划步骤与工具调用合并进入“任务进程”，成果文件合并进入“产物”，用户确认继续在对话流中展示。运行组合、确认结果和文件访问等底层事实仍按现有 Projection、恢复和审计规则保留，移除界面区块不等于删除业务事实。

任务详情不展示：

- 模型私有思考过程；
- API Key、Credential Reference 或凭证明文；
- 进程、数据库事务、Lease/Fencing 等基础设施细节；
- 未经脱敏的 Workspace 真实路径和完整外发正文。

### 6.7 模型交互体验

Model Experience 产品语义已经由 [`MODEL-EXPERIENCE-FEATURE-SPEC-v1.0.md`](./MODEL-EXPERIENCE-FEATURE-SPEC-v1.0.md) 冻结。前端可以先用 Mock 实现模型确认、Streaming、默认/有效模型和恢复体验；个人模型真实 Credential 与 Provider 链路仍需完成对应架构增补、后端方案和独立编码授权。

专项 Spec 已冻结并继续约束：

- 外发确认卡片的信息层级；
- 外发目标、模型、数据类别和范围摘要；
- 允许、拒绝、取消和恢复操作；
- `connecting`、`generating`、`reconnecting`、`enterprise_unavailable`、`manual_attention`、`completed`、`failed`、`cancelled`、`timed_out` 的文案与动作；
- ephemeral Streaming 与持久 Assistant Message 的替换行为；
- 全局 `Max` 开关的默认行为、个人偏好、模型支持提示、Adapter 映射和任务级锁定；
- 可访问性和敏感信息禁止展示规则。

前端不得把临时 delta 当作持久消息重复保存；重启后只从持久消息恢复最终正文。

## 7. 智能中心

智能中心包含“机器人、技能、工具”三个 Tab，不建立跨对象统一资源模型。

### 7.1 机器人

#### 分类

| 分类 | 内容 |
| --- | --- |
| 全部 | 当前用户可见的所有机器人，包括企业发布、部门发布和我创建的机器人 |
| 我创建的 | 当前用户自己创建的机器人草稿 |

“全部”和“我创建的”允许重叠；“我创建的”用于快速进入个人草稿，不建立第二套机器人事实。

#### 列表页

机器人使用卡片列表，每张卡片只展示：

- 图标；
- 机器人名称；
- “来源 · 创建人”文本；
- 简介。

卡片不展示“企业/部门/我的”分类标签，也不展示“可用/维护中/草稿”等状态标签。状态和来源事实继续用于权限与操作判断；机器人不可使用时，通过详情或主要操作的不可用原因说明，不在卡片上增加状态标签。

#### 详情页

展示名称、创建人、使用范围、简介、行为与规则，以及模型、技能、工具和知识的限制配置摘要。

主要操作：开始任务；有权限用户可以基于已发布版本创建个人草稿。

#### 创建机器人

创建机器人页面包含“基础信息”和“能力配置”两个区域。

基础信息字段固定为：

- 头像：支持系统默认头像、平台预设头像和用户上传图片；
- 名称；
- 标签；
- 简介：用于机器人列表和选择器中的简短介绍；
- 行为与规则：定义机器人的工作方式、约束和响应原则。

创建页面不再设置“输入要求”“输出要求”“风险说明”字段；原“能力说明”统一改为“简介”，原“Instructions”统一使用用户可理解的“行为与规则”。

头像初始使用系统默认值。用户可以选择和切换平台预设头像，也可以上传本地图片并预览或替换。预设头像不提供删除或移除操作；用户可以改选其他预设头像或系统默认头像。只有当前头像来自用户上传时，鼠标悬停头像才显示覆盖式“×”移除图标，不再提供独立“移除”按钮；点击后清除已上传头像并恢复系统默认头像。未上传头像时不显示该图标。上传失败、格式不支持或文件不符合限制时保留修改前头像，并在头像字段附近说明原因。用户上传头像的格式、大小、裁切、存储和删除规则由 Agent/Skill Feature Spec 与受控文件输入链路冻结；前端原型不得把本地临时预览伪装成已保存头像。

能力配置固定为四个带开关的配置项：

| 配置项 | 开关语义 | 关闭时 | 开启后 |
| --- | --- | --- | --- |
| 模型 | 是否限制模型使用 | 不设置机器人级限制，可使用当前用户全部合法模型 | 展开模型多选区；开启后仅允许已选择模型 |
| 技能 | 是否限制技能使用 | 不设置机器人级限制，按用户和运行时可用范围处理 | 展开限制区，显示“＋添加技能” |
| 工具 | 是否限制工具使用 | 不设置机器人级限制，按用户和运行时可用范围处理 | 展开限制区，显示“＋添加工具” |
| 知识 | 是否限制知识使用 | 不设置机器人级限制，按用户和运行时可用范围处理 | 展开限制区，显示“＋添加知识” |

四个开关默认关闭，关闭时收起对应内容区；开启时在原位置展开选择内容。关闭开关不得解释为禁用全部对应资源。用户关闭已配置的开关时，已选内容保留在当前草稿中但不生效；再次开启时恢复原选择，避免因展开收起丢失配置。模型多选仅形成允许列表，不形成用户可编辑排序；实际顺序使用 Core/后台返回的稳定模型顺序，当前可以按模型配置或添加时间形成，前端不自行推断。

技能、工具和知识的“添加”不是创建新资源，而是从当前用户有权使用的现有资源中建立机器人级允许列表。只有对应限制开关开启后，“＋添加技能”“＋添加工具”或“＋添加知识”才可见和可操作；选择器支持搜索、多选、查看最小来源信息和移除已选项。关闭限制开关后不得继续展示可点击选择入口。

限制开关开启且未添加任何资源时，语义为“该机器人不允许使用此类资源”，页面必须显示就近提示，不得误写为“未限制”。保存草稿允许保留这一配置；模型为空时禁止测试、发布和开始任务，技能、工具或知识为空时在测试和提交发布复核中明确展示，并由实际任务能力需求判断是否可继续。限制开关关闭时，运行时仍只能使用用户、企业、Workspace 和当前任务共同允许的资源，不会扩大任何上游权限。

保存为个人草稿，并支持修改、测试和提交发布。

草稿与字段门槛固定为：

- 保存草稿时名称必填；简介和行为与规则允许暂缺，缺失项在草稿详情中明确标记；
- 运行测试和提交发布前，名称、简介和行为与规则全部必填；
- 每次成功保存形成新的草稿资源 revision；名称、简介、行为与规则或模型/Skill/Tool/Knowledge 限制变化时，同时形成新的 Agent instruction revision/digest；
- 头像和标签只改变展示信息，不进入 Prompt，也不单独改变 Agent instruction digest；
- 测试只能运行已经保存的准确 revision；存在未保存修改时先要求保存，不用临时表单内容冒充固定 revision。

提交发布前必须形成完整、固定、不可编辑的审核版本；状态和能力包字段在 Agent/Skill Feature Spec 中冻结。

### 7.2 技能

#### 分类

技能 Tab 没有“全部”，固定使用以下四个分类：

| 分类 | 内容 |
| --- | --- |
| 技能广场 | 企业或部门发布、当前用户可浏览安装且尚未安装的技能 |
| 已安装 | 已安装到当前工作台的技能，包含系统技能和已安装的企业/部门技能 |
| 本地目录 | 在本地项目空间或用户目录中发现的技能 |
| 我创建的 | 当前用户自己创建的技能草稿 |

四个分类按技能在当前工作台中的产品关系组织，不再使用“企业/部门/我的”作为一级分类。

#### 列表页

技能使用卡片列表，每张卡片展示：

- 技能标题，由创建者自定义的中文标题；
- 技能名称，即技术标识，使用较小的次要文本展示，例如 `ui-ux-pro-max`；
- 创建人：“技能广场”“已安装”“我创建的”展示创建人；
- 所属目录：“本地目录”展示项目空间或用户 Skill 的工作区文件夹名称；
- 技能描述。

技能卡片不展示图标，也不展示“企业/部门/我的”“已启用/未启用”“系统技能/本地技能”等分类或状态标签。技能来源、安装状态和类型仍作为分类、权限及操作事实存在。

使用次数不作为技能卡片字段。使用次数仍属于 P1；前端 Prototype 阶段允许在详情或专项原型中使用 Mock 数据，P0 没有真实统计口径和上报链路时隐藏，不以 `0` 伪装成真实统计结果。

P1 接入真实统计前，必须在 Feature Spec 中统一“用户选择”与“实际加载”的计数口径，并明确机器人固定引用、本地 Skill、测试运行和离线运行的统计及汇总规则。

#### 技能详情

技能详情的主要信息固定为四项：

| 字段 | 说明 |
| --- | --- |
| 技能标题 | 用户命名的展示标题，例如“全栈设计” |
| 技能名称 | 技能实际名称，即英文技术标识，例如 `ui-ux-pro-max` |
| 技能描述 | 技能用途说明 |
| 技能行为与规则 | 技能的工作准则、执行步骤和约束 |

技能广场详情提供“安装”操作；已安装技能可以额外查看技能目录和 Markdown 文件，并提供“卸载”操作；“我创建的”草稿详情提供“运行测试”和“提交发布”操作。系统技能如不允许卸载，应通过操作不可用原因说明，不增加状态标签。真实使用次数仅在 P1 统计能力可用后展示。

技能广场中的“安装”具有明确的文件语义：客户端下载当前用户有权使用的已发布技能压缩包，校验包身份、版本和完整性后，将其解压到对应的 RoboThree 受控 Skill 目录。只有全部文件安全写入成功后，技能才进入“已安装”；下载、校验或解压失败时不得留下可被发现的半安装目录，也不得显示安装成功。

P0 安装只负责下载、校验和解压技能文件，不自动执行 `scripts/`，不自动运行包内程序，也不自动安装 Python、Node.js 或系统级环境依赖。技能运行需要的 Tool、环境或依赖继续由 `SKILL.md` 声明，并在真实运行时按 Tool、Workspace 和用户授权规则处理。同名同版本重复安装应幂等；同名不同版本不得静默覆盖，必须通过明确的更新或替换流程处理。卸载只删除本机受控目录中的安装副本，不删除企业技能库中的已发布压缩包和历史版本。

技能测试只从“我创建的”草稿详情发起，不在创建对话页出现。详情页至少区分未测试、测试中、测试通过和测试失败，并展示与当前草稿版本对应的结果摘要和可执行的重试入口；修改草稿后，旧测试结果不得继续伪装成当前版本的有效结果。测试结果、草稿 revision 绑定方式以及“提交发布”对测试结果的要求由 Agent/Skill Feature Spec 冻结。

#### 本地技能规则

- 支持项目 Skill 和用户 Skill；
- 保留原始来源，不强制复制或改写；
- 用户明确选择后才进入任务；
- 同名来源不静默覆盖；
- 修改时基于来源创建个人技能草稿，不直接修改原始 Skill 文件；
- Skill 需要程序、网络或文件操作时仍必须通过 Tool 和用户确认。

#### 创建技能

创建技能固定为两个阶段。

**阶段一：创建表单**

用户填写以下三个必填字段后点击“下一步”：

| 字段 | 说明 |
| --- | --- |
| 技能名称 | 用户输入的展示名称，生成后作为技能标题展示 |
| 描述 | 简要说明技能解决什么问题、适合什么场景 |
| 技能主要功能 | 描述技能需要完成的核心工作，可使用多行文本 |

阶段一不提供 Tool、Knowledge、输入输出、脚本语言、依赖、权限或风险等附加配置，不把轻量表单扩展为完整技能编辑器。

**阶段二：对话式创建助手**

用户点击“下一步”后，客户端新建一个任务/会话，进入 Skill 创建助手，预选平台已确认的内置“技能创建助手”能力，并将阶段一的三个字段自动整理成第一条用户消息发送。该消息在对话中可见，用户无需重复输入。

对话页复用任务对话布局。用户可以继续通过自然语言补充要求、添加已有文件或要求助手修改目录；助手在受控工作空间内生成技能草稿目录：

- `SKILL.md`：体现技能标题、英文技术名称、技能描述、技能行为与规则、输入输出以及 Tool/Knowledge 使用要求；
- `references/`：按需保存参考资料、模板和示例；
- `scripts/`：按需保存脚本、程序及相关依赖内容。

`references/` 和 `scripts/` 没有实际内容时不生成空目录。Tool 和 Knowledge 不作为创建表单或对话页的独立功能配置，统一在 `SKILL.md` 中描述；实际运行仍受用户权限、Workspace 和授权规则约束。

创建对话页不提供“运行测试”和“提交发布”操作。助手完成有效技能目录生成后，个人技能草稿出现在“我创建的”分类；用户从技能详情查看四项主要信息，并在详情页发起“运行测试”或“提交发布”。测试结果、提交前检查、固定 Skill Package、审核和发布状态继续由 Agent/Skill Feature Spec 定义。

阶段一创建会话失败时停留在表单页，保留三个字段并展示可执行的“重试”入口。“重试”必须重新发起创建会话流程，不得只隐藏错误、跳转页面或伪装成功；重试成功后创建并打开任务/会话，继续自动发送结构化首条消息。每次重新打开创建技能表单均视为一次新的创建尝试，不继承上一次打开期间的失败或重试状态。阶段二生成失败时保留会话、用户消息和已生成文件，允许用户继续补充或重试，不返回阶段一要求重复填写。

真实创建、测试、固定能力包、审核和发布状态接入前，必须完成 Agent/Skill Feature Spec。

### 7.3 工具

工具 Tab 不设置子分类，使用单一卡片列表；机器人、技能和工具三个列表各自独立，搜索、筛选和选择状态不互相联动。

每张工具卡片展示：

- 工具名称；
- “来源 · 类型”文本；
- 描述；
- 风险等级和状态，统一使用中性灰标签。

工具卡片不展示图标。

Desktop 智能中心的工具使用卡片；Admin Console 的工具管理仍使用表格，不受本条影响。

Desktop 工具 Tab 不提供“＋申请工具”或其他用户侧新增入口。工具由管理员在中央统一配置，普通用户只浏览当前可见工具。

详情展示名称、完整描述、来源、执行位置、用途、权限、输入输出摘要、风险等级和是否需要用户确认。

前端区分“客户端预装”和“中央远程”，但不展示底层密钥、运行实例或内部 Adapter 信息。MCP 不作为独立产品类型展示。

Tool 接入与管理遵循 [`TOOL-MANAGEMENT-FEATURE-SPEC-v1.0.md`](./TOOL-MANAGEMENT-FEATURE-SPEC-v1.0.md)：

- 内置代码、HTTP API、MCP 是 Tool 的接入来源，不建立三套 Tool 资源或运行体系；
- Desktop 可以展示“客户端预装 · 内置代码”“中央远程 · HTTP API”“中央远程 · MCP”等安全来源摘要；
- 普通用户不能新增、安装、配置或测试 Tool；
- Tool 不可用时展示原因，不静默替换其他 Tool，也不把机器人自动降级为无 Tool 状态；
- Desktop 只消费安全 Catalog Projection，不接收企业 Endpoint、Credential、内部 Binding 或设备绝对路径。

## 9. 设置

### 9.1 模型管理（P0）

企业模型由后台配置、排序和授权。个人模型由后台“允许个人配置模型”权限控制，仅有权限用户可见添加入口；两类模型在任务选择器中共享一致体验，但凭证域和调用路径保持隔离。

个人模型在“个人设置 → 模型”中添加和编辑，字段固定为：提供商、接口地址、API Key、模型标识、显示名称。模型标识是提交给 Provider 的精确 Model ID；显示名称用于列表和选择器，默认等于模型标识并可单独修改。提供商包括 DeepSeek、智谱、Kimi、自定义；前三者自动带出受控接口地址，自定义由用户填写且 MVP 只支持冻结的 OpenAI-compatible 最小协议。

支持添加、编辑、更换/查看个人 API Key、删除和设置用户默认模型。本期不提供测试连接；保存成功后模型进入“未验证”，后续真实调用成功或失败再更新为可用或类型化失败状态。

网络失败表示最近一次调用的临时连接结果，模型仍可被再次选择并通过下一次真实任务调用重试；认证失败、协议不兼容和模型不存在保持禁用，分别在更换 Key、修改 Provider/Endpoint 或修改模型标识后回到“未验证”。有有效个人默认模型时继续使用；企业模型为空但存在其他可用个人模型时要求用户明确选择；只有企业模型和个人模型都不可用时才阻止新任务。

边界：

- API Key 保存后默认显示掩码；个人模型所有者可以主动显示自己的完整 Key，再次隐藏或离开页面后清除 Renderer 中的明文；企业模型 Credential 不提供查看入口；
- Renderer 仅在用户输入、保存提交或所有者主动查看期间短暂处理个人 Key，不得写入全局/持久状态、日志、埋点、错误、Fixture、测试快照或 QA 证据；
- MVP 不检测、不阻止、不审计操作系统截图或外部录屏；测试和官方演示只使用假 Key；
- 个人 API Key 只保存在本机安全凭证存储；
- 企业服务不接收、代理、备份或展示个人 API Key；
- 企业模型与个人模型不交换凭证，也不互相静默回退；
- 存在使用个人模型的执行中任务时禁止删除；其他终态任务不阻止删除，历史任务保留模型追溯摘要；删除用户默认个人模型后按统一初始规则重新选择，企业模型为空但仍有其他可用个人模型时要求用户明确选择；
- 保存后查看完整 Key 需要 ADR-013 增补或等价架构决策冻结受控反向敏感通道，完成前不得用普通 HTTP、公共 Contract 或 Mock 伪装真实回显。

### 9.2 个性化（P1 / Prototype）

支持自定义指令：输出偏好、工作习惯。

支持回复风格：默认、专业、幽默、直言不讳。

个性化内容未来是否及如何进入 Model Context、如何与机器人行为与规则组合，在真实接入前由 Personalization Feature Spec 冻结；当前版本的确定结论是“不注入”。

在该专项 Spec 获得接受前，个人设置中的自定义指令、输出偏好、工作习惯和回复风格只允许 Prototype 展示，不进入
生产 Platform Prompt、Agent Layer、Skill Layer 或 Dynamic Reference。未来真实接入时应使用独立、可版本化且
任务级锁定的 User Preference `advisory` layer，不直接修改 Platform Prompt 或机器人行为与规则，也不得授予
Tool、Workspace、Knowledge、模型或授权权限。

### 9.3 个人记忆（P1 / Prototype / Gated）

前端可以先实现个人记忆的查看、修改和删除页面原型。

真实记忆的写入、检索、上下文注入、敏感内容 Gate、删除一致性和外发确认由独立长期记忆 PRD、ADR 和开发计划负责；在这些文档获得接受前，本入口不得连接真实 Memory Store，也不得自动从任务、Tool、Knowledge 或文件内容生成记忆。

### 9.4 问题反馈（P1 / Prototype）

用户可以描述问题并上传截图。前端原型应覆盖提交中、提交成功、提交失败、截图移除和隐私提示。

真实反馈接收系统、截图存储、保留期限、敏感信息处理和管理员回复能力在 Feedback Feature Spec 中确认。

### 9.5 登录与身份（P1 / Enterprise Integration）

正式环境计划接入企业统一身份认证和企业现有 RBAC 权限体系：

- 用户通过企业单点登录进入 RoboThree；
- 登录后同步用户身份、组织信息和企业授权结果；
- RoboThree 不重复建设复杂组织、角色和权限继承体系；
- 测试和前端开发阶段使用测试账号和简化权限配置。

正式 SSO、组织同步、会话失效、设备信任和权限刷新不属于当前前端自主实现范围。

## 10. Admin Console

### 10.1 通用要求

- Admin Console 以桌面端业务对象为管理入口，不建设统一“能力”管理页；
- 列表、详情和编辑页面覆盖 Loading、Empty、Permission denied、Unavailable 和 Error；
- 保存操作必须显示成功或失败结果，不使用仅关闭弹窗作为成功反馈；
- API Key 和凭证明文保存后不可再次展示；
- P0 可以使用简单用户和权限列表，不建设复杂组织继承。

### 10.2 模型管理（P0）

列表展示模型名称、Provider、状态、是否默认和更新时间。

详情展示基础信息、使用范围、授权用户和模型能力。

新增/编辑支持 Provider、Endpoint、Model ID、显示名称、API Key、使用范围、授权用户、启停和测试连接。

管理员不能查看个人模型 API Key，不填写内部 Credential Reference。

### 10.3 工具管理（P0）

工具管理使用统一表格，区分“代码工具/HTTP API/MCP”接入来源和“客户端预装/受控 Runtime/中央远程”执行位置。代码工具内部继续标注“官方内置/企业可信包”交付来源。首屏按管理员任务聚合为 6 列：Tool、接入方式、状态、治理、更新时间、操作；配置、验证、健康和生效四组状态仍须分别可识别。搜索和来源筛选常驻，执行位置、状态、风险和使用范围进入“更多筛选”。列表不展示 Endpoint、Credential Reference、Secret、设备绝对路径或内部 Runtime Handle。

当前 Document Tool 与其他代码工具属于同一类型。官方或企业代码实现须由研发在 Admin Console 之外完成开发、构建、功能与安全测试、受控发布和可信 Manifest 登记；发布成功后自动进入企业 Tool 列表，默认处于“待启用”或“当前环境不可用”。Admin Console 不承担代码上传、在线编写、构建、依赖安装、发布、安装或候选选择。

“新增 Tool”只提供两种配置接入方式：

1. 连接 API：手动配置或粘贴单条 cURL 快速生成一个受控 HTTP Operation；P0 支持 GET/POST，解析结果回填现有 Connection、认证、请求方式、参数和使用范围表单；OpenAPI/Swagger 文本、文件、URL及批量 Operation 导入后置 P1；
2. 连接 MCP 服务：P0 只连接 Central 可访问的已部署远程 MCP 服务，不展示“远程/本地”类型选择；管理员填写服务名称、地址，并从“无需认证 / 访问令牌（Bearer Token） / API Key”中选择认证方式。选择后两者时在当前表单直接填写 Token/API Key；API Key 默认通过 `X-API-Key` Header 发送，特殊 Header 名称收进高级配置，不允许将 API Key 放入 URL Query。验证后自动发现 Tool，选择一个或多个能力分别保存为 RoboThree Tool 草稿。不建设独立 MCP 菜单、Credential 库或凭证选择器，Server identity、稳定 ID 和 Schema 由系统生成。

代码工具不提供创建、添加、安装、草稿、手动测试或删除入口。可信发布物自动登记后，系统自动检查 package、Runtime 和客户端兼容性；管理员只查看能力说明、来源、版本、风险和当前环境状态，配置允许范围、更严格确认并启用/停用。Binding、Adapter、digest、Runtime 等技术事实默认收进“技术详情”。

HTTP 创建对齐当前原型，收敛为“基础配置 → 连接配置”2 步；第二步顶部提供“粘贴 cURL 快速导入（推荐）”，解析后直接填入现有 API 地址、认证、Method 和参数卡片，管理员检查后保存草稿。手动填写始终作为兜底。MCP 创建保持“验证并发现工具 → 选择 Tool → 设置范围并保存草稿”3 步。两类创建都只保存草稿，单个 Tool 的安全测试和启用统一在详情页完成。普通管理员首先看到业务名称、用途、连接信息和使用范围；技术名称、Schema、映射、超时和重试等低频字段由系统生成或默认折叠到“高级配置”。

cURL 导入每次只处理一条请求，使用确定性解析器，不执行 Shell、不发起 API 请求，也不依赖模型猜测 Method、URL、参数位置或认证方式。解析出的示例值默认只是示例，不自动写死；检测到 Authorization、API Key、Cookie 或 Basic Auth 等敏感值时只显示认证类型和掩码，不把 Secret 自动写入普通字段或持久草稿，管理员在当前 Connection 表单直接填写或重新确认 Token/API Key。原始 cURL 和明文 Secret 不进入草稿正文、浏览器持久存储、日志、埋点、审计或 QA evidence。解析失败或部分解析必须逐项指出，不能静默丢弃字段。

MCP 首次发现以业务名称、技术名称、用途和读取/写入/删除/外发风险摘要展示；提供搜索、“选择全部只读工具”和取消选择，读取能力可默认选择，写入、删除和外发能力默认不选。第三步统一设置“所有人/指定范围”和“遵循默认规则/全部额外确认”，管理员只能收窄范围或增加确认，不能降低远端 Tool 的风险要求。风险摘要由系统生成，不要求管理员逐个重写 Schema、参数、Endpoint 或风险事实。

本地 MCP 不属于 P0 管理员配置。Admin 不接收 `Command`、`Arguments`、`npx`、工作目录、环境变量或依赖安装；未来如支持本地 MCP，必须先通过可信发布和受控 Runtime 部署后自动登记。MCP Tool 详情只编辑标题、补充说明、范围、额外确认和启停；服务地址与访问密钥在“来源 MCP 服务”的连接详情统一编辑和重新验证/发现，不建设一级 MCP 模块，也不自动同步或启用新发现的 Tool。

MVP 不建设独立企业 Tool Credential 管理功能。管理员在 HTTP/MCP Connection 表单中直接填写当前连接需要的 API Key 或 Token，密钥随连接受控保存；保存后只显示掩码，编辑时只能保留或替换，不能查看完整值，也不允许跨连接选择复用。内部密钥引用、企业 Endpoint 和原始远程响应不下发 Desktop/Core。

HTTP/MCP 的保存草稿、测试通过、启用、运行健康和当前用户可用必须分开；满足安全测试或 TGM-0 冻结的替代验证门槛前不得启用，有副作用 Tool 不得默认对生产数据执行测试。代码 Tool 使用研发发布验证和系统自动环境检查，不要求管理员重复测试。

普通停用形成新的配置/Registry generation，只影响使用新 generation 的新任务。运行中任务保持创建时锁定的精确 revision；被机器人引用的 Tool 停用后，新任务显示能力配置不完整并失败关闭，不删除引用、不自动换 Tool。代码 Tool 不提供管理员删除，可信实现下架由研发发布流程处理；仅从未启用且未被引用的 HTTP/MCP 企业草稿允许删除企业登记。

Tool 管理接真实链路前必须遵循 `TOOL-MANAGEMENT-FEATURE-SPEC-v1.0.md` 和 TGM-0～TGM-5 门槛。Prototype/GATED 页面只能使用明确 Fixture 或禁用控件，不得接收真实代码包、Secret、生产 Endpoint，不得修改本地状态并伪造新增、测试、启停或删除成功。

### 10.4 机器人管理（P0）

企业机器人列表展示名称、创建人、状态和使用范围。

详情展示基础信息、使用范围、版本，以及模型、技能、工具和知识的限制配置摘要。限制关闭时显示“未设置机器人级限制”，不能显示成“无”；限制开启且列表为空时显示“不允许使用任何此类资源”。

管理员创建和编辑企业机器人草稿时，基础信息与 Desktop 创建机器人保持同一业务命名：头像、名称、标签、简介、行为与规则；管理端额外配置发布范围。不得重新使用“一句话说明”“Instructions/System Prompt”等旧界面名称作为主字段。

能力配置与 Desktop 使用同一套四项限制开关：模型、技能、工具和知识均默认关闭并收起。模型开关关闭表示不设置
机器人级限制，可使用目标用户全部合法模型；开启后仅允许已选模型。只有管理员打开对应限制开关后，才展开选择区
并出现“添加技能”“添加工具”“添加知识”或模型多选；管理端不得默认铺开全部资源复选框。模型多选不提供前端
自定义排序，使用 Core/后台稳定顺序。

- 技能选择器只展示企业内已发布、当前管理员有权引用且未停用的技能；
- 工具选择器只展示企业已启用、未撤销且允许被机器人引用的 Tool；
- 知识选择器只展示当前企业已配置且管理员有权引用的知识源；
- 模型选择器只展示当前企业可用且允许该机器人使用的模型；
- 选择器使用搜索和多选，已选项回到展开区展示；同名资源补充来源或版本，不能静默选错；
- 开关关闭后保留草稿中的已选项但暂不生效，再次开启恢复；保存、测试和发布摘要必须分别展示开关状态与实际生效列表。

管理员创建的草稿可以免人工审核，但必须完成测试、固定版本并显式发布；发布前不对用户开放。提交发布时固定当前有效的模型、技能、工具和知识引用及其 revision。已发布机器人修改后生成新草稿版本，不直接覆盖当前发布版本。被选择的资源在测试或发布前变为不可用时阻止继续并指出具体资源；发布后资源被停用或撤销时，后续新任务按既有失败关闭规则处理，不自动扩大允许列表或替换资源。

用户提交的机器人审核支持通过和拒绝，拒绝必须填写原因。

### 10.5 技能管理（P0）

支持企业技能列表、技能详情、上传并解析技能压缩包、编辑企业技能草稿信息、配置使用范围、草稿测试、固定版本发布和停用。P0 不提供在 Admin Console 中从空白表单编写 `SKILL.md`、目录路径、文件清单或脚本的“创建企业技能”编辑器；需要修改技能行为、Markdown 正文、脚本或其他包内文件时，由创建者在本地或受控研发流程中修改文件并重新上传新压缩包版本。

管理端“新增技能”固定为上传技能包：

1. 管理员选择 `.zip`、`.rar`、`.tar.gz` 或 `.tgz` 压缩包；单个上传压缩包不得超过 200 MB；
2. 系统先在隔离暂存区校验文件类型、压缩包大小、解压后总量、路径穿越、绝对路径、符号链接和同名冲突，不执行包内脚本；加密或需要密码的压缩包不属于 MVP 支持范围；
3. 压缩包内任意目录必须存在且只能存在一个可识别的 `SKILL.md`，不要求该文件位于压缩包最外层；系统以 `SKILL.md` 所在目录作为该技能包的逻辑根目录，并从该目录识别同级或下级的 `references/`、`scripts/` 和其他技能文件，不要求管理员额外填写目录路径、README 或文件清单。扫描不到时提示“包内未找到 SKILL.md”；检测到多个时提示“检测到多个 SKILL.md，当前只支持单技能包”，不得自行猜测；已经找到唯一文件但读取、解压或内容解析失败时，必须反馈对应失败原因，不得误报为文件不存在；
4. 系统从 `SKILL.md` 解析技能名称、Markdown 正文和描述；包内版本声明属于可选信息，存在时只作为辅助回填和只读参考，缺失、无法识别或不符合企业发布版本格式均不得计入上传校验失败；技能标题默认依次取显式标题、Markdown 一级标题或由技能名称生成的可读名称；
5. 校验和解析通过后不直接创建草稿，而是进入“编辑技能信息”页面。管理员可编辑技能标题、技能描述、版本号和使用范围；技能名称、`SKILL.md` 正文、压缩包名称、文件清单、完整性摘要和校验结果只读；
6. 企业技能发布版本由管理员在编辑页填写并按 `主版本.次版本.修订号` 校验；只有包内版本能够被识别为有效发布版本时才可用于预填，否则版本号输入框保持为空并由管理员填写，不阻止进入编辑页。已有同名技能上传新版本时，发布版本必须高于当前已发布版本且不得与已有版本重复；“草稿”是独立生命周期状态，不在版本号后自动追加 `-draft`；
7. 管理员确认编辑信息后保存为企业技能草稿；上传并解析成功不等于草稿已保存、测试通过、发布成功或用户已安装；
8. 草稿完成测试并固定不可编辑的“技能包摘要 + 技能信息 + 使用范围”revision 后，由管理员显式发布；发布后进入用户“技能广场”。

技能标题、技能描述和版本号是企业技能目录中的草稿与发布信息，用于列表、详情、版本选择和安装更新判断；编辑这些字段不会改写原始压缩包或 `SKILL.md`，也不会改变技能运行行为。技能名称是从 `SKILL.md` 解析的稳定技术标识，不允许在页面修改。编辑页应同时展示包内原始描述，以及存在时的包内版本声明；包内未声明版本时显示“未声明”，不得作为错误或警告。当管理员填写内容与包内声明不同时，必须明确区分“展示信息”和“包内声明”，避免误认为 Markdown 已被改写。

管理员上传的技能可以免人工审核，但不能跳过包结构与安全校验、信息编辑复核、测试、版本固定和显式发布。未固定草稿可继续编辑标题、描述、版本号和使用范围；修改版本号时重新校验唯一性和递增关系。已发布技能及已固定 revision 不可原地编辑；更新时上传新压缩包并重新进入编辑页形成新草稿版本。企业服务保存原始发布包、固定技能信息、发布版本和完整性摘要，客户端安装时下载同一发布包并校验后解压到对应的受控 Skill 目录。

Admin Console 只审核固定能力包，不展示或管理创建者测试报告。

### 10.6 知识管理（P0 Conditional）

支持添加一个企业知识源、配置连接、设置使用范围与授权用户、测试连接和查询、查看最近错误。

真实数据源未确定时，本模块可以保持未配置状态，不阻塞其他 P0 能力。

### 10.7 系统管理

系统管理统一承载用户与权限、审计日志和反馈管理三个二级页面，不建立独立的系统管理概览页。一级导航点击后默认进入当前管理员有权访问的第一个二级页面；进入任一详情或编辑页时，一级导航继续保持“系统管理”选中，并在二级导航中标明所属模块。

#### 10.7.1 用户与权限（P0）

用户权限页面只配置通用权限；具体资源使用范围回到对应资源页面配置。同一项权限不得在两个位置产生可冲突的事实源。

测试阶段使用简化用户和权限配置；正式 SSO、组织和完整 RBAC 后置到 Enterprise Integration。

#### 10.7.2 审计日志（P0）

支持按用户、时间、对象类型和结果查询：

- 使用的机器人、技能、工具、模型和知识；
- 文件访问和修改摘要；
- 用户确认结果；
- 任务最终结果和成果；
- 管理员配置变更；
- 机器人/技能发布审核记录。

审计不展示完整任务正文、API Key、凭证明文、模型私有思考过程和不必要的敏感数据。P0 只要求页面查询，不要求审计导出。

审计日志只对具有“查看审计”权限的管理员显示，保持只读；MVP 不将其提升为独立一级菜单。只有后续扩展出风险事件、登录记录、安全告警、留存策略和合规报表等完整安全治理能力时，才重新评估独立“安全与审计”一级模块。

#### 10.7.3 反馈管理（P1 / Prototype）

反馈列表展示反馈内容摘要、反馈人、反馈时间和处理状态。

反馈详情展示截图、完整反馈内容和必要的客户端版本信息。

当前页面不包含企业公告、通知发布、消息模板或通知渠道配置，因此不再使用“通知与反馈”名称。MVP P0 不建设独立消息中心、工单流、多级处理和 SLA 管理。

## 11. 核心产品流程

### 11.1 开放式任务

```text
用户输入目标
→ 选择项目空间和可选机器人 / 技能 / 模型
→ Core 校验固定权限和运行组合
→ 模型理解任务
→ 读取必要项目空间 / 知识
→ 调用工具
→ 风险操作请求用户确认
→ 生成成果
→ 用户查看并继续修改
```

### 11.2 本地技能

```text
用户授权项目空间
→ 系统发现项目级或用户级候选 Skill
→ 用户手动选择明确来源
→ 系统读取可兼容内容，不改写原文件
→ 检查所需 Tool 和 Workspace 范围
→ 执行任务
→ 保存成果和基础审计
```

### 11.3 机器人/技能创建与发布

```text
机器人：填写基础信息并按需开启模型/技能/工具/知识限制
→ 保存个人草稿并按机器人流程测试、提交

技能：填写技能名称、描述和技能主要功能
→ 点击“下一步”进入新任务/会话
→ 系统自动发送表单信息并调用内置技能创建助手
→ 助手生成 SKILL.md、references/ 和 scripts/
→ 草稿进入“我创建的”
→ 用户打开技能详情运行测试
→ 在技能详情点击“提交发布”
→ 系统生成不可编辑审核版本
→ 管理员通过或拒绝
→ 发布或返回修改
→ 已发布内容更新时创建新草稿版本并重新发布

企业技能：管理员上传包含 SKILL.md 的技能压缩包
→ 系统安全校验并解析包内容，不执行脚本
→ 进入编辑页，修改技能标题、技能描述、版本号并配置使用范围
→ 技能名称、SKILL.md 正文、文件清单和校验结果保持只读
→ 保存企业技能草稿
→ 测试、固定压缩包 revision 并显式发布到技能广场
→ 用户点击安装后客户端下载并校验发布包
→ 解压到对应受控 Skill 目录
→ 全部文件写入成功后进入“已安装”
```

### 11.4 企业服务不可用

```text
客户端无法连接企业服务
├─ 企业会话仍有效
│  → 只使用 Core 判定为当前可继续的本地能力
└─ 企业会话失效
   → 企业能力暂停

Central 恢复
→ Core 复核会话和设备状态
→ 如发现配置更新，Desktop 提示用户是否同步并应用
→ 用户确认后完成受控同步和 Runtime Activation
```

前端不得在 Central 恢复后自行下载、激活配置或静默切换当前任务能力。

## 13. AI 与运行编排要求

### 13.1 模型选择

- 后台企业模型顺序、用户默认模型、机器人允许模型和当前任务有效模型分别具有唯一事实源；
- 没有有效用户偏好时使用后台顺序中的第一个可用企业模型；
- 用户在无机器人约束的新任务中手动选模后更新用户默认模型；
- 机器人未开启模型限制时可以使用当前用户全部合法模型；开启后只能使用已选模型与当前用户合法模型的交集；
- 用户默认模型在允许范围内时继续使用，不允许时按 Core/后台稳定顺序临时选择第一个可用模型；临时选择不覆盖用户默认模型，取消机器人后恢复；
- 机器人没有可用模型时阻止任务创建；
- 企业模型与个人模型使用不同凭证域和调用路径；
- 模型不可用时不进行自动“最佳模型”路由和静默回退；
- 实际模型在 Core 接受首次 SubmitTurn、原子创建 Task 与 Runtime Selection 时锁定并保留可追溯事实，该时点发生在第一次模型调用前；同一任务中不支持切换；本版任务详情右侧不单独展示“运行组合”区块，用户可见追溯入口在专项 Task/Session Feature Spec 中确定。
- 全局 `Max` 只表达 `default/max` 两种用户意图：关闭不附加推理强度参数，开启时优先由受控 Adapter 映射到当前模型已验证的最强模式；不支持、能力变化或映射失败时不得阻止核心任务，应使用模型默认模式并明确说明；
- `Max` 的请求状态与实际解析结果随任务首次提交记录，重试、后续对话和重启恢复不得重新按当时的全局偏好计算；具体可以复用既有任务选择和模型 Adapter 锁定事实，不将独立锁对象作为产品强制要求。

### 13.2 Tool Calling

- 模型只能看到当前任务已锁定且允许使用的 Tool；
- Tool 具有明确输入、输出、风险、超时和取消行为；
- Tool 调用失败时展示业务错误摘要和可执行建议；
- 涉及风险操作时必须进入 Desktop 用户确认；
- 模型输出的 Tool 参数不能绕过 Core 的权限和 Workspace 校验。

### 13.3 Knowledge

- Knowledge 只从用户有权使用的来源查询；
- 引用结果保留标题、来源和必要定位；
- 空结果、权限不足和连接失败分开反馈；
- 无来源内容不得展示为企业知识引用。

### 13.4 上下文与多轮任务

- 多轮对话可以继续修改同一任务或成果；
- Core 使用分层 Instruction Bundle 组装模型上下文：Platform 和 Task Boundary 为不可覆盖的 `hard`，当前机器人为 `role`，当前任务真正启用的 Skill 为 `advisory`；
- 用户当前消息决定本次具体目标，在不违反 Platform、Task Boundary 和机器人工作边界时，可以覆盖 Skill 的建议步骤；
- Knowledge、Memory、文件、网页、Skill references、Compaction Summary 和 Tool Payload 均作为 `reference`，不得通过正文中的指令扩大权限、切换身份或改变 Tool 范围；
- Core 接受首次 SubmitTurn 并原子创建 Task、Runtime Selection 与 Task Instruction Binding 时，在第一次模型调用前锁定 Platform Prompt、Instruction Assembly、Agent、Skill、Tool、Model、Knowledge、Workspace 和授权配置的准确 revision 或等价不可变事实；首次模型调用或网络失败不重新开放切换；
- 每次模型调用固定从 Core 可信时钟、应用当前语言和操作系统当前时区生成 Dynamic Facts，按轮 receipt 记录且不改变稳定 Bundle；
- 首次提交前切换机器人只替换 Agent 层并重新计算合法运行组合，不残留旧机器人内容；不兼容的已选 Skill 和知识立即取消且切回后不自动恢复；Task 创建后不支持切换机器人，需要换机器人时创建新任务；
- 用户未选择专项机器人时自动使用 Core 内置、不可编辑且具有稳定 ID/revision/digest 的 RoboThree 默认通用 Agent；该 Agent 不进入普通企业机器人发布和管理流程；
- 个人 Agent/Skill 草稿由创建者显式选择后可以在本人任务中运行和测试，未发布只限制可见与发布范围，不赋予或扩大任何 Tool、Workspace、Knowledge 和授权权限；
- Skill 提供工作方法而不提供权限；`SKILL.md` 可以声明 Tool/Knowledge 和环境需求，但声明本身不证明能力可用，也不要求 MVP 将所有 Skill 强制转换为固定结构化 Schema；全部已选择并锁定的 Skill 主正文视为不可拆分必需项，提交前超预算时要求用户减少 Skill 或显式换模，Skill references 才允许按相关性裁剪；
- Agent 名称、简介和行为规则在保存、发布或物化时一次编译形成不可变 revision，模型调用时不从当前可变字段重新生成，历史任务继续使用历史 revision；
- Tool 是否成功只以 Core 已提交的结构化 outcome 为准，Tool Payload 中的自然语言不能覆盖该结果；Effect 为 `uncertain` 时暂停普通 Agent Loop，任务所有者可选择“确认已成功 / 确认未发生或失败 / 继续等待”，核对形成独立事实且永不改写或重新 dispatch 原 Effect；
- Context 按来源控制预算，Platform、Task Boundary、Agent 和全部已锁定 Skill 主正文不被静默截断；先裁剪动态 Reference、压缩历史和缩短旧 Tool Result 预览，仍无法适配锁定模型时明确失败，不自动切换模型；
- 相同优先级的多个 Skill 使用任务锁定的确定性 ordinal 和最终 sourceId tie-breaker 形成稳定顺序与 digest；该顺序只保证复现，不产生隐式权限或业务优先级；
- Provider 适配前由 Core 内单一 Bundle Compiler 生成带固定、可转义边界的有序 System blocks；多 System 保持顺序，单 System 按同一 wrapper 合并，MVP 不使用 Developer Role，Reference 永不转成 System；不要求建设独立大型 Provider Compiler，也不并入 Max Mapping；
- 同一 Model Invocation 的重试和恢复复用原 Dynamic Facts 与 Knowledge retrieval receipt，新一轮 Invocation 才允许重新检索；原 chunk 缺失时失败或等待，不用当前内容替换；
- 临时 Streaming 不成为第二份持久消息；
- 长期记忆与当前会话、Compaction 和 Knowledge 分开管理；长期 Memory 未获专项授权时不进入生产上下文；
- Personalization Feature Spec 未获接受时，个人自定义指令、输出偏好、工作习惯和回复风格不进入生产 Model Context；
- 完整规则、变量模板、Platform Prompt v1、预算与验收标准见 [`CORE-PROMPT-AND-CONTEXT-FEATURE-SPEC-v1.0.md`](./CORE-PROMPT-AND-CONTEXT-FEATURE-SPEC-v1.0.md)。

### 13.5 安全与幻觉控制

- 不展示模型私有思考过程；
- 需要事实来源的 Knowledge 结果展示引用；
- Tool 结果和文件内容使用有界摘要进入模型上下文；
- 无法确认外部操作结果时进入“需要人工处理”，不盲目重试；
- 敏感内容、凭证和完整任务正文不进入日志、审计和 QA 证据。

## 15. 非功能要求

### 15.1 性能建议目标

| 指标 | 建议目标 |
| --- | --- |
| Desktop 冷启动 | 5 秒内进入可交互状态 |
| 本地任务状态更新 | 500ms 内反映到 UI |
| 模型首字响应 | Provider 正常时 5 秒内 |
| 用户取消传播 | P95 1 秒内到达受控 Tool |
| 企业配置本地读取 | 500ms 内可用 |
| 重启恢复识别 | 10 秒内识别未完成任务状态 |

具体指标在真实 Model、企业网络和安装包环境接入后重新验证；可以收紧，不得静默放宽。

### 15.2 可靠性

- 应用重启后恢复会话、任务和成果关系；
- Tool 失败、超时、取消和不确定结果具有不同状态；
- 配置同步失败不覆盖最近一次成功配置；
- 重试不重复破坏已完成工作；
- 历史任务不因后续配置变化被静默改写。

### 15.3 安全

- 跨进程和跨服务输入必须校验；
- 文件操作使用真实路径边界；
- 除个人模型 Key 按专项 Spec 在输入、保存或所有者主动查看期间短暂处理外，API Key 和敏感凭证不得进入 Renderer；任何 Key 均不得进入 Renderer 持久状态；
- 风险操作必须经过 Desktop 用户确认；
- 未经审核的可执行扩展不进入 Core 进程；
- 审计不包含完整任务正文和凭证明文。

### 15.4 可访问性

- 核心操作可使用键盘完成；
- 弹窗打开后正确管理焦点，关闭后返回触发位置；
- 状态不只依赖颜色表达；
- 表单控件具有可读 Label、错误说明和帮助文本；
- Loading、Streaming 和状态变化向辅助技术提供适当提示；
- 动画支持减少动态效果偏好。

### 15.5 可维护性

- 前端组件与业务 Projection 分离；
- Renderer 不建立第二状态机；
- Mock 与真实 Adapter 使用明确边界；
- 页面新增数据需求先记录，再决定复用或扩展 Contract；
- 每个接入真实链路的模块具有自动化测试、独立 QA 和用户体验验收。

## 16. 日志、埋点与审计

### 16.1 产品埋点候选

| 事件 | 目的 |

- 审计用于记录用户、对象、操作和结果；
- 三者不能互相替代，也不能因调试需要突破数据最小化原则。

- [ ] 用户创建任务时可以选择真实生效的智能授权模式，任务创建后锁定，三种模式具有可验证的确认行为差异并在重启后保持；
- [ ] 模型不可用时不静默切换；
- [ ] 普通文件操作和风险操作按授权规则处理；

- [ ] Renderer 不直接访问文件、数据库或 Credential Store；个人 Key 只在受控交互中短暂处理并在隐藏/离开后清除；
- [ ] 不展示模型私有思考过程。

- [ ] 官方或企业代码 Tool 完成可信发布后自动进入企业列表；技术事实只读，管理员不添加、安装、保存草稿、测试或删除代码 Tool，只配置范围、确认策略和启停；
- [ ] 新增 Tool 只提供连接 API 与连接 MCP 服务；HTTP 使用两步创建并在第二步支持单条 cURL 快速导入，MCP 保持 3 步；两者均在详情页测试、启用；
- [ ] cURL 解析回填同一份手动表单，不执行命令、不联网、不自动保存/测试/启用；敏感值只识别类型并脱敏，Token/API Key 由管理员在当前 Connection 表单直接填写；
- [ ] MCP P0 只连接远程服务，使用“验证并发现 → 选择 Tool → 设置范围并保存草稿”；不展示本地 Command/Arguments，写入/删除/外发能力默认不选；
- [ ] MCP Tool 策略和服务连接分别编辑；重新发现只产生待复核变化或新草稿，不自动启用、不静默覆盖机器人引用；
- [ ] MCP 只作为 Tool 实现来源出现，不建设独立 MCP 菜单；
- [ ] 配置、验证、健康和生效状态分开；HTTP/MCP 保存、测试和启用互不冒充；代码 Tool 的发布验证和自动环境检查不伪装成管理员测试；
- [ ] 企业 Tool Credential 不下发客户端，GATED 页面不接收真实 Secret 或伪造成功；
- [ ] 普通停用只影响新任务，运行中任务保持精确锁定；被机器人引用的 Tool 不可用时新任务失败关闭且不静默换 Tool；
- [ ] Admin 创建/编辑机器人使用与 Desktop 一致的四项限制开关；模型限制关闭允许目标用户全部合法模型，开启后仅允许已选模型并使用 Core/后台稳定顺序；技能、工具和知识只有开关开启后才能选择，列表不再默认铺开全部复选框；
- [ ] Admin 机器人选择器只展示当前企业可引用资源，同名项展示来源或版本；发布复核明确区分“未限制”“限制为所选资源”和“禁止使用该类资源”；
- [ ] Admin 新增技能只通过上传 `.zip`、`.rar`、`.tar.gz` 或 `.tgz` 压缩包开始，单包上限为 200 MB；包内任意目录存在且只存在一个可识别的 `SKILL.md` 即通过结构校验，系统以其所在目录作为逻辑根目录；`SKILL.md` 未声明版本或版本无法识别不得阻止解析和进入编辑页；编辑页允许修改技能标题、技能描述、企业发布版本和使用范围，技能名称、`SKILL.md` 正文、文件清单和校验事实保持只读；未找到、检测到多个、已找到但读取或解析失败时分别提供准确反馈；
- [ ] 技能包选择、结构与安全校验、解析完成、技能信息编辑、草稿保存、测试、固定 revision、发布和客户端安装是相互独立的状态；编辑展示信息不得改写原始技能包或冒充技能行为已变化；
- [ ] 技能包发布后用户安装等于下载、校验并解压到受控 Skill 目录，安装过程不执行脚本、不自动安装环境依赖，失败不伪装成功；
- [ ] 管理员可以管理机器人/技能草稿、固定版本和发布；
- [ ] 管理员只审核不可编辑的固定能力包；
- [ ] 用户通用权限和具体资源权限具有唯一配置入口；
- [ ] 用户与权限、审计日志和反馈管理不再作为独立一级菜单；系统管理默认进入第一个有权访问的二级页面，无审计权限时隐藏审计入口；
- [ ] Knowledge 未配置时不阻塞其他模块；
- [ ] 审计不展示完整任务正文和凭证明文。

### 17.4 端到端验收任务

1. 用户打开 Desktop，选择或授权一个项目空间；
2. 用户选择机器人或使用默认机器人，选择合法模型；
3. 用户提交一个包含本地文件读取的任务；
4. Core 锁定运行组合并执行模型与 Tool 链路；
5. 普通读取直接执行，外部发送或风险操作请求确认；
6. 用户允许后任务继续，拒绝后获得替代建议；
7. 任务详情对话流展示确认，右侧“概览”展示产物、计划步骤和 Tool Activity，并可通过文件标签预览支持的文件；
8. 用户关闭并重启应用；
9. 任务状态和最终成果仍可查看；
10. Admin Console 只能看到必要审计元数据，不能查看任务正文或凭证明文。
