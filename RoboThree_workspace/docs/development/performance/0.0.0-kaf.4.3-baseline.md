# RoboThree `0.0.0-kaf.4.3` Performance and Reliability Baseline

> 状态：Developer baseline，等待独立 QA  
> 日期：2026-07-23  
> 机器可读结果：[0.0.0-kaf.4.3-baseline.json](./0.0.0-kaf.4.3-baseline.json)

## 环境与方法

- Apple M3，8 logical CPUs，16 GiB；
- macOS / Darwin 24.4.0；
- Node.js 24.13.0、pnpm 11.11.0、Vitest 4.1.10；
- SQLite 3.50.4，WAL、`busy_timeout=5000`、`synchronous=FULL`；
- 使用临时数据库和 Process Echo，不接触用户数据；
- warmup 与正式 sample 分离，输出 p50/p95/p99；普通单元测试只保留宽松工程护栏。

运行命令：

```bash
CI=true pnpm run performance:kaf43
```

该命令同时向 stdout 输出 `robothree.performance.v1` JSON 和 Markdown 表格。

纯 reducer P95 `<10 ms`、Authorization P95 `<5 ms`、Fake Backend 取消传播 P95 `<100 ms` 均满足冻结目标。Registry resolver 使用按 ID 建立的 Map，不扫描全部能力。

SQLite `create_task` 是包含 Head 与 Checkpoint 的完整 `FULL` durability 事务，结果高于 KAF-4.3 的 500～1,000 events/s 初始量级，但它不是批量 Event 吞吐的等价替代，因此这里只作为保守的事务基线，不把它宣称为商业 Event SLA。没有为了提高数字修改 PRAGMA、事务或故障语义。

## 长期可靠性与有界性

- 16 个 active Run + 256 个 queued Run 到达明确上限；第 257 个排队请求 typed fail-fast；
- 256 个 queued cancellation 全部清理，active/queued/timer 回到 0；
- 8 路 Retry storm 每路精确 3 次 attempt，任一时刻最多 8 个 backoff timer；
- 慢订阅者接收 100,000 个 delta 后 buffer 仍为 64；断开后 subscriber 与 buffer 均归零；
- 10,000 Event 从合法 Checkpoint 重放成功；
- SQLite 连续 20 次 restart/preflight 后 schema、Task、Event 和 Outbox 不漂移；
- Outbox backlog 按 `maxBatch × maxBatches` 明确限制恢复 drain；
- Core stop 先停止新工作、取消并有时限等待 active work，再停止 Outbox 并反向关闭 Adapter；真实 Process Echo ChildProcess 关闭后 health 为 unavailable；
- DurableTaskRuntime in-process snapshot cache 默认最多 256 条，可显式配置并清空。

## 已知限制

- 这是单机 Kernel Alpha 工程基准，不是跨机器或商业 SLA；
- RSS/GC 会受同机负载影响，本轮以长期 retained collection 的显式容量和清理结果作为主要内存护栏；
- Outbox 空 backlog 的 drain latency 与 SQLite 完整事务基准分开记录，不能推导生产消息总线吞吐；
- Desktop WebSocket、Central Event Bus、OpenTelemetry、生产告警和分布式压测不在 KAF-4.3；
- `node:sqlite` 仍输出 ExperimentalWarning。
