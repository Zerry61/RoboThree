## 4. 关键强化验证

### 4.1 首调用执行中取消 → 后续未分发全部收敛 ✅

I2 覆盖了"已分发调用取消成功"但未覆盖"第一个调用正在执行中 + 后续未分发全部取消"。I3 补齐：`effectAttemptId` 保留不更换，后续 ordinals 全部 `cancelled_before_dispatch`，Backend 不得开始后续调用。

### 4.2 Transaction A 后首次 dispatch 前崩溃 ✅

I1 覆盖了 Transaction A 原子性，但未覆盖"A 已提交但第一次 Tool dispatch 尚开始前就崩溃"的恢复路径。I3 补齐：Recovery 从精确 Task/Run/Batch durable intent 取得执行权并按 ordinal 完成。

### 4.3 并发 recovery 单 owner + 幂等 ✅

SQLite close/reopen 后并发 recovery 请求只产生一个新增执行 owner，另一次调用读取已收敛结果。Effect identity 和 Tool Result 均不重复。
