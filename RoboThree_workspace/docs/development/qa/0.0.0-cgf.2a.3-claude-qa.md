### 2. 两个节点独立 PID / 独立端口 / 独立 Hikari Pool / 只共享 PostgreSQL ✅

源码验证（`Cgf2a3DualNodeModelRecoveryIntegrationTest` 行 333-344）：

- 每个节点 `ModelRecoveryNode.start()` 使用 `ProcessBuilder` 启动独立 `java` 进程

### 3. A accept → B status 读取 + durable SSE cursor reconnect ✅

A 节点 accept Invocation → B 节点 HTTP GET status 返回 `accepted`/`running`。B 按 durable cursor 重建 `text/event-stream`（通过 `/model-recovery-harness/events` endpoint），ephemeral delta 不参与重连。

### 4. A 在 running commit 后退出 → B 只在数据库时间 lease 到期后接管 ✅

源码验证（行 85-108）：
- A 节点 `Runtime.halt(82)` 在 `running` 持久化后退出
- `assertThat(nodeA.exitCode()).isEqualTo(82)`
- B 节点读取 status 为 `running`，lease 未过期时拒绝接管（返回 `lease_not_expired`）
- 等待数据库时间 lease 到期后 B 接管，同一 Invocation 恢复为 `completed`
- B 接管后产生正确的 durable event 序列（`dispatch_decided` → `usage_recorded` → `completed`）

### 5. B takeover 后 A 的旧 epoch 迟到提交被 fencing 拒绝 ✅

源码验证（行 109-140）：
- A 节点创建新 Invocation，Backend 设为 BLOCK/UNKNOWN
- A 启动异步执行后，B takeover 并完成（status=`completed`）
- A 释放阻塞 → 迟到提交返回 `succeeded=false`
- `errorCode = "model_gateway.fencing_epoch_conflict"`
- `terminalEventCount = 1`（只有一个终态事件，不重复）

### 6. Cancel / Completion 并发只形成一个可信终态 ✅

源码验证（行 142-174）：
- Node B 的 Provider completion 与 Node A 的 cancel 并发竞争
- 结果 `status ∈ {cancelled, completed}`，只有一个终态
- durable event 序列不包含重复 terminal event

### 7. 两节点相同 request 幂等 + 不同 digest conflict ✅

- 相同 `clientRequestId + requestDigest` → 同一 Invocation ID，200 幂等
- 相同 scope 不同 digest → 409 `model_gateway.client_request_conflict`

### 8. PostgreSQL pause/unpause → 双节点 readiness 恢复无需重启 ✅

- 既有 Invocation 可继续读取
