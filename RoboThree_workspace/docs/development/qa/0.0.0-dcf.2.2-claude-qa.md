## 15 项独立 QA 逐条验证

### 1. clean build + pnpm run check ✅

96/620 + Architecture boundary + ESLint + TypeScript/Preload/Renderer build。

### 2. 五类高层 Command 只经 Main/Preload 白名单进入 Core ✅

cancel/retry/continue/provide input/decide confirmation 均通过固定 IPC channel + `DesktopIpcRouter` + `CorePrivateClient` → Local Core `DesktopTaskControlService`。Renderer 不直连 Core ✅

### 3. commandId + digest 精确重放 + 同 ID 不同内容 conflict ✅

`DesktopTaskControlService` 以 Task revision、commandId 和 canonical digest 处理。重复 → 幂等，冲突 → typed error ✅

### 4. cancel 传播 AbortSignal + 不改写 reducer 取消语义 ✅

cancel 传播到活动 Agent Loop 的 `AbortSignal`。Kernel `task-state-reducer.ts` 的 `cancel_task`/`retry_run` 是 KAF-1 既有语义，DCF-2B 未修改 Kernel ✅

### 5. retry 创建新 Run / attempt 递增 / 旧 Run 不改写 ✅

retry 始终由既有 reducer 创建新 Run（`retry_run` → 新 `runId` + `retryOfRunId`）。旧 Run 不覆盖 ✅

### 6. continue 只恢复 external_dependency / provide input 只恢复 user_input ✅

continue 只允许 `external_dependency`，provide input 只允许 `user_input`。不绕过确认等待 ✅

### 7. 补充输入 durable + 重放不重复写消息 ✅

补充输入先通过 Conversation prepared-message/commit 事务持久化。相同命令重放不重复写入消息 ✅

### 8. Confirmation 精确绑定 Task/Run/Step/Action + requestDigest ✅

绑定 `confirmationId` + 完整 `requestDigest` + Task/Run/Step/Action 五层。`DesktopTaskControlService` 行 89/228-240 验证 ✅

### 9. 重复/冲突/迟到/过期/错 Task/错 revision → typed rejection ✅

全部返回 typed error，不静默通过 ✅

### 10. rejected/expired 不产生 Effect 或外部副作用 ✅

拒绝或过期不产生外部副作用。allow 后分发前仍需通过实时再校验 ✅

### 11. allow 后分发前 disabled/revoked/health/credential/permission 再检查 ✅

allow 之后、调用 `UserConfirmationCoordinator` 之前执行实时再校验。任一收窄 → 失败关闭 ✅
