## 7. 问题清单

### ISSUE-P3-001

| 字段 | 值 |
| --- | --- |
| 标题 | SQLite 集成测试在 vitest 并发 worker pool 下偶发 `enableDefensive is not a function` |
| 严重等级 | P3 |
| 所属模块 | `services/core` — SqliteTaskPersistence / SQLite 集成测试 |
| 发现方式 | 第 1 次全量 `pnpm run check`（13 文件并行）时出现；第 2 次全量运行和独立运行均通过 |
| 风险影响 | `node:sqlite` 实验性 API `DatabaseSync.enableDefensive()` 在 vitest forks pool 多 worker 并发打开/关闭文件数据库时，偶发方法不可用。不影响生产路径（生产不使用 vitest workers）；仅影响 CI/QA 稳定性 |

**前置条件**：vitest 默认 `pool: forks` + `fileParallelism: true`；多个 SQLite 测试文件并发运行

**复现步骤**：
1. `pnpm run check`（运行全部 13 个测试文件）
2. 观察 `sqlite-persistence.integration.test.ts` 中需要 close/reopen 的用例

**预期结果**：所有测试通过

**实际结果**：第 1 次运行时 2/4 集成测试失败（`enableDefensive is not a function`）；第 2 次运行时 4/4 通过。独立运行始终通过。

**复现频率**：偶发（1/2 次全量运行出现）

**证据**：
- 第 1 次运行失败日志：`TypeError: database.enableDefensive is not a function` at `sqlite-task-persistence.ts:65`
- 第 2 次运行（独立文件 + 2 次全量 re-run）：全部通过

**建议处理方向**：
- 短期：在 `sqlite-task-persistence.ts` 中对 `enableDefensive` 做 feature detection（`typeof database.enableDefensive === 'function' ? database.enableDefensive(true) : undefined`），降级为跳过而非崩溃
- 中期：跟踪 Node.js `node:sqlite` 去实验性标记进度（预计 Node 25+），并在 CI 中固定 vitest `pool: 'forks'` 配置
- 长期：KAF-4 压测阶段重新评估 SQLite 适配器的线程安全策略

**是否阻断发布**：否
