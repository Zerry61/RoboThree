## 3. repair.1 P1 修复（encoded route）复核

### 3.1 根因

`%2e%2e`/`%2f` 形式的 URL 编码能够在 `relativePath` 校验（`contains("..")` / `startsWith("/")`）中保持未解码形态，通过校验后由 `URI.resolve()` 解码归一化，造成路径穿越进入网络 Transport。

### 3.2 修复

[JdkModelAuthorizedHttpTransport.java:110-111](services/central-service/src/main/java/com/robothree/central/modelgateway/adapter/http/JdkModelAuthorizedHttpTransport.java#L110-L111)：

```java
|| relativePath.indexOf('%') >= 0
|| relativePath.indexOf('\\') >= 0
```

`%` 拒绝任何百分号编码，`\` 拒绝反斜杠（Windows 路径分隔符）。两个字符均在 `relativePath` 被 URI resolve 之前拦截，返回 `model_gateway.provider_route_invalid` typed error，不进入网络层。

### 3.3 修复边界

- 未新增 URL 解析策略、Header 或公共错误类型
- 未放宽 Endpoint Policy 的 host allowlist / DNS / restricted-address 校验
- 修复只作用于 Transport 层，属于最小防御

### 3.4 验证

Closure harness security scenarios (10/10) 覆盖了 encoded route、redirect、Binding/Credential drift、Header 安全等全矩阵，全部通过且 zero network call to unintended targets。
