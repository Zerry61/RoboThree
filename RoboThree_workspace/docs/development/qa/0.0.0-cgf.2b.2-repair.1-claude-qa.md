## 4. 真实 Provider Harness ⚠️ → **P1**

### 4.1 执行过程

用户提供短期限额 OpenAI-compatible Key（DeepSeek）。

首次尝试：Maven forked JVM 继承系统代理属性 `socksProxyHost=127.0.0.1:7897`，Harness 的 `HttpClient` 默认走代理 → `provider_runtime_failure`。

独立诊断程序证实：JVM with 代理 → Status 200/675ms（代理正常），但 Maven Surefire 子进程中的网络行为不同。

在清除 Maven proxy system properties 后重跑，抓到真实异常栈：

```
java.lang.IllegalArgumentException: text must not be blank
    at DomainValueChecks.text(DomainValueChecks.java:17)
    at ModelProviderStreamEvent$TextDelta.<init>(ModelProviderStreamEvent.java:14)
    at OpenAiCompatibleModelProviderAdapter$StreamState.accept(OpenAiCompatibleModelProviderAdapter.java:152)
```

### 4.2 根因

DeepSeek（OpenAI-compatible）返回的第一个 SSE chunk 是角色声明帧：

```json
{"choices":[{"index":0,"delta":{"role":"assistant","content":""},"finish_reason":null}]}
```

其中 `content: ""` 是**空字符串**（非 null）。OpenAI-compatible adapter 的 `accept()` 方法直接将 `delta.path("content").asText(null)` 的结果（`""`）传入 `ModelProviderStreamEvent.TextDelta`，而 `TextDelta` 构造函数调用 `DomainValueChecks.text()` 拒绝 blank 值，throw `IllegalArgumentException`（RuntimeException）。

`DiagnosticAdapter` 捕获此 RuntimeException，设 `safeErrorCode = "model_gateway.provider_runtime_failure"`，Backend 返回 `UNCERTAIN`。

### 4.3 影响面

**所有 OpenAI-compatible 协议的 Provider 都受此影响**（DeepSeek、自定义 OpenAI 中转等均用同一 adapter）。Anthropic-compatible adapter 不受影响（已正确处理 `thinking_delta`/`signature_delta` 的非文本 delta 类型）。

修复方向：在 [OpenAiCompatibleModelProviderAdapter.java:150](services/central-service/src/main/java/com/robothree/central/modelgateway/adapter/provider/OpenAiCompatibleModelProviderAdapter.java#L150) 旁增加 null/blank 跳过逻辑，仅当 `text != null && !text.isBlank()` 时创建 TextDelta。

```java
// 当前（Line 150-152）
String text = delta.path("content").asText(null);
// ...
sink.accept(new ModelProviderStreamEvent.TextDelta(text));

// 修复方向
String text = delta.path("content").asText(null);
if (text != null && !text.isBlank()) {
    sink.accept(new ModelProviderStreamEvent.TextDelta(text));
}
```

### 4.4 分级

**P1** — 阻塞全部 OpenAI-compatible 协议的真实 Provider Streaming Conformance。`withStubProvider` mock 测试不受影响（Stub 不含空 content chunk），完整门禁 181/0/0/0 通过。

非法凭证/取消/Deadline 场因正常 Streaming 失败而无法在本次 QA 中验证（测试在第一个场景 `normal_streaming` 就已 fail），但代码路径审查已确认映射逻辑正确。
