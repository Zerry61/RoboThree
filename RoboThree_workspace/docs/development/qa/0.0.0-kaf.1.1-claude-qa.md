## 5. DEVELOPMENT-LOG 13 项"独立 QA 建议范围"覆盖表

### #1 — ADR-005 的 10 条关键不变量是否都被 Schema、Reducer 或测试落实

| 不变量（§4） | Schema | Reducer | 测试 |
| --- | --- | --- | --- |
| Task created 不能有 run | `TaskRunStateSchema.superRefine:121-122` | `startRun` `requireCondition(status==="created")` | runtime-contracts "rejects structurally inconsistent waiting state" |
| active task ↔ activeRunId 必一致 | `TaskRunStateSchema.superRefine:132-133` | 所有 transition 中维持 | — 隐式覆盖 |
| run attempt 连续且有序 | `TaskRunStateSchema.superRefine:141-142` | `retryRun` `attempt = prev+1` | task-runtime "retry attempt=2, retryOfRunId=run1" |
| 只有一个 active step per run | `TaskRunStateSchema.superRefine:146-155` | `startStep` `requireCondition(!activeStepId)` | task-runtime "serializes concurrent commands so only one active Step" |
| waiting run 必须有 activeStepId | `TaskRunStateSchema.superRefine:150-151` | `waitStep` 设置 wait 后状态为 waiting | task-runtime "models interrupt and resume as explicit waiting" |
| terminal run 不能有 activeStepId | `TaskRunStateSchema.superRefine:147-148` | complete/fail/cancel 后 activeStepId 清除 | — 同一测试 |
| Retry 始终创建新 Run、旧 Run 不变 | — | `retryRun` `runs: [...runs, newRun]` | task-runtime "runs[0] = oldRun, runs[1] = new with attempt=2" |
| 迟到 Observation 拒绝且不污染 | — | `recordObservation` 检查 `runId===activeRunId` + `stepId===activeStepId` | task-runtime "rejects observations from the old Run" |
| Cancellation created Task 不创建 Run | — | `cancelTask` branch：`status==="created"` 时直接 `{status:"cancelled", runs:[]}` | task-runtime "can cancel a created Task without inventing a Run" |
| Deadline 取最早值、相等到期 | — | `activeDeadline` 取 min(task/runs[-1]/steps[-1].deadlineAt) + `compareTimestamps(issuedAt, deadline) >= 0` | task-runtime "uses the earliest effective deadline and expires on equality" + "times out created Task instead of starting" |

**结论**：✅ 10 条不变量全部落地。Schema 负责结构不变量，Reducer 负责转换不变量，Tests 覆盖所有关键场景。
