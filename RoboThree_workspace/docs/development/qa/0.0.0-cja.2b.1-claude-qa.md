### 2. Production Dependency Manifest 每项恰好一个 Bean 检查 ✅

`ProductionDependencyManifest v1` 白名单登记 23 个必需 Bean。`ProductionDependencyValidator` 使用 `ApplicationContext.getBean(type)` 对每项执行精确一次查找——多于一（歧义）或零（缺失）均 typed startup failure。`ProductionDependencyValidatorTest` 验证缺失/歧义/Fake 三类拒绝。

### 3. 缺失 / 歧义 / Fake/InMemory/Development Bean 全部失败关闭 ✅

`ProductionDependencyValidatorTest` + `CentralProductionBootstrapConfigurationTest` 覆盖：
- Manifest 中声明但 Context 中不存在的 Bean → typed startup failure
- Fake/InMemory/Development Bean 代替生产实现 → 拒绝
- 一个 type 有多个候选 Bean → 拒绝（歧义）

黑名单扫描（Fake/InMemory/Development Bean 检测）作为第二道守卫保留，但不替代白名单。

### 4. Fixture Controller 在 production Profile 不存在 ✅

`FoundationFixtureController` 声明 `@Profile({"default", "development"})`，不含 `"production"`。`CentralAlignment2b1ArchitectureTest` 自动化验证：production Bean Graph 中 FoundationFixtureController 为零。

### 5. Startup Validator 在 Context ready 前执行且不用 Fake fallback ✅

`CentralProductionBootstrapConfiguration` 实现 `SmartInitializingSingleton`，在 Context refresh 完成、对外 ready 之前运行 `ProductionDependencyValidator` + `CentralProductionReadinessVerifier`。`CentralProductionBootstrapConfigurationTest` 验证：缺依赖时 Context refresh 失败，不会进入 ready。未使用通用 `BeanPostProcessor` 承担业务启动正确性。

### 6. 空业务库可 Ready ✅

`CentralProductionReadinessVerifierTest` 验证：全新空库（无用户、设备、权限、配置数据）可以 Ready。Readiness 不要求业务数据行——`SELECT 1` 探针 + Schema ledger/version/digest/manifest/preflight + 表零结果只读探针即可。符合方案约定：合法空库不应被判 unhealthy。
