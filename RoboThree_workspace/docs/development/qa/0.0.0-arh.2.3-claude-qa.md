## 三、发现

### P2-1：W6 并发收敛测试偶发超时（flaky test）

**现象**：`arh2.3-process-recovery.test.ts` 的 "W6 lets two fresh recovery owners converge on one active Record" 在 `Promise.all([run("recover"), run("recover")])` 场景下偶发 "Timed out running recover"（~10.1s）。

**根因**：测试 helper `run()`（L166）使用固定 10 秒超时。两个 owner 并发恢复同一 SQLite 文件时，单写锁竞争导致第二个子进程偶尔等待超过 10 秒才返回 `result` 消息。

**证据**：
- 独立复跑 3 次：pass / fail(10170ms) / pass —— 确认偶发
- harness JSON 证据显示 W6 `recoveryClass: stale_reload`、一个 active Record、contextRevision=1 —— **生产逻辑正确**
- 失败是子进程握手超时，非断言失败

**影响**：使 `pnpm run check` 回归门禁偶发红。生产逻辑无缺陷。

**建议**：将 `run()`/`crashAt()` helper 的超时从 10s 提升到 30s（与 vitest `--testTimeout=30000` 对齐），或为 W6 并发场景单独设置更长超时。属于测试基础设施修复，不涉及生产代码。
