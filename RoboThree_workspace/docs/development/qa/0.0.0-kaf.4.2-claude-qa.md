## 3. 重点验证项（Codex 高亮五项）

### 3.1 Admission 真实有界性与释放

- 默认 16 Run / 8 Tool / 256 queue ✅ (`admission-controller.test.ts`)
- queue full → typed `RuntimeError`，非 drop/无限等待 ✅
- cancelled/expired queued work 立即移除，不占 slot ✅
- success/failure/cancel/timeout/throw 均 `finally` 释放 ✅
- Adapter `maxConcurrency` (1~1024) 生效，按锁定 revision ✅

### 3.2 KAF-4.1 Gate 不可绕过

- Tool admission 严格在 Authorization audit 成功后、Effect `prepared` 前取得 ✅ (`tool-execution.integration.test.ts`: "applies Tool backpressure after Authorization but before Effect PREPARED")
- queue full/expired/cancelled Tool → Backend 0, Effect 0 ✅
- Confirmation Gate 在并发/取消路径下不被绕过 ✅ (`user-confirmation.integration.test.ts` 15 tests)

### 3.3 Process Echo 无双重排队

- `maxConcurrency: 1`，单飞行 ✅
- admission bypass → `process_echo.concurrent_execution` fail-closed ✅ (`process-echo-tool.integration.test.ts`: "rejects direct concurrent calls instead of building an unbounded Adapter queue")
- 删除内部 Promise tail ✅

### 3.4 Retry 对未知副作用不盲重发

- rate-limit/5xx/network/stream → retryable；auth/user_rejected/deadline/config/uncertain → 不重试 ✅ (`retry-policy.test.ts`)
- `RetryCoordinator` 公开 safety：只允许 pre-Effect、幂等 non-Effect、Outbox publish ✅
- 边界检查禁止 RetryCoordinator 依赖 EffectCoordinator/EffectExecutor/ToolExecutionBackend ✅
- dispatched Effect 三种 ADR-007 recovery mode 不回归 ✅

### 3.5 Outbox backoff 跨 SQLite 重启

- `maxBatch` 限制 + due-only selection ✅ (`durable-task-runtime.test.ts`: "caps every Outbox drain to the configured batch size")
- failed attempt → 持久 `nextAttemptAt`，未到期不选 ✅
- publish→ack 失败 → 稳定 ID at-least-once 重发 ✅
- SQLite migration 4 + close/reopen ✅ (`sqlite-persistence.integration.test.ts` 5 tests)
