## 15 项独立 QA 逐条验证

### 1. Node 66/458 ✅ 2. Central 53/0/0 x2 + Docker/PgEmbedded ✅ 3. E2E 实际执行 ✅

三门禁 + E2E 全部独立重跑，无失败、无跳过。E2E 验证了 Java test-profile Token 链、随机 loopback、Node 正式 Adapter 和 SQLite reopen 全部实际执行。

### 4. HTTP Client：HTTPS / test-loopback / 拒绝 URL credential / redirect: manual / 跨 Origin

`HttpEnterpriseConfigurationClient`（`http-enterprise-configuration-client.ts`）：
- `validateOrigin()`：默认拒绝 HTTP，仅 `allowInsecureLoopbackForTest=true` 时放行 loopback ✅
- Bearer Token 仅在 `Authorization` header（`fetchBounded` 函数内），不进入 URL、query string、hash ✅
- `redirect: "manual"` — 不自动跟随重定向 ✅
- Origin 固定为构造时传入的 `baseUrl`，跨 Origin 请求不可构造 ✅

### 5. Bearer 不进入 URL/日志/错误/Fixture/SQLite/输出

- `fetchBounded` 将 `lease.compactToken` 仅放入 `Authorization: Bearer <token>` header ✅
- E2E 测试显式验证 `output.doesNotContain(accessToken)` ✅
- HTTP Client 错误消息只包含 typed code（`configuration.client_unauthorized` 等），不包含 Token ✅
- SQLite schema 无 Token 列 ✅

### 6. Content-Length + 流式字节双上限 / fatal UTF-8 / media type / malformed/截断 body / timeout / cancel

`fetchBounded`：
- `Content-Length` 预检：若 > maxBytes，提前拒绝 ✅
- 流式读取时累积字节，超过 maxBytes 即
  `configuration.client_response_too_large` ✅
- 响应体非 UTF-8 → `configuration.client_protocol_invalid` ✅
- `Content-Type` 非 `application/json` →
  `configuration.client_protocol_invalid` ✅
- `AbortController` + `signal` 支持外部取消 ✅
- `setTimeout` 触发内部 `AbortController.abort()` 完成超时控制 ✅

### 7. 一次配置操作最多续签一次 / scope+audience+permission 不漂移 / seal 前重新检查

`HttpEnterpriseConfigurationReadOperation.#request()`（行 135-174）：
- `lease = await this.#tokenSession.acquire()` → 初次获取
- `token_expired` 时 `renewed=false` → 续签一次 → `renewed=true`
- 第二次 `token_expired` → `configuration.client_unauthorized` ✅
- `EnterpriseConfigurationTokenSession` 在 `#acceptLease()` 中验证 scope/audience/permission 不漂移 ✅
- `assertReadyToSeal()` → `provider.assertCurrentSession(scope, permission)` ✅

### 8. Snapshot 304：三个分支（complete / no-local / corrupt）+ unconditional repair

- 本地 active 完整且 `materializationDigest` 一致 → 304 no-op ✅
- 本地 active 缺失 → 无条件完整重取 ✅
- 本地 active 存在但校验失败（corrupt）→ 无条件完整重取 ✅
- 第二次仍为 304 且本地不完整 →
  `configuration.client_protocol_invalid` 失败关闭 ✅

### 9. Package 304：只复用可验证的 exact Package

- Package 304 只在本地 active Package 可重新验证时复用 ✅
- revision/digest/kind/file digest 漂移 → 全部失败关闭，不回退到 latest ✅

### 10. 部分 stage 失败 → 复用已验证 candidate / sealed 前/后崩溃 / active commit 响应丢失

- 下载中断后重建：已验证的 Snapshot/Package 从 candidate 复用，损坏的未密封 candidate 被丢弃重建 ✅
- sealed 前崩溃：candidate 未密封，下次同步 discard 后重建 ✅
- sealed 后 / activate 前崩溃：candidate 已密封，重新 activate（CAS 匹配 → replay） ✅
- active commit 后响应丢失：activation fact 保留，重试 replay，只能恢复为完整旧 active 或完整新 active ✅

### 11. Central 切换 active 时客户端使用 exact locked reference

- 客户端在 Snapshot 下载时锁定 `snapshotId/snapshotRevision/snapshotDigest`
- Package 下载使用 locked Snapshot facts，不动态查询 Central 当前 active ✅
- Central 在 Snapshot 和 Package 下载间切换 active → 客户端仍按 exact reference 请求 ✅
