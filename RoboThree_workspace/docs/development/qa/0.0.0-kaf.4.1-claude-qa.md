## C. 阻塞问题

### ISSUE-KAF41-001：Authorization 审计既不完整，也不能保证持久

| 字段 | 值 |
| --- | --- |
| 严重等级 | **P1** |
| 模块 | Contracts / ToolExecutionService / TaskPersistence |
| 发现方式 | 架构对照、源码审查、现有成功路径测试、最小故障注入复现 |
| 是否阻断 | 是 |

**架构要求**

- `docs/adr/006-permission-policy-data-approval.md:227-233` 明确要求允许、拒绝、确认请求、确认结果和分发前失效全部形成可关联 Event。
- 同文件 `:285` 要求审计记录配置 revision。
- `docs/architecture/KAF-4-DEVELOPMENT-PLAN.md:188-200` 把 Authorization Event 作为 KAF-4.1 交付，`:228-240` 要求退出门槛全部满足。

**实际**

1. `packages/contracts/src/persistence/task-event.ts:8-20` 没有 `authorization.allowed` Event 类型。
2. `services/core/src/application/tool-execution-service.ts:127-161` 的 allowed 路径直接进入 Effect，未提交 allowed Event。
3. 现有成功路径测试 `services/core/tests/tool-execution.integration.test.ts:64-72` 明确断言 Event 序列只有 Runtime/Effect Event，没有 allowed Event。
4. 拒绝路径 `tool-execution-service.ts:299-331` 调用 `commitAuthorizationAudit()` 后不检查返回结果；而两个 Persistence Adapter 都会在 event sequence 竞争时返回失败，例如 `in-memory-task-persistence.ts:281-301`。
5. 拒绝 Event payload 只有 decision；没有 `activeConfigRevision`、用户稳定引用、Lock/Binding/Descriptor revision 或授权输入 digest。`activeConfigRevision` 只存在于 `authorization-context.ts:46-60`。

**最小复现**

```bash
node qa-reports/2026-07-23-1043-version-0.0.0-kaf.4.1/evidence/repro/authorization-audit-commit-failure.mjs
```

复现稳定得到：

- Persistence 返回 `persistence.sequence_conflict`；
- `ToolExecutionService` 仍返回普通 `status: denied`；
- 调用方无法知道强制审计没有落盘，也没有重试。

**影响**

- 授权成功路径天然缺审计 Event。
- 授权拒绝在同 Task Event 竞争或持久化故障时可静默丢失。
- 即使 Event 落盘，也无法用配置 revision 复现当时的授权上下文。
- Effect Gate 本身仍保持 fail-closed，因此当前未发现未授权副作用；但强制审计与恢复证据不成立，违反已接受 ADR，属于发布阻塞。

**推荐修改**

- 增加版本化 `authorization.allowed` Event。
- 将 Authorization audit 纳入 Task mailbox/同一持久事务，或把审计失败显式返回并执行有界重试；禁止忽略 `PersistenceWriteResult`。
- Event 仅加入稳定 user/config/lock/capability/binding/descriptor revision 与规范化输入 digest，不复制敏感内容。
- 新增 allowed、denied、sequence conflict、audit failure、Outbox 原子性测试。

### ISSUE-KAF41-002：调用方可把敏感文本放入 Confirmation Event/Outbox

| 字段 | 值 |
| --- | --- |
| 严重等级 | **P1** |
| 模块 | Authorization Contract / ToolExecutionService / DurableTaskRuntime |
| 发现方式 | Contract 审查、数据流审查、最小复现 |
| 是否阻断 | 是 |

**架构要求**

- `ADR-006:229-233` 只允许稳定 ID、revision、digest、规范化引用和安全的用户摘要；禁止保存 Token/Credential、文件正文、完整 Prompt、大块外发内容和未经验证的目标展示字符串。

**实际**

1. `services/core/src/application/tool-execution-service.ts:32-36` 暴露 caller-controlled `displaySummary`。
2. `packages/contracts/src/authorization/user-confirmation.ts:9-19` 只校验其为 1～2000 字符字符串。
3. `tool-execution-service.ts:273-284` 原样写入 `UserConfirmationRequest`。
4. `services/core/src/application/durable-task-runtime.ts:301-326` 把完整 request 原样复制到版本化 Event；Outbox 又携带该 Event。

**最小复现**

```bash
node qa-reports/2026-07-23-1043-version-0.0.0-kaf.4.1/evidence/repro/confirmation-summary-secret-like-content.mjs
```

使用纯 QA 假值 `token=qa-only-fake-secret`，Schema 稳定接受。未使用任何真实密钥。

**影响**

- 未来 Agent、Tool 调用装配层或 UI 若把 Prompt、正文、目标原文或 Token 拼入摘要，会持久进入 confirmation 表、Event 和 Outbox。
- 现有测试只验证禁止新增 `token/prompt/pid/runtimeHandle` 字段，没有验证敏感值藏在合法字符串字段中。

**推荐修改**

- 不接受任意 caller summary；由受信 Core 使用结构化、白名单字段生成展示摘要。
- 持久层保存稳定引用/digest 和经过明确脱敏的短摘要；Event/Outbox 再做一次安全边界校验。
- 新增 Token/Prompt/正文/长目标字符串的数据流测试，验证 confirmation 表、Event 与 Outbox 均不含原文。

### ISSUE-KAF41-003：冻结退出门槛要求的自动化矩阵未完整实现

| 字段 | 值 |
| --- | --- |
| 严重等级 | **P2** |
| 模块 | KAF-4.1 测试基线 |
| 发现方式 | 计划与测试逐项映射 |
| 是否阻断 | 否（但需在 P1 修复复验一并补齐） |

`KAF-4-DEVELOPMENT-PLAN.md:228-240` 要求 ADR-006 15 项全部自动化，并明确确认/拒绝/重复/并发决定幂等、漂移、SQLite 恢复等退出门槛。当前 4 个定向文件共 21 项测试，但以下矩阵未被自动化覆盖：

- `bulk_overwrite`、`protected_resource`、`local_execution` 的 exact Action confirmation；
- external Task scope 的已确认复用，以及 target/data scope/三类 revision 漂移拒绝；
- confirmation scope/ID 冲突、同决定重放、相反决定和真正并发决定；
- SQLite close/reopen 后 confirmed scope 的复用与 rejected exact Action 的防重复提示；
- allowed/denied/confirmation/invalidated Event 的关联字段、敏感内容和 Outbox 原子性；
- prepared 前漂移与 audit sequence conflict。

实现中可看到部分失败关闭逻辑，但冻结计划要求的是自动化退出门槛，不能用静态阅读代替持续回归保护。
