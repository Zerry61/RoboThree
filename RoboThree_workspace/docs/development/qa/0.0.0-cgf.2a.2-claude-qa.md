### 2. Access Token `model.use` / synthetic admission / accept 幂等/冲突 / 重放 ✅

`RoboThreeModelInvocationAccessAuthorizer` 验证 `model.use` permission。synthetic admission 是唯一允许的 admit 类型（user-confirmed 属于 CGF-2C）。Accept 幂等：相同 clientRequestId + requestDigest → 200；不同 digest → 409 `model_invocation_conflict`。响应丢失后重放收敛为幂等成功。

### 3. accepted→running→terminal 同事务 + Provider 只在 running commit 后调用 ✅

`ModelInvocationRuntime.execute()` 执行链：`accepted` persists Invocation + Event + Outbox → `dispatch_decided` + `running` persists → `backend.execute()` 调用 Fake Provider → terminal commit。Provider 调用（行 210）发生在 running 持久化提交之后。如果 running commit 后 Provider 调用前崩溃，recovery 不会重复 dispatch。

### 4. v0007 字节/manifest 不变 + dispatch_decision 精确 64 字符摘要 ✅

- v0007 B0007 MD5：`9b8cf002cc275253611a01e2abb9fc74`（与 CGF-2A.1 冻结一致）
- Manifest + sidecar：未修改
- `ModelDispatchDecision`：`^[a-f0-9]{64}$` regex 验证 + `CanonicalJson.sha256(length:bindingRevision|length:bindingDigest|)` 计算，同时锁定 Binding revision 与 digest，不含 URL/Credential

### 5. disabled/revoked/health/credential 收窄 + 旧 Binding 恢复 + 禁止 silent failover ✅

`DevelopmentModelBindingStateProvider` 实时状态（disabled、revoked、health、credential 变化）只能收窄可执行性。旧 Binding revision 使用不可变保留语义。`ModelInvocationRuntime` 恢复时按 dispatch_decision 中的 binding revision + digest 精确解析历史 Binding，禁止静默切换到新 Binding。

### 6. 三种 Recovery Mode + 数据库时间 lease + renew/takeover + stale fencing ✅

源码验证三类恢复（`ModelInvocationRuntime` L207-216）：
- `idempotent_retry`：复用同一 logical invocation，幂等重放
- `query_then_retry`：依据 terminal/not-found/unknown evidence 决策
- `manual_reconciliation`：显式进入 uncertain

Lease 使用数据库 `CURRENT_TIMESTAMP`、`SELECT ... FOR UPDATE`、fencing epoch CAS。`renewLease()` 验证 fencing epoch 匹配，stale epoch 拒绝。旧 owner 迟到提交被 fencing epoch 检查拒绝。

`running` 未知恢复不伪造成 `failed`——Provider 无法查询时收敛为 `uncertain`。

### 7. cancel / timeout / late terminal 竞争 ✅

- `accepted` 前取消：不创建 Invocation
- `dispatch` 前 deadline 超时：`timed_out`
- `running` cancel intent：乐观取消，Provider 已完成则竞争收敛为 completed
- late terminal（Provider 在 cancel 后返回结果）：`completed` vs `cancelled` 竞争，只形成一个可信终态

### 8. Ephemeral delta 不进入 DB / Event / Outbox ✅

`ModelInvocationEphemeralBuffer` 是纯内存有界缓冲，不在 PostgreSQL 持久化。Runtime 重建后 ephemeral 为空，恢复只依赖 Durable Event。Ephemeral delta（text/tool-call）不写入 `model_invocation_event`、`model_invocation` 或 `model_invocation_audit_outbox`。
