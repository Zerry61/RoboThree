## 15 项独立 QA 逐条验证

### 1. selectionHandle 不入 SQLite / Receipt 明文 / 长期持久事实 ✅

- `grep -rn "selectionHandle" services/core/src/adapters/sqlite` → **0 命中** ✅
- `selectionHandle` 仅在 Application/Port 类型定义中作为 Renderer→Main 的 opaque 引用传递，不入持久层 ✅
- SQLite schema（migration 7）无 `selection_handle` 列 ✅

### 2. realpath / 路径分段 / .. / NFC / symlink / dangling symlink 越界失败关闭 ✅

`NodeWorkspacePathResolver`：
- `realpath` 对授权根执行目录校验 ✅
- 分段相对路径，拒绝 `..` 越界 ✅
- NFC 标准化 ✅
- NUL 字符拒绝 ✅
- symlink 越界（目标在授权根外）→ 失败关闭 ✅

### 3. read-only WorkspaceGrant 不允许写操作 ✅

`WorkspaceGrantService`：read-only grant 调用写操作（create/rename/delete）时返回 `"workspace grant is read-only"` typed error ✅

### 4. SessionHead 继续属于现有 Conversation，不建立第二套对话系统 ✅

`DesktopSessionService` 复用 KAF-5 `ConversationPersistence` 和 `SessionHead`。Desktop title/revision/tombstone 作为独立 Session 元数据存储于 `desktop_session_metadata` 表，不创建独立对话系统 ✅

### 5. title/revision/tombstone 与 Compaction Contract 分离 ✅

Session 元数据（title、revision、tombstone）独立存储于 `desktop_session_metadata` 表。rename/delete 使用 `expected revision` CAS。Compaction 不感知 Desktop Session 元数据 ✅

### 6. SessionCreateIntent 在 SessionHead 前锁定 command digest ✅

`desktop_session_create_intents` 表：在创建 SessionHead 之前，先写入 intent（含 commandId、canonical command digest、内外部 Session ID、preparedAt）。同一 commandId 不同 digest → `desktop.session_intent_conflict` ✅

### 7. SessionHead 提交后崩溃，时钟变化后仍能恢复 ✅

`SessionCreateIntent` 的 `preparedAt` 和 `command digest` 在崩溃后允许确定性重放。时钟变化不影响 intent 的幂等判断（以 digest 为准，不以时间为准） ✅

### 8. 相同 commandId、不同 digest → typed conflict ✅

InMemory 和 SQLite `insertSessionCreateIntent`：已存在 intent 但 digest 不匹配 → `desktop.session_intent_conflict` ✅

### 9. create/rename/tombstone 与 Workspace create/revoke 提交后响应丢失均可恢复 ✅

- `desktop_command_receipts` 表记录每个 command 的 receipt
- 提交后响应丢失 → 客户端重新发送同一 command → receipt replay（返回原持久结果） ✅
- WorkspaceGrant 创建/撤销同理由可恢复 ✅

### 10. delete 只写 tombstone，不删除 SessionHead ✅

`desktop_session_metadata.tombstoned` 列：delete 操作设置 `tombstoned = true` + 递增 `revision`。UPDATE 语句带 `WHERE tombstoned = 0 AND revision = ?`，不 DELETE 行 ✅

### 11. InMemory/SQLite 运行相同 Conformance ✅

`desktop-foundation-persistence.conformance.test.ts`：两套 variant（InMemory + SQLite）运行同一测试矩阵。覆盖 SessionHead 后崩溃、metadata 提交后响应丢失、Workspace create/revoke 恢复、同 digest 回放、不同 digest conflict、tombstone 语义、symlink 逃逸、Conversation 顺序投影 ✅

### 12. migration 7 / preflight / close/reopen / 旧 migration 前向升级 ✅

- Migration 7 新增 4 表：`desktop_workspace_grants`、`desktop_session_metadata`、`desktop_session_create_intents`、`desktop_command_receipts` + 3 索引 ✅
- Schema preflight 校验列、索引、migration history、integrity、foreign key ✅
- `sqlite-conversation-persistence.integration.test.ts` 验证 close/reopen 和旧 migration 升级 ✅

### 13. Conversation Projection 保持消息顺序，不自行生成 durable cursor ✅

`DesktopConversationProjectionService`：从 Conversation 持久事实投影 `MessageProjection`/`ConversationSnapshot`。`latestDurableCursor` 由调用方提供，DCF-1.1A 不伪造 ✅
