## 2. 关键实现

### 2.1 单一 Planner 与可信交集

- `AgentResourceDecisionPlanner.plan()` 是同步纯函数；输入均为已锁定 Agent、exact Entitlement、accepted
  selection、exact preference、Registry、Workspace/Authorization facts 与 Tool policy candidates；
- Model 严格执行 explicit → exact preference → entitlement stable ordinal 的真值表；explicit 不合法时 typed
  reject，不 fallback；
- Model eligibility 只取 Entitlement、Agent restriction、Registry exact revision/availability、required
  capabilities、Workspace/Authorization 五者交集；Tool candidate 非空时额外要求 Tool Calling；
- Skill/Knowledge 只处理 accepted exact refs，不因 unrestricted 自动全选；Knowledge Provider 未 ready 且选择
  非空时 typed fail-closed；
- Tool 只消费 `TaskToolCandidatePolicy` 产生的 exact candidates，再与 Agent/Entitlement/Registry/Authorization
  求交；Prompt、Agent 文本、模型输出均不能新增 Tool；
- entitlement digest、Registry exact drift、candidate Registry drift、重复 facts 全部 fail-closed。

### 2.2 code-owned `agent.general`

- `BuiltInGeneralAgentSource` 逐字段构造冻结 material，不使用 spread、env、DB、Renderer 或 fixture；
- stable ID=`agent.general`，schema=`v1alpha2`，management=`system_builtin`；
- 中文 name/identity/goal/instructions 与产品 authority 字节一致；LF、无尾随换行；
- 四类 restriction 全为 unrestricted、无 default Model、不绑定 scripted provider；
- exact revision/digest 为 `sha256:f846f63e…0078cc`，模块初始化与测试均独立重算验证；
- Source 只按 stable ID + exact revision 加载，未知 revision 不 fallback。

### 2.3 fixture 与兼容边界

- 新 scripted fixture 使用 `agent.fixture.desktop-scripted`，继续绑定 deterministic scripted Model；
- fixture factory 位于 fake adapter source，未从 Core root export；Built-in 与 fixture 不共享 source/factory；
- 当前 legacy v1 Desktop composition 为保持既有 Task/Renderer 回归，仍 active 注册历史
  `agent.general` exact revision；新的 fixture revision 以独立 ID 非 active 注册；
- 这不是 production R2D cutover。R2D-3.3 才负责 v1alpha4 首次接受与新 Task 切换，禁止本批提前接线。
