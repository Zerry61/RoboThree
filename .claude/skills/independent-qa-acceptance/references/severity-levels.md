# Severity Levels

问题分级是发布决定的唯一依据。每一条问题都必须落到唯一一级，避免"看着像 P1 又像 P2"的模糊分级。复测通过后可下调或关闭。

## 通用判定原则

1. **影响面 × 触发概率 × 后果严重度** 三者综合定级，而不是只看现象吓人程度。
2. **可绕过 ≠ 不严重**：高权限操作绕过难度低的仍按后果定级。
3. **数据破坏与安全漏洞优先**：哪怕只在特定输入触发，仍按 P0 处理。
4. **复现不到 ≠ 不存在**：标"未复现 / 待复现"，但仍按潜在级别记录。
5. **重复出现 ≥ 3 次**：自动上调一级。

---

## P0 — 阻断级（Blocker）

**结论：禁止发布，必须修复后才能进入下一轮验收。**

定义：以下任一情况成立即视为 P0。

| 维度 | 触发条件 |
| --- | --- |
| 数据 | 出现数据破坏、覆盖生产数据、不可逆删除、跨租户/跨用户数据可见 |
| 安全 | 严重安全漏洞：任意命令执行、任意文件读写、沙箱逃逸、API Key / Token 明文泄露到客户端或日志 |
| 可用性 | 应用完全不可用：无法安装、无法启动、启动后立即崩溃、无法回滚 |
| 影响范围 | 一旦发布将影响多数用户或所有用户，或可能影响生产系统 |
| 合规 | 触发合规红线（个人信息保护、跨境数据传输、企业审计缺失） |

### RoboThree P0 示例

- 模型网关把用户 API Key 回显到 Renderer DevTools 或日志。
- Worker Core 在无退出条件下无限循环，把任务跑满到 OOM。
- Electron 渲染进程通过 `nodeIntegration` 直接执行任意 shell。
- 任务日志写入磁盘时未脱敏，明文包含数据库连接串或企业 token。
- 自动更新覆盖安装后用户本地数据被清空且无法恢复。
- 跨租户调用未过滤，导致 A 组织的数据出现在 B 组织的任务结果里。

---

## P1 — 严重级（Critical）

**结论：默认禁止发布，必须修复并复测通过。例外需要负责人书面接受。**

定义：

| 维度 | 触发条件 |
| --- | --- |
| 功能 | 核心功能不可用或返回严重错误结果 |
| 权限 | 存在权限越权（普通用户可访问企业功能、可调用未授权工具） |
| 稳定性 | 高频崩溃（崩溃率 ≥ 1%）、关键数据丢失、内存泄漏确认存在 |
| 自动升级 | 自动升级导致应用不可用或静默降级 |
| Agent | Agent 可能执行未授权操作（未确认的高风险动作） |

### RoboThree P1 示例

- 工具调用前未校验权限，普通用户能删除他人文件。
- 高风险工具（`run_command`、`write_file`、`http_request`）不弹确认直接执行。
- 模型网关 Token 过期后未自动刷新，导致全部任务失败且无降级路径。
- MCP 服务不可用时 Worker 静默失败，任务状态停留在"运行中"。
- 自动更新下载成功后校验失败仍覆盖安装，导致启动失败。
- 任务取消后内部状态不一致，二次启动时残留执行。

---

## P2 — 一般级（Major）

**结论：可评估带风险发布，但必须记录在报告中并跟踪修复。**

定义：

| 维度 | 触发条件 |
| --- | --- |
| 功能 | 非核心功能异常，仅在特定输入或边界场景触发 |
| 体验 | 错误提示不准确、空状态文案错误、操作引导缺失 |
| 性能 | 明显性能问题（P95 延迟翻倍、内存占用翻倍） |
| 恢复 | 任务恢复不完整，特定条件下需要用户手工介入 |
| 可绕过 | 可绕过但影响正常使用的问题 |

### RoboThree P2 示例

- 任务进度长时间停留在 99% 直到完成才跳到 100%。
- 长任务上下文超过窗口后未滚动，旧工具结果保留导致费用异常。
- 中文路径下文件读取偶发失败（仅在 macOS 测试通过，Windows 失败）。
- 流式输出中断后无法重连，必须刷新整个会话。
- 用户自定义模型的白名单未生效但也没拒绝，仅打印 warning。
- 同一工具在一次任务中无意义重复调用 > 3 次。

---

## P3 — 轻微级（Minor）

**结论：记录在报告，进入后续版本迭代，不阻断发布。**

定义：

| 维度 | 触发条件 |
| --- | --- |
| UI | 视觉瑕疵、像素偏差、间距不一致、暗色模式异常 |
| 文案 | 文案错别字、翻译不一致、按钮含义不清 |
| 日志 | 日志格式不规范、缺时间戳、缺 requestId |
| 低概率 | 不影响核心使用的小问题，仅在极端路径触发 |

### RoboThree P3 示例

- 设置页底部"关于"链接颜色与主题不匹配。
- 错误弹窗关闭按钮在小屏下被截断。
- Toast 文案大小写不一致。
- 控制台偶发非阻塞 warning，不影响功能。

---

## 升降级规则

| 信号 | 操作 |
| --- | --- |
| 同一问题在 N 次构建中 ≥ 3 次复发 | 上调一级 |
| 修复后复测稳定通过 ≥ 2 个回归轮次 | 允许关闭或下调 |
| 业务方书面接受风险（写入报告） | P1 → 带风险发布 |
| 触发合规告警 | 自动上调到 P0 |
| 影响范围被精确收敛到 ≤ 0.1% 用户且无数据/安全后果 | 可由 P1 降为 P2 |

---

## 发布结论与问题级别的硬绑定

| 结论 | 允许的问题组合 |
| --- | --- |
| **PASS** | 仅 P3，且全部 P3 已在报告中列出；无 P0/P1/P2 |
| **PASS WITH RISKS** | 无 P0；无未接受 P1；允许 P2/P3 |
| **FAIL** | 存在 P0，或存在未解决/未接受的 P1 |
| **INCOMPLETE** | 关键测试未执行；环境阻塞；需求不明确；不能判 PASS |

任何与上表冲突的结论必须在报告中说明例外与批准人。
