# 验收规则

> 合并：证据等级 + 验收结论 + 缺陷等级 + 与 independent-qa-acceptance 边界。
> 用于 C 模式"验收设计与验收评审"。

## 1. 证据等级（L1-L4）

取获取到的最强证据对应等级；不要求 L1/L2 全存才能到 L3。

| 等级 | 名称 | 含义 | 证据类型 |
| --- | --- | --- | --- |
| **L1** | 文档证据 | 文档/Contract/UI 文案之间无矛盾 | 文档路径 + 截图 |
| **L2** | 静态实现证据 | 代码与文档一致 + Conformance Test 通过 | 代码 `file:line` + 测试报告 |
| **L3** | 执行证据 | 本地/测试环境实际运行 | 命令 + 输出 + exit code + 时间戳 |
| **L4** | 真实环境证据 | 试点企业环境运行 | 用户环境日志 + 反馈 |

## 2. 验收结论（5 选 1）

| 结论 | 触发条件 |
| --- | --- |
| **通过** | 全部需求 L3+，无 P0/P1 |
| **有条件通过** | 无 P0；P1 由产品负责人接受 |
| **部分通过** | 关键路径通过；非关键路径存在 P1 |
| **不通过** | 存在 P0 或核心功能失败 |
| **无法验证** | 环境不完整 / 需求不明 / 关键测试未执行 |

无运行证据 → 禁止 L3+。L2 不得表述为"功能已通过验收"。

## 3. 验收缺陷等级（与需求评审 P0-P3 分离）

| 等级 | 含义 | 触发结论 |
| --- | --- | --- |
| **BLOCKER** | 核心路径失败 / 数据丢失 / 安全漏洞 | 不通过 |
| **MAJOR** | 非核心路径失败 / 关键功能缺失 | 部分通过 / 不通过 |
| **MINOR** | 边缘场景 / 文案 / 状态不一致 | 有条件通过 |
| **SUGGESTION** | 可优化项 / 后续版本 | 通过 / 有条件通过 |

## 4. 禁止措辞

"体验良好""功能正常""系统稳定""用户可以成功使用""应该没问题"。

## 5. 与 independent-qa-acceptance 边界

| 职责 | 本 Skill（C 模式） | independent-qa-acceptance |
| --- | --- | --- |
| 验收标准设计 | ✓ | — |
| 证据汇总与评审 | ✓ | — |
| 产品验收结论 | ✓ | — |
| 启动应用 | — | ✓ |
| 执行测试 | — | ✓ |
| 收集日志/截图 | — | ✓ |

本 Skill 证据不足→生成待执行验收清单→移交 QA Skill→获取证据→形成产品验收结论。
